Explicación de los Controllers del Backend

Esta página explica el funcionamiento de los diferentes controllers utilizados en la aplicación de comercio electrónico Pharma & Skincare. Los controllers contienen la lógica de negocio del backend. Reciben las solicitudes enviadas por el frontend, procesan los datos y devuelven una respuesta al cliente.

1. Order Controller - Gestión de pedidos

El Order Controller permite gestionar todas las operaciones relacionadas con los pedidos de los clientes. Permite crear un pedido, recuperar los pedidos, modificar su estado y eliminar un pedido.

2. Función createOrder

La función createOrder permite crear un nuevo pedido. Recupera la información enviada por el frontend desde req.body.

La información recuperada incluye los productos pedidos, los datos del cliente, el método de pago y el estado del pago.

El controller comprueba primero que items sea un array y que contenga al menos un producto. Por lo tanto, se rechaza un pedido vacío.

A continuación, el controller recupera el identificador del usuario conectado mediante req.user.id o req.user._id. Esta información generalmente procede del middleware de autenticación JWT.

El identificador del usuario se valida para asegurarse de que tiene un formato MongoDB ObjectId válido.

3. Validación de los productos del pedido

Para cada producto incluido en el pedido, el controller comprueba que exista un identificador de producto.

También comprueba que el nombre del producto no esté vacío.

El precio se convierte en número mediante Number() y debe ser mayor o igual que cero.

La cantidad también se convierte en número y debe ser mayor o igual que uno.

Estas validaciones permiten evitar que se almacenen datos incorrectos en MongoDB.

4. Cálculo del total del pedido

El controller calcula automáticamente el importe total del pedido. Para cada producto, el precio se multiplica por la cantidad.

Todos los resultados se suman para obtener el importe total del pedido.

El método toFixed(2) permite conservar dos cifras después del punto decimal.

5. Creación del pedido en MongoDB

Después de realizar todas las validaciones, el controller utiliza Order.create() para guardar el pedido en MongoDB.

El pedido contiene el usuario, la información del cliente, los productos, el importe total, el método de pago, el estado del pago y el estado del pedido.

El estado inicial del pedido se establece en En attente.

6. Population del pedido

Después de la creación, el controller utiliza populate() para recuperar la información completa del usuario y de los productos.

La relación user permite recuperar la información del usuario.

La relación items.product permite recuperar la información de los productos asociados al pedido.

7. Función getAllOrders

La función getAllOrders permite al administrador recuperar todos los pedidos registrados en MongoDB.

Los pedidos se ordenan por fecha de creación en orden descendente. Por lo tanto, los pedidos más recientes aparecen primero.

La información de los usuarios y de los productos también se recupera mediante populate().

Esta función se utiliza principalmente en el dashboard del administrador.

8. Función getUserOrders

La función getUserOrders permite recuperar todos los pedidos pertenecientes a un usuario específico.

El identificador del usuario se recupera desde req.params.userId.

El controller comprueba que este identificador exista y corresponda a un ObjectId MongoDB válido.

MongoDB busca entonces todos los pedidos cuyo campo user corresponda a este identificador.

9. Función getOrderById

La función getOrderById permite recuperar un pedido específico a partir de su identificador.

El controller comprueba primero que el identificador proporcionado sea válido.

Si ningún pedido corresponde a este identificador, el servidor devuelve un error 404 con el mensaje Commande introuvable.

Si el pedido existe, se devuelve con la información del usuario y de los productos asociados.

10. Función getMyOrders

La función getMyOrders permite al usuario conectado recuperar únicamente sus propios pedidos.

El identificador se recupera desde el token JWT mediante req.user.id o req.user._id.

Esta función es útil para mostrar una página "Mis pedidos" en el área del cliente.

11. Función updateOrderStatus

La función updateOrderStatus permite al administrador modificar el estado de un pedido.

Los estados permitidos son: En attente, En préparation, Expédiée, Livrée y Annulée.

El controller comprueba que el nuevo estado pertenezca a esta lista antes de modificar el pedido.

A continuación, se utiliza el método findByIdAndUpdate() para modificar el estado en MongoDB.

12. Función updatePaymentStatus

La función updatePaymentStatus permite modificar el estado del pago asociado a un pedido.

Los tres estados permitidos son: En attente, Payé y Échec.

Esta función puede ser utilizada por el administrador para supervisar el estado de los pagos.

13. Función deleteOrder

La función deleteOrder permite eliminar un pedido utilizando su identificador.

El controller comprueba primero que el identificador sea válido.

El método findByIdAndDelete() elimina posteriormente el pedido de MongoDB.

14. Payment Controller - Gestión de pagos

El Payment Controller es responsable de la integración con Stripe. Permite crear una sesión de pago, recuperar los pagos para el administrador y procesar las notificaciones enviadas por Stripe.

15. Función createCheckoutSession

La función createCheckoutSession permite crear una sesión de Stripe Checkout para un pedido.

Recupera orderId de la solicitud enviada por el frontend.

El controller comprueba entonces que el usuario haya iniciado sesión.

Busca el pedido en MongoDB y verifica que realmente pertenezca al usuario conectado.

Esta verificación es importante para impedir que un usuario pague o acceda al pedido de otro usuario.

16. Verificación del pago

Antes de crear una nueva sesión de Stripe, el controller comprueba que el pedido no haya sido pagado anteriormente.

También comprueba que el pedido contenga productos y que su importe total sea superior a cero.

17. Creación del Payment

Se crea un documento Payment en MongoDB con el identificador del pedido, el identificador del usuario, el importe, la moneda, Stripe como método y el estado pending.

18. Creación de los productos de Stripe

Cada producto del pedido se transforma en un line_item de Stripe.

Stripe recibe el nombre del producto, su precio convertido a céntimos y su cantidad.

El precio se multiplica por 100 porque Stripe generalmente utiliza la unidad mínima de la moneda.

19. Creación de la sesión de Stripe

El método stripe.checkout.sessions.create() crea la página de pago de Stripe.

El modo utilizado es payment, que corresponde a un pago único.

Después del pago, Stripe redirige al cliente a payment-success. En caso de cancelación, el cliente es redirigido a payment-cancel.

Los metadatos de Stripe contienen el identificador del pedido y el identificador del pago de MongoDB. Esta información permite posteriormente encontrar los documentos correspondientes cuando Stripe confirma el pago.

20. Función getAllPayments

La función getAllPayments permite al administrador recuperar todos los pagos registrados.

La información del usuario y del pedido se recupera mediante populate().

Los pagos se ordenan del más reciente al más antiguo.

21. Función stripeWebhook

El webhook de Stripe permite que Stripe informe automáticamente al backend cuando ocurre un evento de pago.

El controller utiliza la firma stripe-signature para verificar que la notificación proviene realmente de Stripe.

El secreto STRIPE_WEBHOOK_SECRET se utiliza para verificar esta firma.

22. Confirmación del pago de Stripe

Cuando el evento es checkout.session.completed, significa que la sesión Checkout se ha completado.

El controller recupera entonces orderId y paymentId de los metadatos de Stripe.

El pago de MongoDB se actualiza con el estado paid.

El pedido también se actualiza con el estado de pago Payé.

Su estado de pedido pasa automáticamente a En préparation.

23. Product Controller - Gestión de productos

El Product Controller permite al administrador gestionar los productos disponibles en la tienda.

24. Función createProduct

La función createProduct permite crear un nuevo producto.

Recupera el nombre, el precio, el stock y la categoría desde req.body.

La imagen se recupera desde req.file cuando se envía una imagen con la solicitud.

El producto se guarda posteriormente en MongoDB mediante Product.create().

25. Función getProducts

La función getProducts recupera todos los productos almacenados en MongoDB.

Utiliza Product.find() y devuelve los productos al frontend en formato JSON.

26. Función updateProduct

La función updateProduct permite modificar un producto existente.

El producto se busca mediante su identificador utilizando Product.findById().

Si el producto no existe, el servidor devuelve un error 404.

A continuación, se modifican los campos enviados por el frontend. El controller solo modifica los campos presentes en la solicitud.

Si se carga una nueva imagen, la ruta de la nueva imagen sustituye a la imagen anterior.

27. Sales Controller - Estadísticas de ventas

El Sales Controller permite calcular las estadísticas comerciales utilizadas en el dashboard del administrador.

28. Función getSalesOverview

La función getSalesOverview recupera los pedidos que no están cancelados.

A continuación, calcula los ingresos totales sumando los importes de todos los pedidos.

También calcula el número total de pedidos.

El valor medio del pedido se calcula dividiendo los ingresos entre el número de pedidos.

Si no existen pedidos, el valor medio se establece en cero para evitar una división por cero.

29. Función getSalesByDay

La función getSalesByDay utiliza la agregación de MongoDB para calcular las ventas por día.

Los pedidos cancelados se excluyen de las estadísticas.

MongoDB agrupa los pedidos según su fecha de creación utilizando $dateToString.

Para cada día, el sistema calcula el importe total de las ventas y el número de pedidos.

Los resultados se ordenan posteriormente por fecha. Estos datos pueden utilizarse para crear un gráfico en el dashboard del administrador.

30. Settings Controller - Configuración de la tienda

El Settings Controller permite recuperar y modificar la configuración general de la tienda.

31. Función getSettings

La función getSettings busca la configuración almacenada en MongoDB.

Si todavía no existe ningún documento Settings, el controller crea automáticamente un nuevo documento con los valores predeterminados.

Este método garantiza que la aplicación siempre disponga de una configuración.

32. Función updateSettings

La función updateSettings permite al administrador modificar la configuración de la tienda.

Puede modificar el nombre de la tienda, el correo electrónico, el teléfono, la dirección y la moneda.

También puede activar o desactivar los pedidos.

El modo mantenimiento puede activarse o desactivarse.

La configuración de entrega también puede modificarse, incluida la activación de la entrega y los gastos de envío.

Los pagos mediante Stripe también pueden activarse o desactivarse utilizando el campo stripeEnabled.

33. Auth Controller - Autenticación

El Auth Controller permite gestionar el registro, el inicio de sesión y la gestión de clientes.

34. Función register

La función register permite crear una nueva cuenta de usuario.

Recupera el nombre de usuario, el correo electrónico y la contraseña desde la solicitud.

Comprueba que las tres informaciones obligatorias estén presentes.

A continuación, comprueba si el correo electrónico ya existe en MongoDB. Por lo tanto, dos usuarios no pueden utilizar la misma dirección de correo.

35. Cifrado de la contraseña

Antes de guardar el usuario, la contraseña se transforma mediante bcrypt.hash().

Por lo tanto, la contraseña original no se almacena directamente en MongoDB.

36. Creación del token JWT

Después de crear la cuenta, el backend genera un token JWT mediante jwt.sign().

El token contiene el identificador del usuario, su correo electrónico y su rol.

El token está configurado para expirar después de siete días.

El frontend puede almacenar este token y enviarlo en las solicitudes que requieren autenticación.

37. Función login

La función login permite a un usuario existente iniciar sesión en su cuenta.

Recupera el correo electrónico y la contraseña enviados por el frontend.

El correo electrónico se limpia mediante trim() y se convierte a minúsculas.

El backend busca posteriormente el usuario correspondiente en MongoDB.

La contraseña proporcionada se compara con la contraseña hash almacenada en MongoDB mediante bcrypt.compare().

Si los datos son correctos, se genera un nuevo token JWT y se envía al frontend.

38. Función getCustomers

La función getCustomers permite al administrador recuperar todos los usuarios que tienen el rol user.

El campo password se excluye intencionadamente de la respuesta mediante select("-password").

Los clientes se ordenan del más reciente al más antiguo.

39. Función getCustomerById

La función getCustomerById permite recuperar la información de un cliente específico mediante su identificador.

La contraseña también se excluye de la respuesta.

El controller comprueba que el usuario tenga el rol user.

40. Función deleteCustomer

La función deleteCustomer permite al administrador eliminar un cliente.

El controller busca únicamente usuarios que tengan el rol user.

Si el cliente existe, se elimina mediante findOneAndDelete().

41. Funcionamiento general del backend

El frontend React envía solicitudes HTTP al backend Node.js y Express.

Las rutas de Express dirigen las solicitudes hacia los controllers correspondientes.

Los controllers aplican las reglas de negocio, validan los datos y utilizan los modelos Mongoose para comunicarse con MongoDB.

MongoDB almacena los usuarios, productos, pedidos, pagos y configuración de la tienda.

Stripe interviene en el proceso de pago. El backend crea una sesión de Stripe y el webhook de Stripe informa posteriormente al backend cuando el pago se ha completado.

42. Arquitectura general

El funcionamiento general puede resumirse de la siguiente manera: React representa el frontend, Express y Node.js representan el backend, los controllers contienen la lógica de negocio, los modelos Mongoose definen las estructuras de MongoDB, MongoDB almacena los datos, JWT gestiona la autenticación y Stripe gestiona los pagos.

Esta arquitectura permite separar claramente la interfaz de usuario, la lógica de negocio, la base de datos, la autenticación y los procesos de pago.
