Explicação do código React – PharmaShop

Documentação completa do funcionamento da aplicação de e-commerce

1. Visão geral do projeto PharmaShop

O projeto PharmaShop é uma aplicação de e-commerce desenvolvida com React para o frontend e Node.js, Express e MongoDB para o backend. O principal objetivo desta aplicação é permitir que os usuários consultem produtos farmacêuticos e de skincare, pesquisem e filtrem produtos, adicionem produtos ao carrinho, modifiquem as quantidades, removam produtos, criem um pedido e, finalmente, realizem um pagamento com Stripe.

A aplicação também possui um sistema de autenticação que permite ao usuário criar uma conta ou fazer login. Dependendo da função do usuário, especialmente administrador ou usuário comum, a aplicação pode redirecionar o usuário para diferentes interfaces.

O frontend React se comunica com o backend por meio do Axios, enquanto o backend se comunica com o MongoDB para recuperar ou armazenar os dados. Portanto, todo o projeto segue uma arquitetura composta por uma interface frontend, uma API backend e um banco de dados.

2. Função login()

A função login() gerencia a autenticação do usuário na aplicação. Ela recebe dois parâmetros importantes: user, que representa as informações do usuário conectado, e token, que geralmente representa um token JWT utilizado para autenticar o usuário.

A primeira instrução utiliza localStorage.setItem() para armazenar as informações do usuário no navegador. Como o localStorage não pode armazenar diretamente um objeto JavaScript, JSON.stringify() converte o objeto do usuário em texto JSON.

O token é então salvo com a chave token. Por fim, setUser(user) atualiza o estado do React que contém o usuário atualmente conectado.

3. Gerenciamento global do carrinho com CartContext

CartContext é utilizado para gerenciar o carrinho de forma global na aplicação React. Sem a Context API, seria necessário passar as informações do carrinho entre vários componentes usando props, o que tornaria a aplicação mais difícil de manter.

Com createContext(), é criado um espaço compartilhado para armazenar as informações e as funções do carrinho. O componente CartProvider contém esse estado global e fornece os dados aos componentes que estão dentro do Provider.

O carrinho é inicializado com useState([]), o que significa que, ao iniciar a aplicação, o array cart está vazio. Componentes como Products, Cart e Checkout podem então acessar os mesmos dados por meio de useContext().

4. Função addToCart()

A função addToCart() permite adicionar um produto ao carrinho. Antes de adicionar o produto, o código utiliza o método find() para verificar se já existe um produto com o mesmo identificador _id.

Se o produto já existir, o método map() percorre o carrinho e cria uma nova versão do produto com a quantidade aumentada em um. O operador spread mantém as outras propriedades do produto.

Se o produto ainda não existir, ele é adicionado ao array com a propriedade quantity: 1. Essa lógica permite gerenciar automaticamente as quantidades dos produtos no carrinho.

5. Remoção e modificação dos produtos do carrinho

A função removeFromCart() permite remover um produto do carrinho. Ela utiliza o método filter() para criar um novo array contendo apenas os produtos cujo identificador é diferente do identificador do produto que deve ser removido.

A função updateQuantity() permite modificar a quantidade de um produto. Se a nova quantidade for menor ou igual a zero, a função chama automaticamente removeFromCart().

A função clearCart() permite esvaziar completamente o carrinho utilizando setCart([]).

6. Cálculo do número de produtos e do valor total

O código utiliza o método reduce() para realizar os cálculos relacionados ao carrinho. A variável cartCount representa o número total de itens presentes no carrinho.

A variável cartTotal representa o valor total do pedido. Para cada produto, o preço é multiplicado pela quantidade e o resultado é adicionado ao total geral.

7. Função useCart()

useCart() é um hook personalizado criado para simplificar o uso do CartContext. Em vez de escrever diretamente useContext(CartContext) em cada componente, o desenvolvedor pode simplesmente chamar useCart().

Esse hook permite recuperar facilmente o carrinho, as funções de adicionar e remover, as funções de alteração de quantidade, o número de itens e o valor total.

8. Componente Auth

O componente Auth gerencia duas operações: login e cadastro. A variável isLogin permite determinar o modo atual do formulário.

Quando isLogin é true, o formulário exibe a interface de login. Quando é false, o formulário exibe a interface de cadastro. As variáveis username, email e password são estados do React utilizados para controlar os campos do formulário.

O componente também utiliza useNavigate() para redirecionar o usuário para outra página após uma operação bem-sucedida.

9. Login do usuário

Durante o login, a função handleAuth() verifica primeiro se o endereço de email e a senha foram preenchidos. O uso de trim() permite remover espaços desnecessários ao redor do endereço de email.

O email também é convertido para letras minúsculas usando toLowerCase(). Em seguida, o Axios envia uma solicitação POST para /api/users/login.

Se a resposta contiver um token e um usuário, essas informações são armazenadas no localStorage. Em seguida, a função do usuário é verificada. Se a função for admin, o usuário é redirecionado para /admin. Caso contrário, ele é redirecionado para /products.

10. Cadastro do usuário

Quando o formulário está no modo de cadastro, o username se torna obrigatório, além do email e da senha.

As informações são agrupadas em um objeto registerData e depois enviadas com Axios para /api/users/register.

O backend cria o novo usuário e pode retornar um token juntamente com as informações da conta. O frontend salva essas informações no localStorage quando elas estão disponíveis.

11. Tratamento de erros no Auth

As solicitações de login e cadastro são colocadas dentro de um bloco try/catch. Se o servidor retornar um erro, o programa entra no bloco catch.

O código utiliza err.response?.data?.message para tentar recuperar a mensagem enviada pelo backend. O símbolo ?. corresponde ao optional chaining e permite evitar um erro caso algumas propriedades não existam.

12. Componente Cart

O componente Cart representa a página do carrinho. Ele recupera as informações necessárias por meio do CartContext. Quando cart.length é igual a zero, a aplicação exibe uma mensagem informando que o carrinho está vazio.

Quando o carrinho contém produtos, cart.map() é utilizado para exibir cada item. Para cada produto, a aplicação mostra seu nome, preço, quantidade e subtotal.

O botão de menos diminui a quantidade usando updateQuantity(), enquanto o botão de mais utiliza addToCart(). O botão de excluir chama removeFromCart().

13. Componente Checkout

Checkout representa a etapa de finalização do pedido. Esse componente recupera as informações do carrinho ou de uma compra direta.

useLocation() permite recuperar as informações transmitidas durante a navegação. Se um produto for enviado diretamente, ele é adicionado a checkoutItems com uma quantidade de um.

Caso contrário, são utilizados os produtos do carrinho. O componente também contém um estado customer que reúne o nome, sobrenome, telefone e endereço do cliente.

14. Gerenciamento do formulário do cliente

A função handleChange() permite atualizar dinamicamente as informações do cliente. Ela utiliza o nome do campo HTML como chave do objeto customer.

Essa técnica evita criar uma função diferente para cada campo do formulário. Dessa forma, o formulário permanece controlado pelo React e os valores inseridos estão sempre disponíveis no estado customer.

15. Recuperação do identificador do usuário

A função getUserIdFromToken() recupera o token JWT armazenado no localStorage. Um token JWT geralmente contém três partes separadas por pontos.

O código recupera a parte central, decodifica-a com atob() e depois transforma o resultado JSON em um objeto JavaScript usando JSON.parse().

A aplicação então procura uma propriedade id, _id ou userId. Isso permite recuperar o identificador do usuário conectado para associá-lo ao pedido.

16. Preparação dos produtos para o pedido

Antes de criar um pedido, o código normaliza as informações dos produtos. A função getProductPrice() procura o preço em várias propriedades possíveis.

A função getProductName() procura o nome do produto em várias propriedades possíveis, como name, productName ou title.

A função getProductQuantity() procura a quantidade em qty ou quantity e utiliza uma quantidade mínima de um.

17. Criação do pedido

Quando o usuário confirma o formulário Checkout, handleSubmit() começa impedindo o comportamento padrão do formulário usando preventDefault().

Em seguida, o código verifica as informações do cliente, os produtos, o token e o identificador do usuário.

Os produtos são transformados em orderItems contendo o produto, seu nome, preço e quantidade. O valor total é calculado usando reduce.

O objeto orderData contém os produtos, as informações do cliente, o método de pagamento Stripe e o status inicial do pagamento. Esse objeto é enviado ao backend por meio de uma solicitação POST para /api/orders.

18. Pagamento com Stripe

Após a criação do pedido, Checkout recupera o identificador do pedido criado pelo backend.

Em seguida, uma segunda solicitação é enviada para /api/payments/create-checkout-session para solicitar ao backend a criação de uma sessão de pagamento Stripe.

Se o backend retornar uma URL Stripe válida, o frontend redirecionará o usuário para essa URL usando window.location.href. O usuário poderá então concluir o pagamento no Stripe.

19. Componente Home

O componente Home representa a página inicial do PharmaShop. Ele exibe um título apresentando a loja, um subtítulo explicando sua atividade e um botão que permite acessar os produtos.

O componente Link do React Router é utilizado para navegar para /products sem recarregar completamente a aplicação.

20. Componente Orders

O componente Orders é responsável por exibir o histórico de pedidos. No código fornecido, os pedidos são recuperados do localStorage usando a chave "orders".

Se nenhum pedido estiver disponível, uma mensagem informa que ainda não há pedidos. Caso contrário, map é utilizado para exibir cada pedido com o cliente, telefone, endereço, produtos, valor total e data.

Um ponto importante é que Checkout realmente cria os pedidos no backend. Se MongoDB for a fonte oficial dos pedidos, seria preferível que Orders recuperasse os pedidos por meio de uma rota de API protegida.

21. Componente Product

O componente Product exibe os detalhes de um produto. useParams() recupera o identificador do produto a partir da URL.

Em seguida, o Axios envia uma solicitação GET para /api/products/:id. O componente possui estados loading e error para exibir corretamente as diferentes situações durante a recuperação dos dados.

Depois que o produto é recuperado, a aplicação pode exibir seu nome, imagem, preço, categoria e descrição.

22. Gerenciamento das imagens dos produtos

A função getImageUrl() permite construir corretamente o endereço de uma imagem. Se a imagem já começar com http, ela será considerada uma URL completa.

Se a imagem corresponder a um caminho relativo, o endereço do servidor backend será adicionado antes do caminho. Essa lógica é útil quando o MongoDB armazena apenas o caminho da imagem, enquanto os arquivos são servidos pelo servidor Node.js.

23. Componente Products

Products é a página que exibe a lista de produtos disponíveis. Ao iniciar, products é inicializado com um array vazio.

useEffect é utilizado para recuperar os produtos da API. O Axios envia uma solicitação GET para /api/products.

Os dados recebidos são então armazenados no estado usando setProducts(). O React atualiza automaticamente a interface quando esse estado é alterado.

24. Pesquisa e filtragem de produtos

A variável search permite pesquisar um produto pelo nome. O método filter() é utilizado para selecionar os produtos que correspondem aos critérios.

O nome é convertido para letras minúsculas usando toLowerCase() e, em seguida, includes() verifica se o texto pesquisado existe no nome do produto.

O filtro de categoria compara a categoria do produto com a categoria selecionada. O filtro de preço verifica se o preço do produto é menor ou igual ao preço máximo.

25. Adição ao carrinho a partir de Products

A função handleAddToCart() permite adicionar um produto diretamente ao carrinho a partir da lista de produtos.

Antes de adicioná-lo, some() verifica se o produto já existe no carrinho comparando os identificadores _id.

Essa verificação evita duplicatas e permite que o CartContext gerencie corretamente o aumento da quantidade.

26. Função Buy Now

handleBuyNow() permite realizar uma compra direta de um produto. O primeiro passo consiste em verificar se o usuário está conectado por meio da presença do token no localStorage.

Se nenhum token existir, o produto selecionado pode ser armazenado temporariamente no localStorage com a chave pendingProduct e o usuário será redirecionado para a página Auth.

Se o usuário já estiver conectado, ele será redirecionado diretamente para Checkout com o produto transmitido no estado de navegação.

27. Logout

handleLogout() permite desconectar o usuário. O token, as informações do usuário e o produto temporário pendingProduct são removidos do localStorage.

Após essa operação, a aplicação redireciona o usuário para a página Auth. A remoção do token impede que as próximas solicitações protegidas utilizem a sessão anterior.

28. Axios e comunicação com o backend

Axios é utilizado em vários componentes para se comunicar com a API backend. As solicitações GET são utilizadas principalmente para recuperar produtos ou outras informações.

As solicitações POST são utilizadas para enviar dados, por exemplo, durante o login, o cadastro, a criação de um pedido ou a criação de uma sessão Stripe.

O frontend utiliza o endereço http://localhost:3000/api como base da API no código fornecido.

29. Arquitetura completa da aplicação

O funcionamento geral pode ser resumido por meio de uma cadeia de comunicação. O usuário interage primeiro com a interface React. Em seguida, o React utiliza Axios para enviar uma solicitação HTTP para a API Express.

O Express recebe a solicitação e a encaminha para o controlador apropriado. O controlador pode consultar ou modificar os dados no MongoDB por meio dos modelos Mongoose.

O backend então retorna uma resposta JSON. O React recebe essa resposta e atualiza seus estados usando useState, o que provoca uma nova atualização da interface.

React → Axios → Express → Controller → MongoDB → JSON → React

30. Uso de useState

useState é um dos principais Hooks do React. Ele permite manter um dado dentro de um componente e modificá-lo.

No PharmaShop, useState é utilizado para gerenciar os produtos, o carrinho, os campos dos formulários, as mensagens de erro, os estados de carregamento e as informações do usuário.

31. Uso de useEffect

useEffect permite executar uma ação após a renderização de um componente. Ele é especialmente importante no PharmaShop para realizar chamadas à API quando uma página é carregada.

Por exemplo, Products utiliza useEffect para recuperar os produtos, Product o utiliza para recuperar um produto específico e Checkout o utiliza para preparar os produtos que serão pedidos.

32. Uso do React Router

React Router permite gerenciar as diferentes páginas da aplicação sem recarregar completamente o navegador.

Link é utilizado para criar links, enquanto useNavigate() permite realizar redirecionamentos a partir de uma função JavaScript.

useParams() permite recuperar os parâmetros presentes na URL e useLocation() permite recuperar as informações relacionadas à navegação.

33. Tratamento de erros e carregamentos

As solicitações ao backend podem falhar por diferentes motivos: o servidor pode estar parado, a URL pode estar incorreta, pode existir um erro de rede, um problema de autenticação ou um erro no lado do servidor.

Por esse motivo, o código utiliza try, catch e, em alguns casos, finally. try contém a operação principal, catch captura o erro e finally permite realizar uma ação que deve acontecer em todos os casos.

34. Pontos importantes a verificar no projeto

O primeiro ponto diz respeito ao componente Orders. No código fornecido, Orders utiliza localStorage enquanto Checkout envia os pedidos para o backend. Portanto, existe o risco de que os pedidos criados no MongoDB não sejam exibidos em Orders.

Para uma aplicação real, recomenda-se utilizar MongoDB como fonte principal dos pedidos e criar uma rota backend que permita ao usuário autenticado recuperar seus pedidos.

O segundo ponto diz respeito ao filtro por categoria em Products. O código contém um estado category e uma condição de filtragem, mas o JSX fornecido não mostra necessariamente um elemento que permita ao usuário selecionar uma categoria.

O terceiro ponto diz respeito a handleBuyNow. A função foi projetada para realizar uma compra direta, mas é necessário verificar se o botão "Comprar agora" está realmente presente na interface Products.

35. Conclusão geral

O código do PharmaShop implementa uma aplicação de e-commerce completa baseada em React. O React é responsável pela interface do usuário e pelo gerenciamento dos estados, a Context API permite compartilhar o carrinho entre os componentes, o React Router gerencia a navegação, o Axios é responsável pela comunicação com a API e o localStorage armazena determinadas informações relacionadas à sessão.

O backend Node.js e Express processa as solicitações, verifica os usuários, cria os pedidos e prepara os pagamentos com Stripe. O MongoDB constitui o banco de dados utilizado para armazenar usuários, produtos e pedidos.

O funcionamento geral é o seguinte: o usuário consulta os produtos, pesquisa ou filtra um produto, adiciona seus produtos ao carrinho, faz login se necessário, insere as informações de entrega, cria um pedido e finalmente é redirecionado para o Stripe para realizar o pagamento.

Essa organização constitui uma boa base para uma aplicação de e-commerce moderna, desde que seja mantida uma separação clara entre os dados temporários do navegador e os dados oficiais armazenados no backend e no MongoDB.
