Explication des Controllers Backend

Cette page explique le fonctionnement des différents controllers utilisés dans l'application e-commerce Pharma & Skincare. Les controllers contiennent la logique métier du backend. Ils reçoivent les requêtes envoyées par le frontend, traitent les données et renvoient une réponse au client.

1. Order Controller - Gestion des commandes

Le Order Controller permet de gérer toutes les opérations liées aux commandes des clients. Il permet notamment de créer une commande, récupérer les commandes, modifier leur statut et supprimer une commande.

2. Fonction createOrder

La fonction createOrder permet de créer une nouvelle commande. Elle récupère les informations envoyées par le frontend à partir de req.body.

Les informations récupérées sont les produits commandés, les informations du client, la méthode de paiement et le statut du paiement.

Le controller vérifie d'abord que items est bien un tableau et qu'il contient au moins un produit. Une commande vide est donc refusée.

Ensuite, le controller récupère l'identifiant de l'utilisateur connecté grâce à req.user.id ou req.user._id. Cette information provient généralement du middleware d'authentification JWT.

L'identifiant de l'utilisateur est ensuite vérifié afin de s'assurer qu'il possède un format MongoDB ObjectId valide.

3. Vérification des produits de la commande

Pour chaque produit présent dans la commande, le controller vérifie qu'un identifiant de produit existe.

Il vérifie également que le nom du produit n'est pas vide.

Le prix est converti en nombre avec Number() et doit être supérieur ou égal à zéro.

La quantité est également convertie en nombre et doit être supérieure ou égale à un.

Ces vérifications permettent d'éviter d'enregistrer des données incorrectes dans MongoDB.

4. Calcul du total de la commande

Le controller calcule automatiquement le montant total de la commande. Pour chaque produit, le prix est multiplié par la quantité.

Tous les résultats sont ensuite additionnés afin d'obtenir le montant total de la commande.

La méthode toFixed(2) permet de conserver deux chiffres après la virgule.

5. Création de la commande dans MongoDB

Après toutes les vérifications, le controller utilise Order.create() pour enregistrer la commande dans MongoDB.

La commande contient l'utilisateur, les informations du client, les produits, le total, la méthode de paiement, le statut du paiement et le statut de la commande.

Le statut initial de la commande est défini sur En attente.

6. Population de la commande

Après la création, le controller utilise populate() pour récupérer les informations complètes de l'utilisateur et des produits.

La relation user permet de récupérer les informations de l'utilisateur.

La relation items.product permet de récupérer les informations des produits associés à la commande.

7. Fonction getAllOrders

La fonction getAllOrders permet à l'administrateur de récupérer toutes les commandes enregistrées dans MongoDB.

Les commandes sont triées par date de création décroissante. Les commandes les plus récentes apparaissent donc en premier.

Les informations des utilisateurs et des produits sont également récupérées avec populate().

Cette fonction est principalement utilisée par le dashboard administrateur.

8. Fonction getUserOrders

La fonction getUserOrders permet de récupérer toutes les commandes appartenant à un utilisateur spécifique.

L'identifiant de l'utilisateur est récupéré à partir de req.params.userId.

Le controller vérifie que cet identifiant existe et qu'il correspond à un ObjectId MongoDB valide.

Ensuite, MongoDB recherche toutes les commandes dont le champ user correspond à cet identifiant.

9. Fonction getOrderById

La fonction getOrderById permet de récupérer une commande précise à partir de son identifiant.

Le controller vérifie d'abord que l'identifiant fourni est valide.

Si aucune commande ne correspond à cet identifiant, le serveur retourne une erreur 404 avec le message Commande introuvable.

Si la commande existe, elle est retournée avec les informations de l'utilisateur et des produits associés.

10. Fonction getMyOrders

La fonction getMyOrders permet à l'utilisateur connecté de récupérer uniquement ses propres commandes.

L'identifiant est récupéré depuis le token JWT grâce à req.user.id ou req.user._id.

Cette fonction est utile pour afficher une page « Mes commandes » dans l'espace client.

11. Fonction updateOrderStatus

La fonction updateOrderStatus permet à l'administrateur de modifier l'état d'une commande.

Les statuts autorisés sont : En attente, En préparation, Expédiée, Livrée et Annulée.

Le controller vérifie que le nouveau statut appartient bien à cette liste avant de modifier la commande.

La méthode findByIdAndUpdate() permet ensuite de modifier le statut dans MongoDB.

12. Fonction updatePaymentStatus

La fonction updatePaymentStatus permet de modifier le statut du paiement associé à une commande.

Les trois statuts autorisés sont : En attente, Payé et Échec.

Cette fonction peut notamment être utilisée par l'administrateur pour suivre l'état des paiements.

13. Fonction deleteOrder

La fonction deleteOrder permet de supprimer une commande à partir de son identifiant.

Le controller vérifie d'abord que l'identifiant est valide.

La méthode findByIdAndDelete() supprime ensuite la commande de MongoDB.

14. Payment Controller - Gestion des paiements

Le Payment Controller est responsable de l'intégration avec Stripe. Il permet de créer une session de paiement, récupérer les paiements pour l'administrateur et traiter les notifications envoyées par Stripe.

15. Fonction createCheckoutSession

La fonction createCheckoutSession permet de créer une session Stripe Checkout pour une commande.

Elle récupère orderId depuis la requête envoyée par le frontend.

Le controller vérifie ensuite que l'utilisateur est connecté.

Il recherche la commande dans MongoDB et vérifie que cette commande appartient bien à l'utilisateur connecté.

Cette vérification est importante afin d'empêcher un utilisateur de payer ou d'accéder à la commande d'un autre utilisateur.

16. Vérification du paiement

Avant de créer une nouvelle session Stripe, le controller vérifie que la commande n'est pas déjà payée.

Il vérifie également que la commande contient des produits et que son montant total est supérieur à zéro.

17. Création du Payment

Un document Payment est créé dans MongoDB avec l'identifiant de la commande, l'identifiant de l'utilisateur, le montant, la devise, Stripe comme méthode et le statut pending.

18. Création des produits Stripe

Chaque produit de la commande est transformé en line_item Stripe.

Stripe reçoit le nom du produit, son prix converti en centimes et sa quantité.

Le prix est multiplié par 100 car Stripe utilise généralement la plus petite unité de la devise.

19. Création de la session Stripe

La méthode stripe.checkout.sessions.create() crée la page de paiement Stripe.

Le mode utilisé est payment, ce qui correspond à un paiement unique.

Après le paiement, Stripe redirige le client vers payment-success. En cas d'annulation, le client est redirigé vers payment-cancel.

Les métadonnées Stripe contiennent l'identifiant de la commande et l'identifiant du paiement MongoDB. Ces informations permettent ensuite de retrouver les documents correspondants lorsque Stripe confirme le paiement.

20. Fonction getAllPayments

La fonction getAllPayments permet à l'administrateur de récupérer tous les paiements enregistrés.

Les informations de l'utilisateur et de la commande sont récupérées grâce à populate().

Les paiements sont triés du plus récent au plus ancien.

21. Fonction stripeWebhook

Le webhook Stripe permet à Stripe d'informer automatiquement le backend lorsqu'un événement de paiement se produit.

Le controller utilise la signature stripe-signature pour vérifier que la notification provient réellement de Stripe.

Le secret STRIPE_WEBHOOK_SECRET est utilisé pour vérifier cette signature.

22. Confirmation du paiement Stripe

Lorsque l'événement est checkout.session.completed, cela signifie que la session Checkout a été complétée.

Le controller récupère alors orderId et paymentId depuis les métadonnées Stripe.

Le paiement MongoDB est ensuite mis à jour avec le statut paid.

La commande est également mise à jour avec le statut de paiement Payé.

Son statut de commande devient automatiquement En préparation.

23. Product Controller - Gestion des produits

Le Product Controller permet à l'administrateur de gérer les produits disponibles dans la boutique.

24. Fonction createProduct

La fonction createProduct permet de créer un nouveau produit.

Elle récupère le nom, le prix, le stock et la catégorie depuis req.body.

L'image est récupérée depuis req.file lorsqu'une image est envoyée avec la requête.

Le produit est ensuite enregistré dans MongoDB avec Product.create().

25. Fonction getProducts

La fonction getProducts récupère tous les produits enregistrés dans MongoDB.

Elle utilise Product.find() et retourne les produits au frontend sous forme JSON.

26. Fonction updateProduct

La fonction updateProduct permet de modifier un produit existant.

Le produit est recherché avec son identifiant grâce à Product.findById().

Si le produit n'existe pas, le serveur retourne une erreur 404.

Les champs envoyés par le frontend sont ensuite modifiés. Le controller ne modifie que les champs présents dans la requête.

Si une nouvelle image est envoyée, le chemin de cette nouvelle image remplace l'ancienne image.

27. Sales Controller - Statistiques des ventes

Le Sales Controller permet de calculer les statistiques commerciales utilisées dans le dashboard administrateur.

28. Fonction getSalesOverview

La fonction getSalesOverview récupère les commandes qui ne sont pas annulées.

Elle calcule ensuite le chiffre d'affaires total en additionnant les montants de toutes les commandes.

Elle calcule également le nombre total de commandes.

Le panier moyen est calculé en divisant le chiffre d'affaires par le nombre de commandes.

Si aucune commande n'existe, le panier moyen est défini sur zéro afin d'éviter une division par zéro.

29. Fonction getSalesByDay

La fonction getSalesByDay utilise l'agrégation MongoDB pour calculer les ventes par jour.

Les commandes annulées sont exclues des statistiques.

MongoDB regroupe les commandes selon leur date de création avec $dateToString.

Pour chaque jour, le système calcule le montant total des ventes et le nombre de commandes.

Les résultats sont ensuite triés par date. Ces données peuvent être utilisées pour créer un graphique dans le dashboard administrateur.

30. Settings Controller - Paramètres de la boutique

Le Settings Controller permet de récupérer et de modifier les paramètres généraux de la boutique.

31. Fonction getSettings

La fonction getSettings recherche les paramètres enregistrés dans MongoDB.

Si aucun document Settings n'existe encore, le controller crée automatiquement un nouveau document avec les valeurs par défaut.

Cette méthode permet donc à l'application d'avoir toujours une configuration disponible.

32. Fonction updateSettings

La fonction updateSettings permet à l'administrateur de modifier les paramètres de la boutique.

Elle peut modifier le nom de la boutique, l'e-mail, le téléphone, l'adresse et la devise.

Elle peut également activer ou désactiver les commandes.

Le mode maintenance peut être activé ou désactivé.

Les paramètres de livraison peuvent également être modifiés, notamment l'activation de la livraison et les frais de livraison.

Le paiement Stripe peut également être activé ou désactivé avec le champ stripeEnabled.

33. Auth Controller - Authentification

Le Auth Controller permet de gérer l'inscription, la connexion et la gestion des clients.

34. Fonction register

La fonction register permet de créer un nouveau compte utilisateur.

Elle récupère le nom d'utilisateur, l'e-mail et le mot de passe depuis la requête.

Elle vérifie que les trois informations obligatoires sont présentes.

Elle vérifie ensuite si l'e-mail existe déjà dans MongoDB. Deux utilisateurs ne peuvent donc pas utiliser le même e-mail.

35. Cryptage du mot de passe

Avant d'enregistrer l'utilisateur, le mot de passe est transformé avec bcrypt.hash().

Le mot de passe original n'est donc pas enregistré directement dans MongoDB.

36. Création du token JWT

Après la création du compte, le backend génère un token JWT avec jwt.sign().

Le token contient l'identifiant de l'utilisateur, son e-mail et son rôle.

Le token est configuré pour expirer après sept jours.

Le frontend peut ensuite stocker ce token et l'envoyer dans les requêtes nécessitant une authentification.

37. Fonction login

La fonction login permet à un utilisateur existant de se connecter à son compte.

Elle récupère l'e-mail et le mot de passe envoyés par le frontend.

L'e-mail est nettoyé avec trim() et converti en minuscules.

Le backend recherche ensuite l'utilisateur correspondant dans MongoDB.

Le mot de passe fourni est comparé avec le mot de passe hashé enregistré dans MongoDB grâce à bcrypt.compare().

Si les informations sont correctes, un nouveau token JWT est généré et envoyé au frontend.

38. Fonction getCustomers

La fonction getCustomers permet à l'administrateur de récupérer tous les utilisateurs ayant le rôle user.

Le champ password est volontairement exclu de la réponse grâce à select("-password").

Les clients sont triés du plus récent au plus ancien.

39. Fonction getCustomerById

La fonction getCustomerById permet de récupérer les informations d'un client précis à partir de son identifiant.

Le mot de passe est également exclu de la réponse.

Le controller vérifie que l'utilisateur possède bien le rôle user.

40. Fonction deleteCustomer

La fonction deleteCustomer permet à l'administrateur de supprimer un client.

Le controller recherche uniquement les utilisateurs possédant le rôle user.

Si le client existe, il est supprimé avec findOneAndDelete().

41. Fonctionnement général du backend

Le frontend React envoie des requêtes HTTP vers le backend Node.js et Express.

Les routes Express dirigent les requêtes vers les controllers correspondants.

Les controllers appliquent les règles métier, vérifient les données et utilisent les modèles Mongoose pour communiquer avec MongoDB.

MongoDB stocke les utilisateurs, les produits, les commandes, les paiements et les paramètres de la boutique.

Stripe intervient dans le processus de paiement. Le backend crée une session Stripe et le webhook Stripe informe ensuite le backend lorsque le paiement est terminé.

42. Architecture globale

Le fonctionnement général peut être résumé ainsi : React représente le frontend, Express et Node.js représentent le backend, les controllers contiennent la logique métier, les modèles Mongoose définissent les structures MongoDB, MongoDB stocke les données, JWT gère l'authentification et Stripe gère les paiements.

Cette architecture permet de séparer clairement l'interface utilisateur, la logique métier, la base de données, l'authentification et le paiement.
