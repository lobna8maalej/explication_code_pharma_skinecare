```html Explicação de AdminProducts, AdminSales e AdminSettings

Explicação dos componentes AdminProducts, AdminSales e AdminSettings

1. Visão geral do AdminProducts

O componente AdminProducts permite ao administrador gerenciar os produtos da loja.

Ele permite exibir a lista de produtos, modificar suas informações, atualizar rapidamente o estoque e excluir um produto.

2. Imports do AdminProducts

useState é um Hook do React que permite criar e gerenciar as variáveis de estado do componente.

useEffect permite executar uma função automaticamente quando uma condição específica é atendida. Aqui, ele é utilizado para buscar os produtos quando a página é carregada.

axios permite que o frontend React se comunique com o backend Node.js/Express por meio de requisições HTTP.

AdminNavbar representa a barra de navegação utilizada na área administrativa.

3. Variáveis useState

A variável products contém a lista de produtos recuperados do backend.

A variável loading indica se os produtos ainda estão sendo carregados.

editingProduct contém o produto atualmente selecionado para edição.

As variáveis name, price, stock e category correspondem aos campos do formulário de edição.

updatingStock indica qual produto está atualmente passando por uma atualização de estoque.

4. Recuperação dos produtos

A função fetchProducts() permite recuperar os produtos do backend.

Ela utiliza uma requisição HTTP GET para: /api/products.

Quando o backend responde, os produtos são armazenados no estado products.

O código verifica vários formatos possíveis de resposta, por exemplo, um array diretamente ou um array dentro de response.data.products.

5. useEffect no AdminProducts

O código utiliza useEffect com um array de dependências vazio.

Isso significa que fetchProducts() é executada quando o componente é carregado.

O objetivo é recuperar automaticamente os produtos quando o administrador abre a página.

6. Atualização do estoque

A função updateStock() permite modificar a quantidade disponível de um produto.

Antes de realizar a atualização, o código verifica se o estoque não é negativo.

O token JWT é recuperado do localStorage.

O token é enviado ao backend no cabeçalho: Authorization: Bearer TOKEN.

Em seguida, uma requisição PUT é enviada para: /products/:id.

7. Aumentar o estoque

A função increaseStock() recupera o estoque atual do produto e adiciona uma unidade.

Por exemplo, se o estoque for igual a 10, o novo estoque será 11.

8. Diminuir o estoque

A função decreaseStock() remove uma unidade do estoque.

O código verifica se o estoque atual é maior que zero. Isso evita que a quantidade se torne negativa.

9. Editar um produto

A função handleEdit() permite ao administrador selecionar um produto.

As informações do produto selecionado são então colocadas nos campos do formulário.

O administrador pode modificar o nome, o preço, o estoque e a categoria.

10. Salvar as alterações

A função handleUpdate() é executada quando o administrador envia o formulário.

Ela valida os dados informados e depois envia uma requisição PUT ao backend.

O preço e o estoque são convertidos em números usando Number().

11. Excluir um produto

A função handleDelete() permite excluir um produto.

Antes da exclusão, window.confirm() solicita uma confirmação ao administrador.

Se o administrador confirmar, uma requisição DELETE é enviada ao backend.

Após a exclusão, filter() é utilizado para remover o produto da lista exibida.

12. Status do estoque

O componente exibe diferentes mensagens de acordo com a quantidade disponível.

Se o estoque for igual a zero, o produto exibe "Sem estoque".

Se o estoque estiver entre 1 e 5, o produto exibe "Estoque baixo".

Se o estoque for maior que 5, o produto exibe "Em estoque".

13. Visão geral do AdminSales

O componente AdminSales permite ao administrador consultar as estatísticas comerciais da loja.

Ele exibe o faturamento, o número de pedidos, o valor médio dos pedidos e a evolução das vendas por dia.

14. Estados do AdminSales

O objeto sales contém as estatísticas gerais de vendas.

totalSales representa o faturamento total.

totalOrders representa o número de pedidos.

averageOrder representa o valor médio de um pedido.

dailySales contém as vendas agrupadas por dia.

15. Recuperação das estatísticas de vendas

A função fetchSales() primeiro recupera o token do administrador.

Em seguida, envia uma requisição para: /sales/overview.

Essa rota retorna as estatísticas gerais da loja.

Uma segunda requisição é enviada para: /sales/by-day.

Essa rota permite obter as vendas diárias.

16. Tratamento de erros

O componente utiliza try, catch e finally para tratar requisições assíncronas.

Um erro 401 geralmente significa que o token não é mais válido ou que a sessão expirou.

Um erro 403 significa que o usuário não possui as permissões necessárias.

17. Formatação dos valores

A função formatMoney() utiliza toLocaleString("fr-FR").

Isso permite exibir os números de acordo com o formato francês, com duas casas decimais.

18. Formatação das datas

A função formatDate() transforma uma data como 2026-09-07 em: 07/09/2026.

19. Gráfico de vendas

O gráfico é criado diretamente com HTML e CSS. Nenhuma biblioteca gráfica externa é necessária.

A largura de cada barra depende do valor das vendas do dia em comparação com o valor máximo.

Quanto maior for o valor, maior será a barra exibida.

20. Tabela de vendas

A tabela exibe, para cada dia, a data, o número de pedidos, o faturamento e o valor médio dos pedidos.

O valor médio do pedido é calculado dividindo o faturamento pelo número de pedidos.

21. Visão geral do AdminSettings

O componente AdminSettings permite ao administrador configurar as configurações gerais da loja.

Ele permite modificar as informações da loja, a moeda, a entrega, o Stripe e o modo de manutenção.

22. Informações da loja

storeName contém o nome da loja.

email contém o endereço de e-mail da loja.

phone contém o número de telefone.

address contém o endereço da loja.

23. Configurações comerciais

currency define a moeda principal utilizada pela loja.

allowOrders permite ativar ou desativar os pedidos.

24. Configurações de entrega

deliveryEnabled permite ativar ou desativar a entrega.

deliveryFee corresponde à taxa de entrega.

25. Configurações do Stripe

stripeEnabled permite ativar ou desativar o Stripe.

stripeCurrency define a moeda utilizada para o Stripe.

stripeExchangeRate representa a taxa de câmbio utilizada pela aplicação.

Por exemplo, com uma taxa de câmbio de 0.32, um valor de 100 TND pode ser convertido em 32 unidades da moeda Stripe selecionada.

26. handleChange

A função handleChange() permite gerenciar as alterações realizadas em todos os campos do formulário.

Para um checkbox, o código utiliza checked. Para os outros campos, utiliza value.

A notação [name] permite modificar automaticamente a propriedade correspondente ao campo.

27. Salvar as configurações

A função handleSubmit() é executada quando o administrador clica no botão de salvar.

Os dados são preparados e depois enviados ao backend por meio de uma requisição PUT para /settings.

Após uma resposta positiva do servidor, as novas configurações são armazenadas no estado do React.

28. useState

useState permite armazenar dados que podem mudar durante o uso da página.

Quando a função de atualização do estado é chamada, o React atualiza automaticamente a interface.

29. useEffect

useEffect é utilizado principalmente aqui para realizar chamadas à API quando os componentes são carregados.

30. Axios

Axios é uma biblioteca JavaScript que permite enviar requisições HTTP.

No projeto, o Axios permite que o React se comunique com o servidor Node.js/Express.

31. localStorage e JWT

O token JWT é recuperado do localStorage.

Depois, ele é enviado ao backend com: Authorization: Bearer TOKEN.

Dessa forma, o backend pode verificar a identidade e as permissões do administrador.

32. map()

O método map() permite percorrer um array e criar um novo elemento para cada elemento do array.

Ele é utilizado principalmente para exibir produtos e vendas nas tabelas HTML.

33. filter()

O método filter() permite manter apenas os elementos que atendem a uma determinada condição.

No AdminProducts, ele pode ser utilizado, por exemplo, para remover um produto da lista após sua exclusão.

34. async e await

As palavras-chave async e await facilitam o trabalho com operações assíncronas, como chamadas à API.

O programa aguarda a resposta do servidor antes de continuar a execução de determinadas instruções.

35. try, catch e finally

try contém o código que pode gerar um erro.

catch captura o erro para que uma mensagem apropriada possa ser exibida.

finally permite executar uma ação em todos os casos, por exemplo, interromper o indicador de carregamento.

36. Arquitetura geral do projeto

O funcionamento geral é:

React → Axios → API Express → Middleware JWT → Controller → MongoDB → JSON Response → React

React representa o frontend. Axios envia as requisições. Express recebe as requisições. O middleware verifica a autenticação. O controller processa os dados. MongoDB armazena as informações.

Por fim, o backend retorna uma resposta JSON e o React atualiza a interface.

37. Pontos importantes a verificar

Porta da API: os componentes utilizam atualmente http://localhost:3000/api. É necessário verificar se o backend está realmente utilizando a porta 3000.

Categoria: o valor skinecare parece ser um erro de ortografia. Se o backend utiliza skincare, os dois valores devem ser idênticos.

Segurança: as validações realizadas no React não substituem as validações do backend.

Rotas: as rotas GET, PUT e DELETE utilizadas pelo React devem existir no backend Express.

38. Conclusão

AdminProducts permite gerenciar os produtos e o estoque.

AdminSales permite consultar o desempenho comercial e as vendas.

AdminSettings permite configurar as configurações gerais da loja, a entrega e os pagamentos.

Esses três componentes utilizam React, Axios, uma API Node.js/Express, MongoDB e autenticação JWT para construir uma área administrativa completa.
```
