React Code Explanation – PharmaShop

Complete documentation of how the e-commerce application works

1. General Overview of the PharmaShop Project

The PharmaShop project is an e-commerce application developed with React for the frontend and Node.js, Express and MongoDB for the backend. The main objective of this application is to allow users to browse pharmaceutical and skincare products, search and filter products, add them to a shopping cart, modify quantities, remove products, create an order and finally make a payment with Stripe.

The application also contains an authentication system that allows a user to create an account or log in. Depending on the user's role, particularly administrator or normal user, the application can redirect the user to different interfaces.

The React frontend communicates with the backend using Axios, while the backend communicates with MongoDB to retrieve or store data. The entire project therefore follows an architecture composed of a frontend interface, a backend API and a database.

2. login() Function

The login() function manages user authentication in the application. It receives two important parameters: user, which represents the information of the logged-in user, and token, which generally represents a JWT token used to authenticate the user.

The first instruction uses localStorage.setItem() to store the user information in the browser. Since localStorage cannot directly store a JavaScript object, JSON.stringify() converts the user object into JSON text.

The token is then saved under the key token. Finally, setUser(user) updates the React state containing the currently logged-in user.

3. Global Cart Management with CartContext

CartContext is used to manage the shopping cart globally in the React application. Without the Context API, the cart information would have to be passed between several components using props, which would make the application more difficult to maintain.

With createContext(), a shared space is created to contain the cart information and functions. The CartProvider component then contains this global state and provides the data to components located inside the Provider.

The cart is initialized with useState([]), which means that the cart array is empty when the application starts. Components such as Products, Cart and Checkout can then access the same data using useContext().

4. addToCart() Function

The addToCart() function adds a product to the cart. Before adding the product, the code uses the find() method to check whether a product with the same _id already exists.

If the product already exists, the map() method loops through the cart and creates a new version of the product with its quantity increased by one. The spread operator preserves the other product properties.

If the product does not exist yet, it is added to the array with the property quantity: 1. This logic therefore automatically manages product quantities in the cart.

5. Removing and Modifying Cart Products

The removeFromCart() function removes a product from the cart. It uses the filter() method to create a new array containing only the products whose identifier is different from the identifier of the product to be removed.

The updateQuantity() function changes the quantity of a product. If the new quantity is less than or equal to zero, the function automatically calls removeFromCart().

The clearCart() function completely empties the cart by using setCart([]).

6. Calculating the Number of Products and Total Amount

The code uses the reduce() method to perform calculations related to the cart. The cartCount variable represents the total number of items in the cart.

The cartTotal variable represents the total order amount. For each product, the price is multiplied by the quantity, and the result is then added to the overall total.

7. useCart() Function

useCart() is a custom hook created to simplify the use of CartContext. Instead of directly writing useContext(CartContext) in every component, the developer can simply call useCart().

This hook makes it easy to retrieve the cart, add and remove functions, quantity modification functions, the number of items and the total amount.

8. Auth Component

The Auth component manages two operations: login and registration. The isLogin variable determines the current form mode.

When isLogin is true, the form displays the login interface. When it is false, the form displays the registration interface. The username, email and password variables are React states used to control the form fields.

The component also uses useNavigate() to redirect the user to another page after a successful operation.

9. User Login

During login, the handleAuth() function first checks that the email address and password have been provided. Using trim() removes unnecessary spaces around the email address.

The email is also converted to lowercase using toLowerCase(). Axios then sends a POST request to /api/users/login.

If the response contains a token and a user, this information is stored in localStorage. The user's role is then checked. If the role is admin, the user is redirected to /admin. Otherwise, the user is redirected to /products.

10. User Registration

When the form is in registration mode, the username becomes required in addition to the email and password.

The information is grouped into a registerData object and then sent with Axios to /api/users/register.

The backend creates the new user and can return a token as well as the account information. The frontend saves this information in localStorage when it is available.

11. Error Handling in Auth

The login and registration requests are placed inside a try/catch block. If the server returns an error, the program enters the catch block.

The code uses err.response?.data?.message to try to retrieve the message sent by the backend. The ?. symbol corresponds to optional chaining and prevents an error if some properties do not exist.

12. Cart Component

The Cart component represents the shopping cart page. It retrieves the necessary information through CartContext. When cart.length is equal to zero, the application displays a message indicating that the cart is empty.

When the cart contains products, cart.map() is used to display each item. For every product, the application displays its name, price, quantity and subtotal.

The minus button decreases the quantity using updateQuantity(), while the plus button uses addToCart(). The delete button calls removeFromCart().

13. Checkout Component

Checkout represents the order completion step. This component retrieves information either from the cart or from a direct purchase.

useLocation() retrieves the information passed during navigation. If a product is sent directly, it is added to checkoutItems with a quantity of one.

Otherwise, the products from the cart are used. The component also contains a customer state containing the customer's first name, last name, phone number and address.

14. Customer Form Management

The handleChange() function dynamically updates the customer's information. It uses the HTML field name as the key of the customer object.

This technique avoids creating a separate function for each form field. The form therefore remains controlled by React, and the entered values are always available in the customer state.

15. Retrieving the User ID

The getUserIdFromToken() function retrieves the JWT token stored in localStorage. A JWT token generally contains three parts separated by dots.

The code retrieves the middle part, decodes it using atob(), and then converts the JSON result into a JavaScript object using JSON.parse().

The application then searches for an id, _id or userId property. This makes it possible to retrieve the identifier of the logged-in user and associate it with the order.

16. Preparing Products for the Order

Before creating an order, the code normalizes the product information. The getProductPrice() function searches for the price in several possible properties.

The getProductName() function searches for the product name in several possible properties such as name, productName or title.

The getProductQuantity() function searches for the quantity in qty or quantity and uses a minimum quantity of one.

17. Creating the Order

When the user submits the Checkout form, handleSubmit() first prevents the default form behavior using preventDefault().

The code then checks the customer information, products, token and user ID.

The products are transformed into orderItems containing the product, its name, price and quantity. The total amount is calculated using reduce.

The orderData object contains the products, customer information, Stripe payment method and initial payment status. This object is sent to the backend using a POST request to /api/orders.

18. Stripe Payment

After the order is created, Checkout retrieves the identifier of the order created by the backend.

A second request is then sent to /api/payments/create-checkout-session to ask the backend to create a Stripe payment session.

If the backend returns a valid Stripe URL, the frontend redirects the user to this URL using window.location.href. The user can then complete the payment on Stripe.

19. Home Component

The Home component represents the PharmaShop home page. It displays a title presenting the store, a subtitle explaining its activity and a button allowing access to the products.

The Link component from React Router is used to navigate to /products without completely reloading the application.

20. Orders Component

The Orders component displays the order history. In the provided code, orders are retrieved from localStorage using the key "orders".

If no orders are available, a message indicates that there are no orders yet. Otherwise, map is used to display each order with the customer, phone number, address, products, total amount and date.

An important point is that Checkout actually creates orders in the backend. If MongoDB is the official source of orders, it would be preferable for Orders to retrieve orders from a protected API route.

21. Product Component

The Product component displays the details of a product. useParams() retrieves the product identifier from the URL.

Axios then sends a GET request to /api/products/:id. The component contains loading and error states to correctly display the different situations while retrieving data.

Once the product has been retrieved, the application can display its name, image, price, category and description.

22. Product Image Management

The getImageUrl() function correctly builds the image URL. If the image already starts with http, it is considered a complete URL.

If the image corresponds to a relative path, the backend server address is added before the path. This logic is useful when MongoDB stores only the image path while the files are served by the Node.js server.

23. Products Component

Products is the page that displays the list of available products. At startup, products is initialized with an empty array.

useEffect is used to retrieve products from the API. Axios sends a GET request to /api/products.

The received data is then stored in the state using setProducts(). React automatically updates the display when this state changes.

24. Product Search and Filtering

The search variable allows the user to search for a product by name. The filter() method is used to select products matching the criteria.

The name is converted to lowercase using toLowerCase(), and then includes() checks whether the searched text exists in the product name.

The category filter compares the product category with the selected category. The price filter checks that the product price is less than or equal to the maximum price.

25. Adding to the Cart from Products

The handleAddToCart() function allows a product to be added directly to the cart from the product list.

Before adding it, some() checks whether the product already exists in the cart by comparing the _id identifiers.

This verification prevents duplicates and allows CartContext to correctly manage quantity increases.

26. Buy Now Function

handleBuyNow() allows a direct purchase of a product. The first step is to check whether the user is logged in by checking for the presence of the token in localStorage.

If no token exists, the selected product can temporarily be saved in localStorage under the key pendingProduct, and the user is redirected to the Auth page.

If the user is already logged in, the user is directly redirected to Checkout with the product passed through the navigation state.

27. Logout

handleLogout() logs the user out. The token, user information and temporary pendingProduct are removed from localStorage.

After this operation, the application redirects the user to the Auth page. Removing the token prevents future protected requests from using the old session.

28. Axios and Backend Communication

Axios is used in several components to communicate with the backend API. GET requests are mainly used to retrieve products or other information.

POST requests are used to send data, for example during login, registration, order creation or Stripe session creation.

The frontend uses the address http://localhost:3000/api as the API base in the provided code.

29. Complete Application Architecture

The overall operation can be summarized as a communication chain. The user first interacts with the React interface. React then uses Axios to send an HTTP request to the Express API.

Express receives the request and forwards it to the appropriate controller. The controller can read or modify data in MongoDB through Mongoose models.

The backend then returns a JSON response. React receives this response and updates its states using useState, which causes the interface to update.

React → Axios → Express → Controller → MongoDB → JSON → React

30. Using useState

useState is one of the main React Hooks. It allows data to be stored inside a component and modified.

In PharmaShop, useState is used to manage products, the cart, form fields, error messages, loading states and user information.

31. Using useEffect

useEffect allows an action to be executed after a component renders. It is particularly important in PharmaShop for making API calls when a page loads.

For example, Products uses useEffect to retrieve products, Product uses it to retrieve a specific product and Checkout uses it to prepare the products to be ordered.

32. Using React Router

React Router manages the different pages of the application without completely reloading the browser.

Link is used to create links, while useNavigate() is used to perform redirects from a JavaScript function.

useParams() retrieves parameters contained in the URL, while useLocation() retrieves information related to navigation.

33. Error and Loading Management

Backend requests can fail for different reasons: the server may be stopped, the URL may be incorrect, there may be a network error, an authentication problem or a server-side error.

This is why the code uses try, catch and sometimes finally. try contains the main operation, catch handles the error and finally allows an action that must happen in all cases to be performed.

34. Important Points to Check in the Project

The first point concerns the Orders component. In the provided code, Orders uses localStorage while Checkout sends orders to the backend. There is therefore a risk that orders created in MongoDB will not be visible in Orders.

For a real application, it is recommended to use MongoDB as the main source of orders and create a backend route allowing the authenticated user to retrieve their orders.

The second point concerns the category filter in Products. The code contains a category state and a filtering condition, but the provided JSX does not necessarily show an element allowing the user to select a category.

The third point concerns handleBuyNow. The function is designed to perform a direct purchase, but you should verify that the "Buy Now" button is actually present in the Products interface.

35. General Conclusion

The PharmaShop code implements a complete e-commerce application based on React. React is responsible for the user interface and state management, the Context API allows the cart to be shared between components, React Router manages navigation, Axios handles communication with the API and localStorage stores certain session-related information.

The Node.js and Express backend processes requests, verifies users, creates orders and prepares Stripe payments. MongoDB serves as the database used to store users, products and orders.

The overall process is therefore as follows: the user browses products, searches for or filters a product, adds products to the cart, logs in if necessary, enters delivery information, creates an order and is then redirected to Stripe to complete the payment.

This organization provides a solid foundation for a modern e-commerce application, provided that a clear separation is maintained between temporary browser data and official data stored in the backend and MongoDB.
