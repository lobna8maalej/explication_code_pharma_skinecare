```html Explanation of AdminProducts, AdminSales and AdminSettings

Explanation of the AdminProducts, AdminSales and AdminSettings Components

1. Overview of AdminProducts

The AdminProducts component allows the administrator to manage the store's products.

It allows the administrator to display the list of products, modify their information, quickly update their stock and delete a product.

2. AdminProducts Imports

useState is a React Hook that allows the component to create and manage state variables.

useEffect allows a function to be executed automatically when a specific condition is met. Here, it is used to retrieve the products when the page is loaded.

axios allows the React frontend to communicate with the Node.js/Express backend through HTTP requests.

AdminNavbar represents the navigation bar used in the administrator area.

3. useState Variables

The products variable contains the list of products retrieved from the backend.

The loading variable indicates whether the products are still being loaded.

editingProduct contains the product currently selected for editing.

The variables name, price, stock and category correspond to the fields of the edit form.

updatingStock indicates which product is currently undergoing a stock update.

4. Retrieving Products

The fetchProducts() function retrieves products from the backend.

It uses an HTTP GET request to: /api/products.

When the backend responds, the products are stored in the products state.

The code checks several possible response formats, for example a direct array or an array contained in response.data.products.

5. useEffect in AdminProducts

The code uses useEffect with an empty dependency array.

This means that fetchProducts() is executed when the component is loaded.

The goal is to automatically retrieve the products when the administrator opens the page.

6. Updating Stock

The updateStock() function allows the available quantity of a product to be modified.

Before performing the update, the code checks that the stock is not negative.

The JWT token is retrieved from localStorage.

The token is sent to the backend in the header: Authorization: Bearer TOKEN.

A PUT request is then sent to: /products/:id.

7. Increasing Stock

The increaseStock() function retrieves the current stock of the product and adds one unit.

For example, if the stock is equal to 10, the new stock becomes 11.

8. Decreasing Stock

The decreaseStock() function removes one unit from the stock.

The code checks that the current stock is greater than zero. This prevents the quantity from becoming negative.

9. Editing a Product

The handleEdit() function allows the administrator to select a product.

The information of the selected product is then placed into the form fields.

The administrator can then modify the name, price, stock and category.

10. Saving Changes

The handleUpdate() function is executed when the administrator submits the form.

It validates the entered data and then sends a PUT request to the backend.

The price and stock are converted into numbers using Number().

11. Deleting a Product

The handleDelete() function allows a product to be deleted.

Before deletion, window.confirm() asks the administrator for confirmation.

If the administrator confirms, a DELETE request is sent to the backend.

After deletion, filter() is used to remove the product from the displayed list.

12. Stock Status

The component displays different messages depending on the available quantity.

If the stock is equal to zero, the product displays "Rupture".

If the stock is between 1 and 5, the product displays "Stock faible".

If the stock is greater than 5, the product displays "En stock".

13. Overview of AdminSales

The AdminSales component allows the administrator to view the store's sales statistics.

It displays revenue, the number of orders, the average order value and the daily sales trend.

14. AdminSales States

The sales object contains the general sales statistics.

totalSales represents the total revenue.

totalOrders represents the number of orders.

averageOrder represents the average order value.

dailySales contains the sales grouped by day.

15. Retrieving Sales Statistics

The fetchSales() function first retrieves the administrator token.

It then sends a request to: /sales/overview.

This route returns the store's general statistics.

A second request is sent to: /sales/by-day.

This route retrieves the daily sales.

16. Error Handling

The component uses try, catch and finally to handle asynchronous requests.

A 401 error generally means that the token is no longer valid or that the session has expired.

A 403 error means that the user does not have the required permissions.

17. Amount Formatting

The formatMoney() function uses toLocaleString("fr-FR").

This allows numbers to be displayed according to the French format with two decimal places.

18. Date Formatting

The formatDate() function transforms a date such as 2026-09-07 into: 07/09/2026.

19. Sales Chart

The chart is created directly using HTML and CSS. No external chart library is required.

The width of each bar depends on the day's sales amount compared with the maximum sales amount.

The higher the amount, the larger the displayed bar.

20. Sales Table

The table displays the date, number of orders, revenue and average order value for each day.

The average order value is calculated by dividing the revenue by the number of orders.

21. Overview of AdminSettings

The AdminSettings component allows the administrator to configure the store's general settings.

It allows the administrator to modify store information, currency, delivery, Stripe and maintenance mode.

22. Store Information

storeName contains the store name.

email contains the store email address.

phone contains the phone number.

address contains the store address.

23. Commercial Settings

currency defines the main currency used by the store.

allowOrders allows orders to be enabled or disabled.

24. Delivery Settings

deliveryEnabled allows delivery to be enabled or disabled.

deliveryFee corresponds to the delivery fee.

25. Stripe Settings

stripeEnabled allows Stripe to be enabled or disabled.

stripeCurrency defines the currency used for Stripe.

stripeExchangeRate represents the exchange rate used by the application.

For example, with an exchange rate of 0.32, a value of 100 TND can be converted into 32 units of the selected Stripe currency.

26. handleChange

The handleChange() function manages changes to all form fields.

For a checkbox, the code uses checked. For other fields, it uses value.

The [name] notation allows the corresponding property of the field to be updated automatically.

27. Saving the Settings

The handleSubmit() function is executed when the administrator clicks the save button.

The data is prepared and then sent to the backend with a PUT request to /settings.

After a successful server response, the new settings are stored in the React state.

28. useState

useState allows data to be stored that may change while the page is being used.

When the state update function is called, React automatically updates the interface.

29. useEffect

useEffect is mainly used here to make API calls when the components are loaded.

30. Axios

Axios is a JavaScript library that allows HTTP requests to be sent.

In the project, Axios allows React to communicate with the Node.js/Express server.

31. localStorage and JWT

The JWT token is retrieved from localStorage.

It is then sent to the backend with: Authorization: Bearer TOKEN.

The backend can therefore verify the identity and permissions of the administrator.

32. map()

The map() method allows an array to be iterated over and creates a new element for each element in the array.

It is used in particular to display products and sales in HTML tables.

33. filter()

The filter() method keeps only the elements that satisfy a condition.

In AdminProducts, it can for example be used to remove a product after it has been deleted.

34. async and await

The async and await keywords make it easier to work with asynchronous operations such as API calls.

The program waits for the server response before continuing the execution of certain instructions.

35. try, catch and finally

try contains the code that may generate an error.

catch captures the error so that an appropriate message can be displayed.

finally allows an action to be executed in all cases, for example stopping the loading indicator.

36. General Project Architecture

The general workflow is:

React → Axios → Express API → JWT Middleware → Controller → MongoDB → JSON Response → React

React represents the frontend. Axios sends the requests. Express receives the requests. The middleware verifies authentication. The controller processes the data. MongoDB stores the information.

Finally, the backend returns a JSON response and React updates the interface.

37. Important Points to Check

API Port: the components currently use http://localhost:3000/api. You must verify that the backend is actually using port 3000.

Category: the value skinecare appears to be a spelling mistake. If the backend uses skincare, both values must be identical.

Security: validations performed in React do not replace backend validation.

Routes: the GET, PUT and DELETE routes used by React must exist in the Express backend.

38. Conclusion

AdminProducts allows products and stock to be managed.

AdminSales allows the administrator to view sales performance and sales statistics.

AdminSettings allows the administrator to configure the store's general settings, delivery and payment options.

These three components use React, Axios, a Node.js/Express API, MongoDB and JWT authentication to build a complete administration area.
```
