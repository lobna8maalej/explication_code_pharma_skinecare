Explicação dos modelos MongoDB

Esta página explica os diferentes modelos MongoDB utilizados na aplicação de e-commerce Pharma & Skincare. Os modelos definem a estrutura dos dados armazenados no MongoDB usando Mongoose.

1. Conexão com o MongoDB

O arquivo de conexão permite que a aplicação Node.js se conecte ao banco de dados MongoDB.

O método mongoose.connect() utiliza o endereço mongodb://localhost:27017/ecommerce. Isso significa que o MongoDB está sendo executado localmente no computador e que o banco de dados utilizado se chama ecommerce.

A função connectDB é uma função assíncrona. Ela utiliza try/catch para detectar qualquer possível erro de conexão com o MongoDB.

Quando a conexão é realizada com sucesso, a mensagem MongoDB connected é exibida no console. Em caso de erro, a mensagem DB connection error é exibida.

2. Modelo Order - Pedidos

O modelo Order representa os pedidos realizados pelos clientes na loja Pharma & Skincare.

Usuário

O campo user contém o identificador MongoDB do cliente que realizou o pedido. Ele utiliza uma referência ao modelo User.

O campo é opcional devido a required: false. Portanto, um pedido pode eventualmente ser registrado sem um usuário conectado.

Informações do cliente

O bloco customer contém as informações necessárias para a entrega e o contato com o cliente.

Ele contém o nome, sobrenome, endereço de e-mail, número de telefone e endereço do cliente.

Produtos pedidos

O campo items é um array que contém os produtos incluídos no pedido.

Cada item contém o identificador do produto, seu nome, preço e quantidade solicitada.

O campo product utiliza uma referência ao modelo Product. Isso permite relacionar o pedido ao produto correspondente.

Total do pedido

O campo totalAmount representa o valor total do pedido. Ele é obrigatório devido a required: true.

Pagamento

O campo paymentMethod indica o método de pagamento. Na sua aplicação, o valor padrão é Stripe.

O campo paymentStatus indica o status do pagamento. Ele pode ser En attente, Payé ou Échec.

Status do pedido

O campo orderStatus é utilizado para acompanhar a evolução do pedido.

Um pedido pode estar: En attente, En préparation, Expédiée, Livrée ou Annulée.

Carimbos de data e hora

A opção timestamps: true adiciona automaticamente dois campos: createdAt e updatedAt. Eles permitem conhecer a data de criação e a data da última modificação do pedido.

3. Modelo Payment - Pagamentos

O modelo Payment é utilizado para armazenar informações sobre os pagamentos realizados para os pedidos.

Pedido

O campo orderId contém o identificador do pedido associado ao pagamento. Ele possui uma referência ao modelo Order.

Usuário

O campo userId contém o identificador do cliente que realizou o pagamento. Ele possui uma referência ao modelo User.

Valor

O campo amount representa o valor do pagamento. Ele é obrigatório.

Moeda

O campo currency indica a moeda utilizada para o pagamento. Por padrão, a moeda é USD.

A opção lowercase: true converte automaticamente o valor para letras minúsculas. Por exemplo, USD se torna usd.

Método de pagamento

O campo method indica o método de pagamento. Neste modelo, somente o método stripe é permitido.

Informações do Stripe

stripeSessionId contém o ID da sessão do Stripe Checkout.

stripePaymentIntentId contém o ID do PaymentIntent do Stripe quando disponível.

Status do pagamento

O campo status indica o status do pagamento. Ele pode ser pending, paid, failed ou refunded.

Isso permite que a administração determine se um pedido foi pago, se o pagamento falhou ou se o valor foi reembolsado.

4. Modelo Product - Produtos

O modelo Product representa os produtos vendidos na loja Pharma & Skincare.

Nome do produto

O campo name contém o nome do produto. Ele é obrigatório, e a opção trim: true remove espaços desnecessários no início e no final.

Preço

O campo price contém o preço do produto. Ele é obrigatório.

Estoque

O campo stock representa a quantidade disponível do produto. Seu valor padrão é 0.

O valor não pode ser negativo devido a min: 0.

Categoria

O campo category é utilizado para classificar os produtos. Por exemplo: cuidados faciais, cuidados capilares, maquiagem ou proteção solar.

Imagem

O campo image contém a URL ou o caminho da imagem do produto. Se nenhuma imagem for fornecida, seu valor será uma string vazia.

Carimbos de data e hora

Com timestamps: true, o MongoDB adiciona automaticamente createdAt e updatedAt.

5. Modelo Settings - Configurações da loja

O modelo Settings permite que o administrador salve as configurações gerais da loja.

Informações da loja

Os campos storeName, email, phone e address contêm as informações gerais da loja.

Moeda

O campo currency representa a moeda utilizada pela loja. Por padrão, ela é definida como TND.

Pedidos

O campo allowOrders permite que o administrador ative ou desative os pedidos. Seu valor padrão é true.

Modo de manutenção

O campo maintenanceMode permite que o administrador ative ou desative o modo de manutenção do site.

Entrega

O campo deliveryEnabled permite que o administrador ative ou desative a entrega.

O campo deliveryFee contém o custo da entrega. Por padrão, ele é igual a 0.

Stripe

O campo stripeEnabled permite que o administrador ative ou desative o Stripe.

O campo stripeCurrency indica a moeda utilizada pelo Stripe. No seu modelo, ela é definida como USD por padrão.

O campo stripeExchangeRate representa a taxa de conversão entre TND e a moeda utilizada pelo Stripe.

Por exemplo, com um valor de 0.32, uma conversão pode ser realizada de acordo com a taxa de câmbio configurada pelo administrador.

6. Modelo User - Usuários

O modelo User é utilizado para gerenciar as contas dos usuários da aplicação.

Email

O campo email contém o endereço de e-mail do usuário. Ele é obrigatório e único.

A opção lowercase: true armazena automaticamente o endereço de e-mail em letras minúsculas.

Username

O campo username contém o nome de usuário. Ele é obrigatório.

Password

O campo password contém a senha do usuário. Ele é obrigatório.

Na prática, a senha não deve ser armazenada em texto simples. Ela deve ser transformada em hash antes de ser armazenada no MongoDB, por exemplo usando bcrypt.

Função

O campo role determina as permissões do usuário.

Existem duas funções disponíveis: user para um cliente e admin para um administrador.

Por padrão, um novo usuário possui a função user.

Carimbos de data e hora

A opção timestamps: true armazena automaticamente as datas de criação e modificação da conta.

7. Relações entre os modelos

Os diferentes modelos estão conectados entre si usando identificadores MongoDB do tipo ObjectId.

Um User pode realizar vários pedidos Order.

Um Order pode conter vários produtos Product.

Um Order pode ter um pagamento Payment.

O modelo Settings contém as configurações gerais da loja, incluindo as configurações do Stripe, entrega, moeda e modo de manutenção.

8. Resumo do funcionamento

O usuário cria uma conta utilizando o modelo User.

O usuário consulta os produtos armazenados em Product.

O usuário adiciona os produtos ao carrinho e depois confirma o pedido. As informações do pedido são armazenadas em Order.

Quando o usuário realiza um pagamento com Stripe, as informações do pagamento são armazenadas em Payment.

O administrador pode então consultar os pedidos, pagamentos e produtos e modificar as configurações da loja utilizando o modelo Settings.

Todos esses modelos permitem, portanto, construir o backend da loja de e-commerce Pharma & Skincare utilizando Node.js, Express, MongoDB e Mongoose.
