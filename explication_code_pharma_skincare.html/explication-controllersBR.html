Explicação dos Controllers do Backend

Esta página explica o funcionamento dos diferentes controllers utilizados na aplicação de comércio eletrônico Pharma & Skincare. Os controllers contêm a lógica de negócio do backend. Eles recebem as requisições enviadas pelo frontend, processam os dados e retornam uma resposta ao cliente.

1. Order Controller - Gerenciamento de pedidos

O Order Controller gerencia todas as operações relacionadas aos pedidos dos clientes. Ele permite que a aplicação crie um pedido, recupere pedidos, atualize seu status e exclua um pedido.

2. Função createOrder

A função createOrder permite criar um novo pedido. Ela recupera as informações enviadas pelo frontend através de req.body.

As informações recuperadas incluem os produtos pedidos, as informações do cliente, o método de pagamento e o status do pagamento.

O controller primeiro verifica se items é um array e se contém pelo menos um produto. Portanto, um pedido vazio é rejeitado.

Em seguida, o controller recupera o identificador do usuário conectado usando req.user.id ou req.user._id. Essas informações geralmente vêm do middleware de autenticação JWT.

O identificador do usuário é então validado para garantir que possui um formato MongoDB ObjectId válido.

3. Validação dos produtos do pedido

Para cada produto incluído no pedido, o controller verifica se existe um identificador de produto.

Ele também verifica se o nome do produto não está vazio.

O preço é convertido para número usando Number() e deve ser maior ou igual a zero.

A quantidade também é convertida para número e deve ser maior ou igual a um.

Essas validações ajudam a impedir que dados incorretos sejam armazenados no MongoDB.

4. Cálculo do total do pedido

O controller calcula automaticamente o valor total do pedido. Para cada produto, o preço é multiplicado pela quantidade.

Todos os resultados são então somados para obter o valor total do pedido.

O método toFixed(2) mantém duas casas decimais.

5. Criação do pedido no MongoDB

Depois que todas as validações são concluídas, o controller utiliza Order.create() para salvar o pedido no MongoDB.

O pedido contém o usuário, as informações do cliente, os produtos, o valor total, o método de pagamento, o status do pagamento e o status do pedido.

O status inicial do pedido é definido como En attente.

6. Population do pedido

Após a criação, o controller utiliza populate() para recuperar as informações completas do usuário e dos produtos.

A relação user permite recuperar as informações do usuário.

A relação items.product permite recuperar as informações dos produtos associados ao pedido.

7. Função getAllOrders

A função getAllOrders permite ao administrador recuperar todos os pedidos armazenados no MongoDB.

Os pedidos são classificados pela data de criação em ordem decrescente. Portanto, os pedidos mais recentes aparecem primeiro.

As informações dos usuários e dos produtos também são recuperadas usando populate().

Essa função é utilizada principalmente pelo dashboard do administrador.

8. Função getUserOrders

A função getUserOrders recupera todos os pedidos pertencentes a um usuário específico.

O identificador do usuário é recuperado através de req.params.userId.

O controller verifica se esse identificador existe e corresponde a um ObjectId MongoDB válido.

O MongoDB então procura todos os pedidos cujo campo user corresponde a esse identificador.

9. Função getOrderById

A função getOrderById recupera um pedido específico usando seu identificador.

O controller primeiro verifica se o identificador fornecido é válido.

Se nenhum pedido corresponder a esse identificador, o servidor retorna um erro 404 com a mensagem Commande introuvable.

Se o pedido existir, ele será retornado com as informações do usuário e dos produtos associados.

10. Função getMyOrders

A função getMyOrders permite que o usuário conectado recupere apenas seus próprios pedidos.

O identificador é recuperado do token JWT usando req.user.id ou req.user._id.

Essa função é útil para exibir uma página "Meus pedidos" na área do cliente.

11. Função updateOrderStatus

A função updateOrderStatus permite ao administrador modificar o status de um pedido.

Os status permitidos são: En attente, En préparation, Expédiée, Livrée e Annulée.

O controller verifica se o novo status pertence a essa lista antes de atualizar o pedido.

O método findByIdAndUpdate() é então utilizado para atualizar o status no MongoDB.

12. Função updatePaymentStatus

A função updatePaymentStatus permite modificar o status do pagamento associado a um pedido.

Os três status permitidos são: En attente, Payé e Échec.

Essa função pode ser utilizada pelo administrador para acompanhar o status dos pagamentos.

13. Função deleteOrder

A função deleteOrder permite excluir um pedido usando seu identificador.

O controller primeiro verifica se o identificador é válido.

O método findByIdAndDelete() então remove o pedido do MongoDB.

14. Payment Controller - Gerenciamento de pagamentos

O Payment Controller é responsável pela integração com o Stripe. Ele permite criar uma sessão de pagamento, recuperar pagamentos para o administrador e processar notificações enviadas pelo Stripe.

15. Função createCheckoutSession

A função createCheckoutSession permite criar uma sessão do Stripe Checkout para um pedido.

Ela recupera orderId da requisição enviada pelo frontend.

O controller verifica então se o usuário está conectado.

Ele procura o pedido no MongoDB e verifica se o pedido realmente pertence ao usuário conectado.

Essa verificação é importante para impedir que um usuário pague ou acesse o pedido de outro usuário.

16. Verificação do pagamento

Antes de criar uma nova sessão do Stripe, o controller verifica se o pedido ainda não foi pago.

Ele também verifica se o pedido contém produtos e se seu valor total é maior que zero.

17. Criação do Payment

Um documento Payment é criado no MongoDB com o identificador do pedido, o identificador do usuário, o valor, a moeda, Stripe como método e o status pending.

18. Criação dos produtos do Stripe

Cada produto do pedido é transformado em um line_item do Stripe.

O Stripe recebe o nome do produto, seu preço convertido em centavos e sua quantidade.

O preço é multiplicado por 100 porque o Stripe geralmente utiliza a menor unidade da moeda.

19. Criação da sessão do Stripe

O método stripe.checkout.sessions.create() cria a página de pagamento do Stripe.

O modo utilizado é payment, que corresponde a um pagamento único.

Após o pagamento, o Stripe redireciona o cliente para payment-success. Em caso de cancelamento, o cliente é redirecionado para payment-cancel.

Os metadados do Stripe contêm o identificador do pedido e o identificador do pagamento no MongoDB. Essas informações são utilizadas para encontrar os documentos correspondentes quando o Stripe confirma o pagamento.

20. Função getAllPayments

A função getAllPayments permite ao administrador recuperar todos os pagamentos registrados.

As informações do usuário e do pedido são recuperadas usando populate().

Os pagamentos são classificados do mais recente para o mais antigo.

21. Função stripeWebhook

O webhook do Stripe permite que o Stripe informe automaticamente o backend quando ocorre um evento de pagamento.

O controller utiliza a assinatura stripe-signature para verificar se a notificação realmente veio do Stripe.

O segredo STRIPE_WEBHOOK_SECRET é utilizado para verificar essa assinatura.

22. Confirmação do pagamento do Stripe

Quando o evento é checkout.session.completed, significa que a sessão Checkout foi concluída.

O controller recupera então orderId e paymentId dos metadados do Stripe.

O pagamento no MongoDB é então atualizado com o status paid.

O pedido também é atualizado com o status de pagamento Payé.

O status do pedido passa automaticamente para En préparation.

23. Product Controller - Gerenciamento de produtos

O Product Controller permite ao administrador gerenciar os produtos disponíveis na loja.

24. Função createProduct

A função createProduct permite criar um novo produto.

Ela recupera o nome, o preço, o estoque e a categoria de req.body.

A imagem é recuperada de req.file quando uma imagem é enviada com a requisição.

O produto é então salvo no MongoDB usando Product.create().

25. Função getProducts

A função getProducts recupera todos os produtos armazenados no MongoDB.

Ela utiliza Product.find() e retorna os produtos ao frontend em formato JSON.

26. Função updateProduct

A função updateProduct permite modificar um produto existente.

O produto é pesquisado usando seu identificador com Product.findById().

Se o produto não existir, o servidor retorna um erro 404.

Os campos enviados pelo frontend são então modificados. O controller modifica apenas os campos presentes na requisição.

Se uma nova imagem for enviada, o caminho da nova imagem substitui a imagem anterior.

27. Sales Controller - Estatísticas de vendas

O Sales Controller calcula as estatísticas de vendas utilizadas no dashboard do administrador.

28. Função getSalesOverview

A função getSalesOverview recupera os pedidos que não estão cancelados.

Em seguida, calcula a receita total somando os valores de todos os pedidos.

Ela também calcula o número total de pedidos.

O valor médio do pedido é calculado dividindo a receita pelo número de pedidos.

Se não houver pedidos, o valor médio do pedido é definido como zero para evitar uma divisão por zero.

29. Função getSalesByDay

A função getSalesByDay utiliza a agregação do MongoDB para calcular as vendas por dia.

Os pedidos cancelados são excluídos das estatísticas.

O MongoDB agrupa os pedidos de acordo com sua data de criação usando $dateToString.

Para cada dia, o sistema calcula o valor total das vendas e o número de pedidos.

Os resultados são então ordenados por data. Esses dados podem ser utilizados para criar um gráfico no dashboard do administrador.

30. Settings Controller - Configurações da loja

O Settings Controller permite que a aplicação recupere e modifique as configurações gerais da loja.

31. Função getSettings

A função getSettings procura as configurações armazenadas no MongoDB.

Se ainda não existir nenhum documento Settings, o controller cria automaticamente um novo documento com os valores padrão.

Esse método garante que a aplicação sempre tenha uma configuração disponível.

32. Função updateSettings

A função updateSettings permite ao administrador modificar as configurações da loja.

Ela pode modificar o nome da loja, o e-mail, o telefone, o endereço e a moeda.

Ela também pode ativar ou desativar os pedidos.

O modo de manutenção pode ser ativado ou desativado.

As configurações de entrega também podem ser modificadas, incluindo a ativação da entrega e as taxas de entrega.

Os pagamentos com Stripe também podem ser ativados ou desativados usando o campo stripeEnabled.

33. Auth Controller - Autenticação

O Auth Controller gerencia o cadastro, o login e o gerenciamento dos clientes.

34. Função register

A função register permite criar uma nova conta de usuário.

Ela recupera o nome de usuário, o e-mail e a senha da requisição.

Ela verifica se todas as três informações obrigatórias estão presentes.

Em seguida, verifica se o e-mail já existe no MongoDB. Portanto, dois usuários não podem utilizar o mesmo endereço de e-mail.

35. Criptografia da senha

Antes de salvar o usuário, a senha é transformada usando bcrypt.hash().

Portanto, a senha original não é armazenada diretamente no MongoDB.

36. Criação do token JWT

Depois que a conta é criada, o backend gera um token JWT usando jwt.sign().

O token contém o identificador do usuário, seu e-mail e seu papel.

O token é configurado para expirar após sete dias.

O frontend pode então armazenar esse token e enviá-lo nas requisições que exigem autenticação.

37. Função login

A função login permite que um usuário existente faça login em sua conta.

Ela recupera o e-mail e a senha enviados pelo frontend.

O e-mail é limpo usando trim() e convertido para letras minúsculas.

O backend então procura o usuário correspondente no MongoDB.

A senha fornecida é comparada com a senha hash armazenada no MongoDB usando bcrypt.compare().

Se as informações estiverem corretas, um novo token JWT é gerado e enviado ao frontend.

38. Função getCustomers

A função getCustomers permite ao administrador recuperar todos os usuários que possuem o papel user.

O campo password é intencionalmente excluído da resposta usando select("-password").

Os clientes são classificados do mais recente para o mais antigo.

39. Função getCustomerById

A função getCustomerById permite ao administrador recuperar as informações de um cliente específico usando seu identificador.

A senha também é excluída da resposta.

O controller verifica se o usuário possui o papel user.

40. Função deleteCustomer

A função deleteCustomer permite ao administrador excluir um cliente.

O controller procura apenas usuários que possuem o papel user.

Se o cliente existir, ele será excluído usando findOneAndDelete().

41. Funcionamento geral do backend

O frontend React envia requisições HTTP para o backend Node.js e Express.

As rotas do Express direcionam as requisições para os controllers correspondentes.

Os controllers aplicam as regras de negócio, validam os dados e utilizam os modelos Mongoose para se comunicar com o MongoDB.

O MongoDB armazena usuários, produtos, pedidos, pagamentos e configurações da loja.

O Stripe participa do processo de pagamento. O backend cria uma sessão do Stripe e o webhook do Stripe informa posteriormente ao backend quando o pagamento é concluído.

42. Arquitetura geral

O funcionamento geral pode ser resumido da seguinte forma: React representa o frontend, Express e Node.js representam o backend, os controllers contêm a lógica de negócio, os modelos Mongoose definem as estruturas do MongoDB, o MongoDB armazena os dados, o JWT gerencia a autenticação e o Stripe gerencia os pagamentos.

Essa arquitetura permite separar claramente a interface do usuário, a lógica de negócio, o banco de dados, a autenticação e os processos de pagamento.
