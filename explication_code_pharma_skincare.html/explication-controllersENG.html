Explanation of Backend Controllers

This page explains how the different controllers used in the Pharma & Skincare e-commerce application work. Controllers contain the business logic of the backend. They receive requests sent by the frontend, process the data, and return a response to the client.

1. Order Controller - Order Management

The Order Controller manages all operations related to customer orders. It allows the application to create an order, retrieve orders, update their status, and delete an order.

2. createOrder Function

The createOrder function allows a new order to be created. It retrieves the information sent by the frontend from req.body.

The retrieved information includes the ordered products, customer information, payment method, and payment status.

The controller first checks that items is an array and that it contains at least one product. Therefore, an empty order is rejected.

The controller then retrieves the identifier of the logged-in user using req.user.id or req.user._id. This information generally comes from the JWT authentication middleware.

The user's identifier is then validated to ensure that it has a valid MongoDB ObjectId format.

3. Order Product Validation

For each product included in the order, the controller checks that a product identifier exists.

It also checks that the product name is not empty.

The price is converted to a number using Number() and must be greater than or equal to zero.

The quantity is also converted to a number and must be greater than or equal to one.

These validations help prevent incorrect data from being stored in MongoDB.

4. Order Total Calculation

The controller automatically calculates the total amount of the order. For each product, the price is multiplied by the quantity.

All the results are then added together to obtain the total order amount.

The toFixed(2) method keeps two digits after the decimal point.

5. Creating the Order in MongoDB

After all validations have been completed, the controller uses Order.create() to save the order in MongoDB.

The order contains the user, customer information, products, total amount, payment method, payment status, and order status.

The initial order status is set to En attente.

6. Populating the Order

After creation, the controller uses populate() to retrieve the complete information of the user and products.

The user relationship allows the user's information to be retrieved.

The items.product relationship allows the information of the products associated with the order to be retrieved.

7. getAllOrders Function

The getAllOrders function allows the administrator to retrieve all orders stored in MongoDB.

Orders are sorted by creation date in descending order. Therefore, the most recent orders appear first.

User and product information is also retrieved using populate().

This function is mainly used by the administrator dashboard.

8. getUserOrders Function

The getUserOrders function retrieves all orders belonging to a specific user.

The user's identifier is retrieved from req.params.userId.

The controller checks that this identifier exists and corresponds to a valid MongoDB ObjectId.

MongoDB then searches for all orders whose user field corresponds to this identifier.

9. getOrderById Function

The getOrderById function retrieves a specific order using its identifier.

The controller first checks that the provided identifier is valid.

If no order corresponds to this identifier, the server returns a 404 error with the message Commande introuvable.

If the order exists, it is returned with the information of the associated user and products.

10. getMyOrders Function

The getMyOrders function allows the logged-in user to retrieve only their own orders.

The identifier is retrieved from the JWT token using req.user.id or req.user._id.

This function is useful for displaying a "My Orders" page in the customer area.

11. updateOrderStatus Function

The updateOrderStatus function allows the administrator to modify the status of an order.

The allowed statuses are: En attente, En préparation, Expédiée, Livrée, and Annulée.

The controller checks that the new status belongs to this list before updating the order.

The findByIdAndUpdate() method is then used to update the status in MongoDB.

12. updatePaymentStatus Function

The updatePaymentStatus function allows the status of the payment associated with an order to be modified.

The three allowed statuses are: En attente, Payé, and Échec.

This function can be used by the administrator to monitor payment status.

13. deleteOrder Function

The deleteOrder function allows an order to be deleted using its identifier.

The controller first checks that the identifier is valid.

The findByIdAndDelete() method then removes the order from MongoDB.

14. Payment Controller - Payment Management

The Payment Controller is responsible for integrating with Stripe. It allows the application to create a payment session, retrieve payments for the administrator, and process notifications sent by Stripe.

15. createCheckoutSession Function

The createCheckoutSession function allows a Stripe Checkout session to be created for an order.

It retrieves orderId from the request sent by the frontend.

The controller then checks that the user is logged in.

It searches for the order in MongoDB and verifies that the order actually belongs to the logged-in user.

This verification is important to prevent a user from paying for or accessing another user's order.

16. Payment Verification

Before creating a new Stripe session, the controller checks that the order has not already been paid.

It also checks that the order contains products and that its total amount is greater than zero.

17. Creating the Payment

A Payment document is created in MongoDB with the order identifier, user identifier, amount, currency, Stripe as the method, and the status pending.

18. Creating Stripe Products

Each product in the order is transformed into a Stripe line_item.

Stripe receives the product name, its price converted into cents, and its quantity.

The price is multiplied by 100 because Stripe generally uses the smallest unit of the currency.

19. Creating the Stripe Session

The stripe.checkout.sessions.create() method creates the Stripe payment page.

The mode used is payment, which corresponds to a one-time payment.

After payment, Stripe redirects the customer to payment-success. In case of cancellation, the customer is redirected to payment-cancel.

Stripe metadata contains the order identifier and the MongoDB payment identifier. This information is then used to find the corresponding documents when Stripe confirms the payment.

20. getAllPayments Function

The getAllPayments function allows the administrator to retrieve all registered payments.

User and order information is retrieved using populate().

Payments are sorted from the most recent to the oldest.

21. stripeWebhook Function

The Stripe webhook allows Stripe to automatically inform the backend when a payment event occurs.

The controller uses the stripe-signature signature to verify that the notification actually comes from Stripe.

The STRIPE_WEBHOOK_SECRET secret is used to verify this signature.

22. Stripe Payment Confirmation

When the event is checkout.session.completed, it means that the Checkout session has been completed.

The controller then retrieves orderId and paymentId from the Stripe metadata.

The MongoDB payment is then updated with the status paid.

The order is also updated with the payment status Payé.

Its order status automatically becomes En préparation.

23. Product Controller - Product Management

The Product Controller allows the administrator to manage the products available in the store.

24. createProduct Function

The createProduct function allows a new product to be created.

It retrieves the name, price, stock, and category from req.body.

The image is retrieved from req.file when an image is sent with the request.

The product is then saved in MongoDB using Product.create().

25. getProducts Function

The getProducts function retrieves all products stored in MongoDB.

It uses Product.find() and returns the products to the frontend in JSON format.

26. updateProduct Function

The updateProduct function allows an existing product to be modified.

The product is searched using its identifier with Product.findById().

If the product does not exist, the server returns a 404 error.

The fields sent by the frontend are then modified. The controller only modifies the fields present in the request.

If a new image is uploaded, the path of the new image replaces the previous image.

27. Sales Controller - Sales Statistics

The Sales Controller calculates the sales statistics used in the administrator dashboard.

28. getSalesOverview Function

The getSalesOverview function retrieves orders that are not cancelled.

It then calculates the total revenue by adding the amounts of all orders.

It also calculates the total number of orders.

The average order value is calculated by dividing the revenue by the number of orders.

If there are no orders, the average order value is set to zero to avoid division by zero.

29. getSalesByDay Function

The getSalesByDay function uses MongoDB aggregation to calculate sales by day.

Cancelled orders are excluded from the statistics.

MongoDB groups the orders according to their creation date using $dateToString.

For each day, the system calculates the total sales amount and the number of orders.

The results are then sorted by date. These data can be used to create a chart in the administrator dashboard.

30. Settings Controller - Store Settings

The Settings Controller allows the application to retrieve and modify the general store settings.

31. getSettings Function

The getSettings function searches for the settings stored in MongoDB.

If no Settings document exists yet, the controller automatically creates a new document with the default values.

This method therefore ensures that the application always has a configuration available.

32. updateSettings Function

The updateSettings function allows the administrator to modify the store settings.

It can modify the store name, email, phone, address, and currency.

It can also enable or disable orders.

Maintenance mode can be enabled or disabled.

Delivery settings can also be modified, including enabling delivery and changing delivery fees.

Stripe payments can also be enabled or disabled using the stripeEnabled field.

33. Auth Controller - Authentication

The Auth Controller manages registration, login, and customer management.

34. register Function

The register function allows a new user account to be created.

It retrieves the username, email, and password from the request.

It checks that all three required pieces of information are present.

It then checks whether the email already exists in MongoDB. Therefore, two users cannot use the same email address.

35. Password Encryption

Before saving the user, the password is transformed using bcrypt.hash().

The original password is therefore not stored directly in MongoDB.

36. JWT Token Creation

After the account is created, the backend generates a JWT token using jwt.sign().

The token contains the user's identifier, email, and role.

The token is configured to expire after seven days.

The frontend can then store this token and send it in requests that require authentication.

37. login Function

The login function allows an existing user to log in to their account.

It retrieves the email and password sent by the frontend.

The email is cleaned using trim() and converted to lowercase.

The backend then searches for the corresponding user in MongoDB.

The provided password is compared with the hashed password stored in MongoDB using bcrypt.compare().

If the information is correct, a new JWT token is generated and sent to the frontend.

38. getCustomers Function

The getCustomers function allows the administrator to retrieve all users with the user role.

The password field is intentionally excluded from the response using select("-password").

Customers are sorted from the most recent to the oldest.

39. getCustomerById Function

The getCustomerById function allows the administrator to retrieve the information of a specific customer using their identifier.

The password is also excluded from the response.

The controller checks that the user has the user role.

40. deleteCustomer Function

The deleteCustomer function allows the administrator to delete a customer.

The controller only searches for users with the user role.

If the customer exists, they are deleted using findOneAndDelete().

41. General Backend Operation

The React frontend sends HTTP requests to the Node.js and Express backend.

Express routes direct the requests to the corresponding controllers.

Controllers apply business rules, validate the data, and use Mongoose models to communicate with MongoDB.

MongoDB stores users, products, orders, payments, and store settings.

Stripe is involved in the payment process. The backend creates a Stripe session and the Stripe webhook then informs the backend when the payment is completed.

42. Overall Architecture

The overall operation can be summarized as follows: React represents the frontend, Express and Node.js represent the backend, controllers contain the business logic, Mongoose models define the MongoDB structures, MongoDB stores the data, JWT manages authentication, and Stripe manages payments.

This architecture makes it possible to clearly separate the user interface, business logic, database, authentication, and payment processes.
