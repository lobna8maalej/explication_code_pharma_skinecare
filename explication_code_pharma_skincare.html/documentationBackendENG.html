Explanation of MongoDB Models

This page explains the different MongoDB models used in the Pharma & Skincare e-commerce application. The models define the structure of the data stored in MongoDB using Mongoose.

1. MongoDB Connection

The connection file allows the Node.js application to connect to the MongoDB database.

The mongoose.connect() method uses the address mongodb://localhost:27017/ecommerce. This means that MongoDB is running locally on the computer and that the database being used is called ecommerce.

The connectDB function is an asynchronous function. It uses try/catch to detect any possible connection error with MongoDB.

When the connection is successful, the message MongoDB connected is displayed in the console. In case of an error, the message DB connection error is displayed.

2. Order Model - Orders

The Order model represents the orders placed by customers in the Pharma & Skincare store.

User

The user field contains the MongoDB identifier of the customer who placed the order. It uses a reference to the User model.

The field is optional because of required: false. Therefore, an order can potentially be registered without a logged-in user.

Customer Information

The customer block contains the information required for delivery and customer contact.

It contains the customer's first name, last name, email address, phone number, and address.

Ordered Products

The items field is an array containing the products included in the order.

Each item contains the product identifier, its name, price, and ordered quantity.

The product field uses a reference to the Product model. This allows the order to be linked to the corresponding product.

Order Total

The totalAmount field represents the total amount of the order. It is required because of required: true.

Payment

The paymentMethod field indicates the payment method. In your application, the default value is Stripe.

The paymentStatus field indicates the payment status. It can be En attente, Payé, or Échec.

Order Status

The orderStatus field is used to track the progress of the order.

An order can be: En attente, En préparation, Expédiée, Livrée, or Annulée.

Timestamps

The timestamps: true option automatically adds two fields: createdAt and updatedAt. They allow you to know the creation date and the date of the last modification of the order.

3. Payment Model - Payments

The Payment model is used to store information about payments made for orders.

Order

The orderId field contains the identifier of the order associated with the payment. It contains a reference to the Order model.

User

The userId field contains the identifier of the customer who made the payment. It contains a reference to the User model.

Amount

The amount field represents the payment amount. It is required.

Currency

The currency field indicates the currency used for the payment. By default, the currency is USD.

The lowercase: true option automatically converts the value to lowercase. For example, USD becomes usd.

Payment Method

The method field indicates the payment method. In this model, only the stripe method is allowed.

Stripe Information

stripeSessionId contains the Stripe Checkout session ID.

stripePaymentIntentId contains the Stripe PaymentIntent ID when available.

Payment Status

The status field indicates the payment status. It can be pending, paid, failed, or refunded.

This allows the administration to determine whether an order has been paid, whether the payment failed, or whether the amount has been refunded.

4. Product Model - Products

The Product model represents the products sold in the Pharma & Skincare store.

Product Name

The name field contains the product name. It is required, and the trim: true option removes unnecessary spaces at the beginning and end.

Price

The price field contains the product price. It is required.

Stock

The stock field represents the available quantity of the product. Its default value is 0.

The value cannot be negative because of min: 0.

Category

The category field is used to classify products. For example: facial care, hair care, makeup, or sun protection.

Image

The image field contains the URL or path of the product image. If no image is provided, its value is an empty string.

Timestamps

With timestamps: true, MongoDB automatically adds createdAt and updatedAt.

5. Settings Model - Store Settings

The Settings model allows the administrator to save the general settings of the store.

Store Information

The storeName, email, phone, and address fields contain the general information of the store.

Currency

The currency field represents the currency used by the store. By default, it is set to TND.

Orders

The allowOrders field allows the administrator to enable or disable orders. Its default value is true.

Maintenance Mode

The maintenanceMode field allows the administrator to enable or disable the website maintenance mode.

Delivery

The deliveryEnabled field allows the administrator to enable or disable delivery.

The deliveryFee field contains the delivery cost. By default, it is equal to 0.

Stripe

The stripeEnabled field allows the administrator to enable or disable Stripe.

The stripeCurrency field indicates the currency used for Stripe. In your model, it is set to USD by default.

The stripeExchangeRate field represents the conversion rate between TND and the currency used by Stripe.

For example, with a value of 0.32, a conversion can be performed according to the exchange rate configured by the administrator.

6. User Model - Users

The User model is used to manage user accounts in the application.

Email

The email field contains the user's email address. It is required and unique.

The lowercase: true option automatically stores the email address in lowercase.

Username

The username field contains the username. It is required.

Password

The password field contains the user's password. It is required.

In practice, the password should not be stored in plain text. It should be hashed before being stored in MongoDB, for example using bcrypt.

Role

The role field determines the user's permissions.

Two roles are available: user for a customer and admin for an administrator.

By default, a new user has the user role.

Timestamps

The timestamps: true option automatically stores the creation and modification dates of the account.

7. Relationships Between the Models

The different models are connected to each other using MongoDB identifiers of type ObjectId.

A User can place multiple Order orders.

An Order can contain multiple Product products.

An Order can have a Payment payment.

The Settings model contains the general settings of the store, including Stripe settings, delivery, currency, and maintenance mode.

8. Summary of the Functioning

The user creates an account using the User model.

The user views the products stored in Product.

The user adds products to the cart and then confirms the order. The order information is stored in Order.

When the user makes a payment with Stripe, the payment information is stored in Payment.

The administrator can then view orders, payments, products, and modify the store settings using the Settings model.

All of these models therefore make it possible to build the backend of the Pharma & Skincare e-commerce store using Node.js, Express, MongoDB, and Mongoose.
