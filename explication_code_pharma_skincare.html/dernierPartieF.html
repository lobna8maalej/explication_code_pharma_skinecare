Explication du projet PharmaShop

React Router, protection des routes, composants, navigation et administration

1. Présentation générale du code

Le code présenté correspond à la partie frontend du projet PharmaShop. L'application est développée avec React et utilise react-router-dom pour gérer la navigation entre les différentes pages.

Le projet contient deux grandes parties : une partie destinée aux utilisateurs et une partie destinée à l'administrateur.

Les utilisateurs peuvent consulter les produits, ajouter des produits au panier, effectuer une commande et accéder au paiement. L'administrateur possède des pages supplémentaires permettant de gérer les produits, les commandes, les paiements, les clients, les ventes et les paramètres.

2. Le composant AdminRoute

AdminRoute est un composant de protection des routes administrateur. Son objectif est d'empêcher un utilisateur normal d'accéder aux pages réservées à l'administrateur.

Le composant récupère d'abord le token depuis localStorage grâce à localStorage.getItem("token").

Le token permet de savoir si l'utilisateur est connecté. Si aucun token n'existe, l'utilisateur est considéré comme non connecté.

Dans ce cas, Navigate redirige automatiquement l'utilisateur vers /auth, qui correspond à la page de connexion.

Le composant récupère ensuite les informations de l'utilisateur depuis localStorage. Les données sont converties de JSON vers un objet JavaScript avec JSON.parse().

Le programme vérifie ensuite : user.role !== "admin". Si l'utilisateur est connecté mais ne possède pas le rôle admin, il est redirigé vers /products.

Si le token existe et que le rôle de l'utilisateur est admin, le composant retourne children. Cela signifie que la page administrateur peut être affichée.

Important : AdminRoute protège la navigation côté frontend, mais la sécurité réelle doit également être vérifiée côté backend avec le token JWT et le rôle de l'utilisateur.

3. Fonctionnement de Navigate

Navigate est fourni par React Router. Il permet de rediriger automatiquement l'utilisateur vers une autre URL.

Par exemple, <Navigate to="/auth" replace /> redirige vers la page de connexion.

La propriété replace permet de remplacer l'entrée actuelle dans l'historique du navigateur au lieu d'en ajouter une nouvelle.

4. Le composant AdminSidebar

AdminSidebar représente le menu latéral de l'espace administrateur.

Il utilise le composant Link de React Router pour permettre à l'administrateur de naviguer entre les différentes pages sans recharger complètement l'application.

Le premier lien pointe vers /admin. Cette URL correspond au tableau de bord administrateur.

Le deuxième lien pointe vers /admin/products. Il permet d'accéder à la gestion des produits.

Le troisième lien pointe vers /admin/orders. Il permet de consulter et gérer les commandes.

Le lien /products permet à l'administrateur de retourner vers la boutique publique.

5. Style du AdminSidebar

Le style du menu est défini dans l'objet JavaScript styles.

La propriété position: "fixed" permet de maintenir le menu fixé sur le côté gauche de l'écran.

height: "100vh" signifie que la sidebar occupe toute la hauteur de la fenêtre.

display: "flex" et flexDirection: "column" permettent d'organiser les liens verticalement.

La couleur de fond #111 donne au menu un aspect sombre.

6. Le composant Footer

Footer représente le pied de page de l'application. Il contient plusieurs informations importantes concernant la boutique.

La première partie correspond à la présentation de l'entreprise. Elle explique que PharmaShop propose des produits de skincare, de beauté et de pharmacie.

La deuxième partie contient les informations de contact : adresse e-mail, numéro de téléphone et localisation.

La troisième partie présente les services proposés : produits skincare, produits pharmaceutiques, cosmétiques et livraison rapide.

La dernière partie affiche les droits d'auteur : © 2026 Pharma & Skincare Store.

7. Footer.css

Le composant Footer importe le fichier Footer.css. Cela signifie que la présentation graphique du footer peut être séparée de sa logique React.

Cette méthode permet de conserver un code React plus propre et de centraliser les styles du footer dans un fichier CSS dédié.

8. Le composant Loader

Loader est un composant utilisé pour afficher un message pendant le chargement des données.

Il affiche un élément possédant la classe CSS spinner. Cette classe peut être définie dans un fichier CSS pour créer une animation de chargement.

Le texte Loading... informe l'utilisateur que les données sont encore en cours de récupération.

Ce composant est particulièrement utile lors des appels API, par exemple lorsque l'application récupère les produits depuis MongoDB via le backend.

9. Le composant Navbar

Navbar représente la barre de navigation principale de la boutique.

Elle utilise Link pour naviguer vers la page d'accueil et la page des produits.

Le composant utilise également useNavigate() afin de pouvoir rediriger l'utilisateur après une déconnexion.

10. Récupération de l'utilisateur dans Navbar

Le code récupère l'utilisateur avec : JSON.parse(localStorage.getItem("user")).

Si aucun utilisateur n'est enregistré, la variable user est vide. Dans ce cas, le bouton Login est affiché.

Si un utilisateur existe, le bouton Logout est affiché à la place.

11. Fonction logout

La fonction logout() permet de déconnecter l'utilisateur.

Elle supprime le compte enregistré dans localStorage grâce à localStorage.removeItem("user").

Elle supprime également le token JWT avec localStorage.removeItem("token").

Enfin, navigate("/auth") redirige l'utilisateur vers la page de connexion.

12. Le composant PrivateRoute

PrivateRoute protège les pages qui nécessitent une authentification.

Contrairement à AdminRoute, il ne vérifie pas le rôle. Il vérifie uniquement l'existence du token.

Si aucun token n'existe, l'utilisateur est redirigé vers /auth.

Si le token existe, le composant retourne children et autorise l'accès à la page.

Dans ton application, PrivateRoute est utilisé notamment pour protéger le panier et la page Checkout.

13. Différence entre PrivateRoute et AdminRoute

PrivateRoute vérifie simplement si l'utilisateur est connecté.

AdminRoute vérifie deux conditions : l'utilisateur doit être connecté et son rôle doit être admin.

On peut donc résumer ainsi : PrivateRoute = utilisateur connecté. AdminRoute = utilisateur connecté + administrateur.

14. Le composant ProductCard

ProductCard permet d'afficher un produit sous forme de carte dans la page des produits.

Le composant reçoit un produit grâce à la propriété product.

Il affiche notamment l'image, le nom du produit, sa catégorie et son prix.

Le prix est affiché avec la devise DT, ce qui correspond au dinar tunisien.

15. Utilisation du CartContext dans ProductCard

Le composant utilise useContext(CartContext) afin d'accéder à la fonction addToCart.

Cette fonction permet normalement d'ajouter le produit sélectionné au panier global de l'application.

Erreur importante dans le code : le bouton appelle ajouteraupanier(product), mais cette fonction n'est pas définie dans le composant.

Comme la fonction récupérée depuis le contexte s'appelle addToCart, le bouton devrait normalement utiliser addToCart(product).

16. Affichage de l'image du produit

L'image est construite avec : http://localhost:3000/${product.image}.

Cela signifie que les images sont supposées être servies par le backend Node.js fonctionnant sur le port 3000.

Par exemple, si product.image contient uploads/cream.jpg, l'application cherchera l'image à l'adresse correspondante sur le serveur backend.

17. Le fichier App.jsx

App.jsx est le composant principal qui organise les différentes routes de l'application.

Il importe BrowserRouter, Routes, Route et Navigate depuis React Router.

Il importe également toutes les pages utilisateur et administrateur.

18. BrowserRouter

BrowserRouter permet à React Router de gérer les URL de l'application.

Grâce à lui, une URL comme /products peut afficher la page Products sans recharger toute l'application.

19. Routes et Route

Routes contient toutes les routes disponibles dans l'application.

Chaque élément Route associe une URL à un composant.

Par exemple : /products affiche le composant Products.

De la même manière, /checkout affiche la page Checkout.

20. Route Home

La route / correspond à la page d'accueil.

Elle affiche le composant Home.

21. Route Products

La route /products permet d'afficher la liste des produits disponibles dans la boutique.

Cette page est publique puisqu'elle n'est pas entourée par PrivateRoute.

22. Route Cart

La route /cart est protégée par PrivateRoute.

Cela signifie qu'un utilisateur doit être connecté pour accéder au panier.

Si l'utilisateur n'est pas connecté, il sera automatiquement redirigé vers /auth.

23. Route Checkout

La route /checkout est également protégée par PrivateRoute.

Seuls les utilisateurs authentifiés peuvent donc accéder à la page permettant de finaliser une commande.

24. Route Auth

La route /auth affiche le composant Auth.

Cette page permet généralement à l'utilisateur de se connecter ou de créer un compte.

Elle reste accessible même lorsque l'utilisateur n'est pas connecté.

25. Route Admin Dashboard

La route /admin affiche AdminDashboard.

Cette route est protégée par AdminRoute.

Par conséquent, seul un utilisateur ayant le rôle admin peut accéder au tableau de bord.

26. Route Admin Products

La route /admin/products affiche AdminProducts.

Cette page est destinée à la gestion des produits par l'administrateur.

Elle est protégée par AdminRoute.

27. Route Admin Orders

La route /admin/orders affiche AdminOrders.

Elle permet à l'administrateur de consulter et gérer les commandes des clients.

Comme les autres pages administrateur, elle est protégée par AdminRoute.

28. Route Admin Payments

La route /admin/payments affiche AdminPayments.

Cette page est destinée à la consultation ou à la gestion des paiements effectués dans la boutique.

29. Route Admin Customers

La route /admin/customers affiche AdminCustomers.

Cette page permet à l'administrateur de consulter les clients enregistrés dans l'application.

30. Route Admin Sales

La route /admin/sales affiche AdminSales.

Elle peut être utilisée pour afficher les statistiques ou informations concernant les ventes réalisées.

31. Route Admin Settings

La route /admin/settings affiche AdminSettings.

Cette page est destinée à la configuration de l'espace administrateur.

32. Protection des routes administrateur

Toutes les routes commençant par /admin sont placées à l'intérieur de AdminRoute.

Cela crée une couche de protection commune. Si l'utilisateur n'est pas administrateur, il ne peut pas afficher ces pages.

Cette organisation évite de répéter la logique de vérification du rôle dans chaque page administrateur.

33. Route inexistante

La route * correspond à toutes les URL qui ne correspondent à aucune route définie précédemment.

Dans ce cas, Navigate redirige l'utilisateur vers la page d'accueil /.

Cela évite d'afficher une page blanche ou une erreur lorsque l'utilisateur saisit une URL incorrecte.

34. Footer dans App.jsx

Le composant Footer est placé après Routes, mais toujours à l'intérieur de BrowserRouter.

Cela signifie que le footer sera affiché globalement dans l'application, quelle que soit la route actuelle.

Si tu souhaites cacher le Footer sur certaines pages, comme les pages d'administration, il faudra ajouter une logique conditionnelle basée sur l'URL actuelle.

35. Architecture générale de la navigation

L'application fonctionne selon une architecture de navigation organisée autour de React Router.

BrowserRouter → Routes → Route → Page

Pour les pages privées :

Route → PrivateRoute → Vérification du token → Page

Pour les pages administrateur :

Route → AdminRoute → Token + rôle admin → Page

36. Organisation globale du projet

Le projet peut être organisé en plusieurs dossiers.

Le dossier pages contient les pages destinées aux utilisateurs comme Home, Products, Cart, Checkout et Auth.

Le dossier admin contient les pages réservées à l'administrateur.

Le dossier components contient les composants réutilisables comme Navbar, Footer, Loader, PrivateRoute, AdminRoute et ProductCard.

Le dossier context peut contenir le CartContext permettant de partager les informations du panier entre plusieurs composants.

37. Flux d'accès utilisateur

Lorsqu'un utilisateur ouvre l'application, il peut accéder à la page d'accueil et à la liste des produits.

Lorsqu'il souhaite accéder au panier ou au checkout, PrivateRoute vérifie la présence du token.

Si le token est absent, l'utilisateur est envoyé vers la page de connexion.

Après connexion, l'utilisateur peut accéder aux fonctionnalités privées de la boutique.

38. Flux d'accès administrateur

Lorsqu'un utilisateur souhaite accéder à /admin ou à une autre route administrateur, AdminRoute est exécuté.

Le composant vérifie d'abord la présence du token.

Ensuite, il récupère les informations de l'utilisateur depuis localStorage.

Enfin, il vérifie que user.role === "admin".

Si toutes les conditions sont satisfaites, la page administrateur est affichée.

39. Point important à corriger dans ProductCard

Dans ton composant ProductCard, tu récupères : const { addToCart } = useContext(CartContext).

Cependant, le bouton utilise : ajouteraupanier(product).

Cette fonction n'existe pas dans le code présenté. Cela provoquera une erreur JavaScript lorsque l'utilisateur cliquera sur le bouton.

La fonction récupérée depuis le contexte est addToCart. Il faut donc utiliser cette fonction pour ajouter le produit au panier.

40. Conclusion

Ce code met en place une structure complète pour une boutique React avec une séparation claire entre les utilisateurs et les administrateurs.

PrivateRoute protège les fonctionnalités nécessitant une connexion.

AdminRoute protège les fonctionnalités réservées aux administrateurs.

Navbar permet la navigation principale et la déconnexion.

AdminSidebar permet à l'administrateur de naviguer dans son espace de gestion.

ProductCard permet d'afficher les produits et de les ajouter au panier.

Footer affiche les informations générales de la boutique.

Enfin, App.jsx centralise toutes les routes et définit la structure de navigation de l'application PharmaShop.
