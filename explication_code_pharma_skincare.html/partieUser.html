Explication du code React – PharmaShop

Documentation complète du fonctionnement de l'application e-commerce

1. Présentation générale du projet PharmaShop

Le projet PharmaShop est une application e-commerce développée avec React pour le frontend et Node.js, Express et MongoDB pour le backend. L'objectif principal de cette application est de permettre aux utilisateurs de consulter des produits pharmaceutiques et skincare, de rechercher et filtrer les produits, de les ajouter dans un panier, de modifier les quantités, de supprimer des produits, de créer une commande et finalement de réaliser un paiement avec Stripe.

L'application contient également un système d'authentification permettant à un utilisateur de créer un compte ou de se connecter. Selon le rôle de l'utilisateur, notamment administrateur ou utilisateur normal, l'application peut rediriger vers des interfaces différentes.

Le frontend React communique avec le backend grâce à Axios, tandis que le backend communique avec MongoDB afin de récupérer ou enregistrer les données. L'ensemble du projet fonctionne donc selon une architecture composée d'une interface frontend, d'une API backend et d'une base de données.

2. Fonction login()

La fonction login() permet de gérer la connexion d'un utilisateur dans l'application. Elle reçoit deux paramètres importants : user, qui représente les informations de l'utilisateur connecté, et token, qui représente généralement un token JWT permettant d'authentifier l'utilisateur.

La première instruction utilise localStorage.setItem() pour enregistrer les informations de l'utilisateur dans le navigateur. Comme localStorage ne peut pas directement enregistrer un objet JavaScript, JSON.stringify() transforme l'objet utilisateur en texte JSON.

Le token est ensuite sauvegardé sous la clé token. Enfin, setUser(user) met à jour l'état React contenant l'utilisateur actuellement connecté.

3. Gestion globale du panier avec CartContext

CartContext est utilisé pour gérer le panier de manière globale dans l'application React. Sans Context API, il faudrait transmettre les informations du panier entre plusieurs composants avec des props, ce qui rendrait l'application plus difficile à maintenir.

Avec createContext(), un espace partagé est créé pour contenir les informations et les fonctions du panier. Le composant CartProvider contient ensuite cet état global et fournit les données aux composants qui se trouvent à l'intérieur du Provider.

Le panier est initialisé avec useState([]), ce qui signifie qu'au démarrage le tableau cart est vide. Les composants comme Products, Cart et Checkout peuvent ensuite accéder aux mêmes données grâce à useContext().

4. Fonction addToCart()

La fonction addToCart() permet d'ajouter un produit dans le panier. Avant d'ajouter le produit, le code utilise la méthode find() pour rechercher si un produit possédant le même identifiant _id existe déjà.

Si le produit existe déjà, la méthode map() parcourt le panier et crée une nouvelle version du produit avec une quantité augmentée de un. L'opérateur spread permet de conserver les autres propriétés du produit.

Si le produit n'existe pas encore, il est ajouté au tableau avec une propriété quantity: 1. Cette logique permet donc de gérer automatiquement les quantités des produits dans le panier.

5. Suppression et modification des produits du panier

La fonction removeFromCart() permet de supprimer un produit du panier. Elle utilise la méthode filter() afin de créer un nouveau tableau contenant uniquement les produits dont l'identifiant est différent de celui du produit à supprimer.

La fonction updateQuantity() permet de modifier la quantité d'un produit. Si la nouvelle quantité est inférieure ou égale à zéro, la fonction appelle automatiquement removeFromCart().

La fonction clearCart() permet de vider complètement le panier en utilisant setCart([]).

6. Calcul du nombre de produits et du montant total

Le code utilise la méthode reduce() pour effectuer les calculs concernant le panier. La variable cartCount représente le nombre total d'articles présents dans le panier.

La variable cartTotal représente le montant total de la commande. Pour chaque produit, le prix est multiplié par la quantité, puis le résultat est ajouté au total général.

7. Fonction useCart()

useCart() est un hook personnalisé créé pour simplifier l'utilisation du CartContext. Au lieu d'écrire directement useContext(CartContext) dans chaque composant, le développeur peut simplement appeler useCart().

Ce hook permet de récupérer facilement le panier, les fonctions d'ajout et de suppression, la modification des quantités, le nombre d'articles et le montant total.

8. Composant Auth

Le composant Auth permet de gérer deux opérations : la connexion et l'inscription. La variable isLogin permet de déterminer le mode actuel du formulaire.

Lorsque isLogin vaut true, le formulaire affiche la connexion. Lorsqu'il vaut false, le formulaire affiche l'inscription. Les variables username, email et password sont des états React utilisés pour contrôler les champs du formulaire.

Le composant utilise également useNavigate() afin de rediriger l'utilisateur vers une autre page après une opération réussie.

9. Connexion de l'utilisateur

Lors d'une connexion, la fonction handleAuth() vérifie d'abord que l'adresse email et le mot de passe sont renseignés. L'utilisation de trim() permet de supprimer les espaces inutiles autour de l'adresse email.

L'email est également converti en minuscules avec toLowerCase(). Ensuite, Axios envoie une requête POST vers /api/users/login.

Si la réponse contient un token et un utilisateur, ces informations sont enregistrées dans localStorage. Le rôle de l'utilisateur est ensuite vérifié. Si le rôle est admin, l'utilisateur est redirigé vers /admin. Sinon, il est redirigé vers /products.

10. Inscription de l'utilisateur

Lorsque le formulaire est en mode inscription, le username devient obligatoire en plus de l'email et du mot de passe.

Les informations sont regroupées dans un objet registerData puis envoyées avec Axios vers /api/users/register.

Le backend crée le nouvel utilisateur et peut retourner un token ainsi que les informations du compte. Le frontend sauvegarde ces informations dans localStorage lorsqu'elles sont disponibles.

11. Gestion des erreurs dans Auth

Les requêtes de connexion et d'inscription sont placées dans un bloc try/catch. Si le serveur retourne une erreur, le programme entre dans catch.

Le code utilise err.response?.data?.message afin d'essayer de récupérer le message envoyé par le backend. Le symbole ?. correspond à l'optional chaining et permet d'éviter une erreur si certaines propriétés n'existent pas.

12. Composant Cart

Le composant Cart représente la page du panier. Il récupère les informations nécessaires grâce à CartContext. Lorsque cart.length est égal à zéro, l'application affiche un message indiquant que le panier est vide.

Lorsque le panier contient des produits, cart.map() est utilisé pour afficher chaque article. Pour chaque produit, l'application affiche son nom, son prix, sa quantité et son sous-total.

Le bouton moins diminue la quantité avec updateQuantity(), tandis que le bouton plus utilise addToCart(). Le bouton supprimer appelle removeFromCart().

13. Composant Checkout

Checkout représente l'étape de finalisation de la commande. Ce composant récupère les informations provenant soit du panier, soit d'un achat direct.

useLocation() permet de récupérer les informations transmises lors de la navigation. Si un produit est envoyé directement, il est ajouté à checkoutItems avec une quantité de un.

Dans le cas contraire, les produits du panier sont utilisés. Le composant contient également un état customer regroupant le prénom, le nom, le téléphone et l'adresse du client.

14. Gestion du formulaire client

La fonction handleChange() permet de mettre à jour dynamiquement les informations du client. Elle utilise le nom du champ HTML comme clé de l'objet customer.

Cette technique évite de créer une fonction différente pour chaque champ du formulaire. Le formulaire reste ainsi contrôlé par React et les valeurs saisies sont toujours disponibles dans l'état customer.

15. Récupération de l'identifiant utilisateur

La fonction getUserIdFromToken() récupère le token JWT enregistré dans localStorage. Un token JWT possède généralement trois parties séparées par des points.

Le code récupère la partie centrale, la décode avec atob() puis transforme le résultat JSON en objet JavaScript avec JSON.parse().

L'application recherche ensuite une propriété id, _id ou userId. Cela permet de retrouver l'identifiant de l'utilisateur connecté afin de l'associer à la commande.

16. Préparation des produits pour la commande

Avant de créer une commande, le code normalise les informations des produits. La fonction getProductPrice() recherche le prix dans plusieurs propriétés possibles.

La fonction getProductName() recherche le nom du produit dans plusieurs propriétés possibles comme name, productName ou title.

La fonction getProductQuantity() recherche la quantité dans qty ou quantity et utilise une quantité minimale de un.

17. Création de la commande

Lorsque l'utilisateur valide le formulaire Checkout, handleSubmit() commence par empêcher le comportement classique du formulaire avec preventDefault().

Le code vérifie ensuite les informations du client, les produits, le token et l'identifiant de l'utilisateur.

Les produits sont transformés en orderItems contenant le produit, son nom, son prix et sa quantité. Le montant total est calculé avec reduce.

L'objet orderData contient les produits, les informations du client, le moyen de paiement Stripe et le statut initial du paiement. Cet objet est envoyé au backend avec une requête POST vers /api/orders.

18. Paiement Stripe

Après la création de la commande, Checkout récupère l'identifiant de la commande créée par le backend.

Une deuxième requête est ensuite envoyée vers /api/payments/create-checkout-session afin de demander au backend de créer une session de paiement Stripe.

Si le backend retourne une URL Stripe valide, le frontend redirige l'utilisateur vers cette URL avec window.location.href. L'utilisateur peut alors effectuer son paiement sur Stripe.

19. Composant Home

Le composant Home représente la page d'accueil de PharmaShop. Il affiche un titre présentant la boutique, un sous-titre expliquant son activité et un bouton permettant d'accéder aux produits.

Le composant Link de React Router est utilisé pour naviguer vers /products sans recharger complètement l'application.

20. Composant Orders

Le composant Orders sert à afficher l'historique des commandes. Dans le code fourni, les commandes sont récupérées depuis localStorage avec la clé « orders ».

Si aucune commande n'est disponible, un message indique qu'il n'y a pas encore de commande. Sinon, map est utilisé pour afficher chaque commande avec le client, le téléphone, l'adresse, les produits, le montant total et la date.

Un point important est que Checkout crée réellement les commandes dans le backend. Si MongoDB est la source officielle des commandes, il serait préférable que Orders récupère les commandes depuis une route API protégée.

21. Composant Product

Le composant Product affiche le détail d'un produit. useParams() récupère l'identifiant du produit depuis l'URL.

Axios effectue ensuite une requête GET vers /api/products/:id. Le composant possède des états loading et error afin d'afficher correctement les différentes situations pendant la récupération des données.

Une fois le produit récupéré, l'application peut afficher son nom, son image, son prix, sa catégorie et sa description.

22. Gestion des images des produits

La fonction getImageUrl() permet de construire correctement l'adresse d'une image. Si l'image commence déjà par http, elle est considérée comme une URL complète.

Si l'image correspond à un chemin relatif, l'adresse du serveur backend est ajoutée devant le chemin. Cette logique est utile lorsque MongoDB conserve seulement le chemin de l'image alors que les fichiers sont servis par le serveur Node.js.

23. Composant Products

Products est la page qui affiche la liste des produits disponibles. Au démarrage, products est initialisé avec un tableau vide.

useEffect est utilisé pour récupérer les produits depuis l'API. Axios envoie une requête GET vers /api/products.

Les données reçues sont ensuite enregistrées dans l'état avec setProducts(). React met automatiquement à jour l'affichage lorsque cet état est modifié.

24. Recherche et filtrage des produits

La variable search permet de rechercher un produit par son nom. La méthode filter() est utilisée pour sélectionner les produits correspondant aux critères.

Le nom est converti en minuscules avec toLowerCase(), puis includes() vérifie si le texte recherché existe dans le nom du produit.

Le filtre de catégorie compare la catégorie du produit avec la catégorie sélectionnée. Le filtre de prix vérifie que le prix du produit est inférieur ou égal au prix maximum.

25. Ajout au panier depuis Products

La fonction handleAddToCart() permet d'ajouter un produit au panier directement depuis la liste des produits.

Avant l'ajout, some() vérifie si le produit existe déjà dans le panier en comparant les identifiants _id.

Cette vérification permet d'éviter les doublons et de laisser CartContext gérer correctement l'augmentation de la quantité.

26. Fonction Buy Now

handleBuyNow() permet de réaliser un achat direct d'un produit. La première étape consiste à vérifier si l'utilisateur est connecté grâce à la présence du token dans localStorage.

Si aucun token n'existe, le produit sélectionné peut être enregistré temporairement dans localStorage sous la clé pendingProduct, puis l'utilisateur est redirigé vers la page Auth.

Si l'utilisateur est déjà connecté, il est directement redirigé vers Checkout avec le produit transmis dans l'état de navigation.

27. Déconnexion

handleLogout() permet de déconnecter l'utilisateur. Le token, les informations utilisateur et le produit temporaire pendingProduct sont supprimés de localStorage.

Après cette opération, l'application redirige l'utilisateur vers la page Auth. La suppression du token empêche les prochaines requêtes protégées d'utiliser l'ancienne session.

28. Axios et communication avec le backend

Axios est utilisé dans plusieurs composants pour communiquer avec l'API backend. Les requêtes GET servent principalement à récupérer les produits ou d'autres informations.

Les requêtes POST servent à envoyer des données, par exemple lors de la connexion, de l'inscription, de la création d'une commande ou de la création d'une session Stripe.

Le frontend utilise l'adresse http://localhost:3000/api comme base de l'API dans le code fourni.

29. Architecture complète de l'application

Le fonctionnement global peut être résumé par une chaîne de communication. L'utilisateur interagit d'abord avec l'interface React. React utilise ensuite Axios pour envoyer une requête HTTP vers l'API Express.

Express reçoit la requête et la transmet au contrôleur approprié. Le contrôleur peut consulter ou modifier les données dans MongoDB à travers les modèles Mongoose.

Le backend retourne ensuite une réponse JSON. React récupère cette réponse et met à jour ses états avec useState, ce qui provoque une nouvelle mise à jour de l'interface.

React → Axios → Express → Controller → MongoDB → JSON → React

30. Utilisation de useState

useState est l'un des hooks principaux de React. Il permet de conserver une donnée dans un composant et de la modifier.

Dans PharmaShop, useState est utilisé pour gérer les produits, le panier, les champs des formulaires, les messages d'erreur, les états de chargement et les informations de l'utilisateur.

31. Utilisation de useEffect

useEffect permet d'exécuter une action après le rendu d'un composant. Il est particulièrement important dans PharmaShop pour effectuer les appels API au chargement d'une page.

Par exemple, Products utilise useEffect pour récupérer les produits, Product l'utilise pour récupérer un produit précis et Checkout l'utilise pour préparer les produits à commander.

32. Utilisation de React Router

React Router permet de gérer les différentes pages de l'application sans recharger complètement le navigateur.

Link est utilisé pour créer des liens, tandis que useNavigate() permet de réaliser des redirections depuis une fonction JavaScript.

useParams() permet de récupérer les paramètres présents dans l'URL et useLocation() permet de récupérer les informations liées à la navigation.

33. Gestion des erreurs et des chargements

Les appels vers le backend peuvent échouer pour différentes raisons : serveur arrêté, mauvaise URL, erreur réseau, problème d'authentification ou erreur côté serveur.

C'est pourquoi le code utilise try, catch et parfois finally. try contient l'opération principale, catch récupère l'erreur et finally permet de réaliser une action qui doit avoir lieu dans tous les cas.

34. Points importants à vérifier dans le projet

Un premier point concerne le composant Orders. Dans le code fourni, Orders utilise localStorage alors que Checkout envoie les commandes au backend. Il existe donc un risque que les commandes créées dans MongoDB ne soient pas visibles dans Orders.

Pour une application réelle, il est recommandé d'utiliser MongoDB comme source principale des commandes et de créer une route backend permettant à l'utilisateur connecté de récupérer ses commandes.

Un deuxième point concerne le filtre par catégorie dans Products. Le code contient un état category et une condition de filtrage, mais le JSX fourni ne montre pas nécessairement un élément permettant à l'utilisateur de sélectionner une catégorie.

Un troisième point concerne handleBuyNow. La fonction est prévue pour effectuer un achat direct, mais il faut vérifier que le bouton « Acheter maintenant » est réellement présent dans l'interface Products.

35. Conclusion générale

Le code PharmaShop met en place une application e-commerce complète basée sur React. React est responsable de l'interface utilisateur et de la gestion des états, Context API permet de partager le panier entre les composants, React Router permet de gérer la navigation, Axios assure la communication avec l'API et localStorage conserve certaines informations de session.

Le backend Node.js et Express traite les requêtes, vérifie les utilisateurs, crée les commandes et prépare les paiements Stripe. MongoDB constitue la base de données permettant de conserver les utilisateurs, produits et commandes.

Le fonctionnement général est donc le suivant : l'utilisateur consulte les produits, recherche ou filtre un produit, ajoute ses produits au panier, se connecte si nécessaire, remplit les informations de livraison, crée une commande, puis est redirigé vers Stripe pour effectuer le paiement.

Cette organisation constitue une bonne base pour une application e-commerce moderne, à condition de maintenir une séparation claire entre les données temporaires du navigateur et les données officielles stockées dans le backend et MongoDB.
