Explicação do projeto PharmaShop

React Router, proteção de rotas, componentes, navegação e administração

1. Visão geral do código

O código apresentado corresponde à parte frontend do projeto PharmaShop. A aplicação é desenvolvida com React e utiliza react-router-dom para gerenciar a navegação entre as diferentes páginas.

O projeto contém duas partes principais: uma parte destinada aos usuários e outra destinada ao administrador.

Os usuários podem consultar os produtos, adicionar produtos ao carrinho, fazer um pedido e acessar o processo de pagamento. O administrador possui páginas adicionais para gerenciar produtos, pedidos, pagamentos, clientes, vendas e configurações.

2. O componente AdminRoute

AdminRoute é um componente utilizado para proteger as rotas de administração. Seu objetivo é impedir que usuários comuns acessem páginas reservadas aos administradores.

O componente primeiro obtém o token do localStorage utilizando localStorage.getItem("token").

O token é utilizado para determinar se o usuário está conectado. Se não existir nenhum token, o usuário será considerado não autenticado.

Nesse caso, Navigate redireciona automaticamente o usuário para /auth, que corresponde à página de login.

Em seguida, o componente obtém as informações do usuário do localStorage. Os dados são convertidos de JSON para um objeto JavaScript usando JSON.parse().

O programa então verifica: user.role !== "admin". Se o usuário estiver conectado, mas não possuir a função admin, ele será redirecionado para /products.

Se o token existir e a função do usuário for admin, o componente retorna children. Isso significa que a página de administração poderá ser exibida.

Importante: AdminRoute protege a navegação no frontend, mas a segurança real também deve ser verificada no backend usando o token JWT e a função do usuário.

3. Como o Navigate funciona

Navigate é fornecido pelo React Router. Ele permite que a aplicação redirecione automaticamente o usuário para outra URL.

Por exemplo, <Navigate to="/auth" replace /> redireciona o usuário para a página de login.

A propriedade replace substitui a entrada atual no histórico do navegador em vez de adicionar uma nova.

4. O componente AdminSidebar

AdminSidebar representa o menu lateral da área de administração.

Ele utiliza o componente Link do React Router para permitir que o administrador navegue entre as diferentes páginas sem recarregar completamente a aplicação.

O primeiro link aponta para /admin. Essa URL corresponde ao painel de administração.

O segundo link aponta para /admin/products. Ele fornece acesso ao gerenciamento de produtos.

O terceiro link aponta para /admin/orders. Ele permite que o administrador visualize e gerencie os pedidos.

O link /products permite que o administrador volte para a loja pública.

5. Estilos do AdminSidebar

Os estilos do menu são definidos no objeto JavaScript styles.

A propriedade position: "fixed" mantém o menu fixo no lado esquerdo da tela.

height: "100vh" significa que a barra lateral ocupa toda a altura da janela.

display: "flex" e flexDirection: "column" organizam os links verticalmente.

A cor de fundo #111 proporciona ao menu uma aparência escura.

6. O componente Footer

Footer representa o rodapé da aplicação. Ele contém várias informações importantes sobre a loja.

A primeira parte corresponde à apresentação da empresa. Ela explica que a PharmaShop oferece produtos para cuidados com a pele, beleza e farmácia.

A segunda parte contém as informações de contato: endereço de e-mail, número de telefone e localização.

A terceira parte apresenta os serviços disponíveis: produtos para cuidados com a pele, produtos farmacêuticos, cosméticos e entrega rápida.

A última parte exibe o aviso de copyright: © 2026 Pharma & Skincare Store.

7. Footer.css

O componente Footer importa o arquivo Footer.css. Isso significa que a apresentação gráfica do footer pode ser separada da sua lógica React.

Essa abordagem mantém o código React mais limpo e centraliza os estilos do footer em um arquivo CSS específico.

8. O componente Loader

Loader é um componente utilizado para exibir uma mensagem enquanto os dados estão sendo carregados.

Ele exibe um elemento que contém a classe CSS spinner. Essa classe pode ser definida em um arquivo CSS para criar uma animação de carregamento.

O texto Loading... informa ao usuário que os dados ainda estão sendo recuperados.

Esse componente é especialmente útil durante chamadas à API, por exemplo, quando a aplicação recupera produtos do MongoDB por meio do backend.

9. O componente Navbar

Navbar representa a barra de navegação principal da loja.

Ele utiliza Link para navegar até a página inicial e a página de produtos.

O componente também utiliza useNavigate() para redirecionar o usuário após fazer logout.

10. Recuperação do usuário no Navbar

O código obtém o usuário usando: JSON.parse(localStorage.getItem("user")).

Se nenhum usuário estiver armazenado, a variável user estará vazia. Nesse caso, o botão Login será exibido.

Se existir um usuário, o botão Logout será exibido.

11. A função logout

A função logout() permite que o usuário faça logout.

Ela remove a conta armazenada no localStorage usando localStorage.removeItem("user").

Ela também remove o token JWT usando localStorage.removeItem("token").

Finalmente, navigate("/auth") redireciona o usuário para a página de login.

12. O componente PrivateRoute

PrivateRoute protege páginas que exigem autenticação.

Diferentemente do AdminRoute, ele não verifica a função do usuário. Ele apenas verifica se o token existe.

Se nenhum token existir, o usuário será redirecionado para /auth.

Se o token existir, o componente retorna children e permite o acesso à página.

Na sua aplicação, PrivateRoute é utilizado principalmente para proteger o carrinho e a página Checkout.

13. Diferença entre PrivateRoute e AdminRoute

PrivateRoute simplesmente verifica se o usuário está conectado.

AdminRoute verifica duas condições: o usuário deve estar conectado e sua função deve ser admin.

Portanto, pode ser resumido da seguinte maneira: PrivateRoute = usuário conectado. AdminRoute = usuário conectado + administrador.

14. O componente ProductCard

ProductCard exibe um produto como um cartão na página de produtos.

O componente recebe um produto por meio da propriedade product.

Ele exibe a imagem, o nome, a categoria e o preço do produto.

O preço é exibido utilizando a moeda DT, que corresponde ao dinar tunisiano.

15. Uso do CartContext no ProductCard

O componente utiliza useContext(CartContext) para acessar a função addToCart.

Essa função normalmente permite adicionar o produto selecionado ao carrinho global da aplicação.

Erro importante no código: o botão chama ajouteraupanier(product), mas essa função não está definida no componente.

Como a função obtida do contexto se chama addToCart, o botão normalmente deveria utilizar addToCart(product).

16. Exibição da imagem do produto

A imagem é construída usando: http://localhost:3000/${product.image}.

Isso significa que as imagens devem ser fornecidas pelo backend Node.js que está sendo executado na porta 3000.

Por exemplo, se product.image contiver uploads/cream.jpg, a aplicação procurará a imagem no endereço correspondente do servidor backend.

17. O arquivo App.jsx

App.jsx é o componente principal que organiza as diferentes rotas da aplicação.

Ele importa BrowserRouter, Routes, Route e Navigate do React Router.

Ele também importa todas as páginas destinadas aos usuários e aos administradores.

18. BrowserRouter

BrowserRouter permite que o React Router gerencie as URLs da aplicação.

Graças a ele, uma URL como /products pode exibir a página Products sem recarregar toda a aplicação.

19. Routes e Route

Routes contém todas as rotas disponíveis na aplicação.

Cada elemento Route associa uma URL a um componente.

Por exemplo: /products exibe o componente Products.

Da mesma forma, /checkout exibe a página Checkout.

20. Rota Home

A rota / corresponde à página inicial.

Ela exibe o componente Home.

21. Rota Products

A rota /products exibe a lista de produtos disponíveis na loja.

Essa página é pública porque não está envolvida pelo PrivateRoute.

22. Rota Cart

A rota /cart é protegida pelo PrivateRoute.

Isso significa que o usuário precisa estar conectado para acessar o carrinho.

Se o usuário não estiver conectado, ele será automaticamente redirecionado para /auth.

23. Rota Checkout

A rota /checkout também é protegida pelo PrivateRoute.

Portanto, apenas usuários autenticados podem acessar a página utilizada para concluir um pedido.

24. Rota Auth

A rota /auth exibe o componente Auth.

Essa página geralmente permite que o usuário faça login ou crie uma conta.

Ela continua acessível mesmo quando o usuário não está conectado.

25. Rota do painel de administração

A rota /admin exibe AdminDashboard.

Essa rota é protegida pelo AdminRoute.

Portanto, somente um usuário com a função admin pode acessar o painel.

26. Rota Admin Products

A rota /admin/products exibe AdminProducts.

Essa página é destinada ao gerenciamento de produtos pelo administrador.

Ela é protegida pelo AdminRoute.

27. Rota Admin Orders

A rota /admin/orders exibe AdminOrders.

Ela permite que o administrador visualize e gerencie os pedidos dos clientes.

Assim como as outras páginas administrativas, ela é protegida pelo AdminRoute.

28. Rota Admin Payments

A rota /admin/payments exibe AdminPayments.

Essa página é destinada à visualização ou gerenciamento dos pagamentos realizados na loja.

29. Rota Admin Customers

A rota /admin/customers exibe AdminCustomers.

Essa página permite que o administrador visualize os clientes cadastrados na aplicação.

30. Rota Admin Sales

A rota /admin/sales exibe AdminSales.

Ela pode ser utilizada para exibir estatísticas ou informações sobre as vendas realizadas.

31. Rota Admin Settings

A rota /admin/settings exibe AdminSettings.

Essa página é destinada à configuração da área de administração.

32. Proteção das rotas administrativas

Todas as rotas que começam com /admin são colocadas dentro do AdminRoute.

Isso cria uma camada de proteção comum. Se o usuário não for administrador, ele não poderá visualizar essas páginas.

Essa organização evita repetir a lógica de verificação da função em cada página administrativa.

33. Rota inexistente

A rota * corresponde a todas as URLs que não correspondem a nenhuma das rotas definidas anteriormente.

Nesse caso, Navigate redireciona o usuário para a página inicial /.

Isso evita uma página em branco ou um erro quando o usuário digita uma URL incorreta.

34. Footer no App.jsx

O componente Footer é colocado depois de Routes, mas continua dentro do BrowserRouter.

Isso significa que o footer será exibido globalmente em toda a aplicação, independentemente da rota atual.

Se você quiser ocultar o Footer em determinadas páginas, como as páginas de administração, será necessário adicionar uma lógica condicional baseada na URL atual.

35. Arquitetura geral de navegação

A aplicação segue uma arquitetura de navegação organizada em torno do React Router.

BrowserRouter → Routes → Route → Page

Para páginas privadas:

Route → PrivateRoute → Verificação do token → Page

Para páginas administrativas:

Route → AdminRoute → Token + função admin → Page

36. Organização geral do projeto

O projeto pode ser organizado em várias pastas.

A pasta pages contém páginas destinadas aos usuários, como Home, Products, Cart, Checkout e Auth.

A pasta admin contém páginas reservadas ao administrador.

A pasta components contém componentes reutilizáveis como Navbar, Footer, Loader, PrivateRoute, AdminRoute e ProductCard.

A pasta context pode conter o CartContext, que permite compartilhar as informações do carrinho entre vários componentes.

37. Fluxo de acesso do usuário

Quando um usuário abre a aplicação, ele pode acessar a página inicial e a lista de produtos.

Quando deseja acessar o carrinho ou o checkout, o PrivateRoute verifica se o token existe.

Se o token estiver ausente, o usuário será enviado para a página de login.

Depois de fazer login, o usuário poderá acessar os recursos privados da loja.

38. Fluxo de acesso do administrador

Quando um usuário deseja acessar /admin ou outra rota administrativa, o AdminRoute é executado.

O componente primeiro verifica se o token existe.

Em seguida, ele obtém as informações do usuário do localStorage.

Finalmente, verifica se user.role === "admin".

Se todas as condições forem satisfeitas, a página de administração será exibida.

39. Ponto importante a corrigir no ProductCard

No seu componente ProductCard, você obtém: const { addToCart } = useContext(CartContext).

No entanto, o botão utiliza: ajouteraupanier(product).

Essa função não existe no código apresentado. Isso causará um erro de JavaScript quando o usuário clicar no botão.

A função obtida do contexto é addToCart. Portanto, essa função deve ser utilizada para adicionar o produto ao carrinho.

40. Conclusão

Este código fornece uma estrutura completa para uma loja React com uma separação clara entre usuários e administradores.

PrivateRoute protege as funcionalidades que exigem autenticação.

AdminRoute protege as funcionalidades reservadas aos administradores.

Navbar fornece a navegação principal e a funcionalidade de logout.

AdminSidebar permite que o administrador navegue pela área de gerenciamento.

ProductCard exibe os produtos e permite adicioná-los ao carrinho.

Footer exibe as informações gerais da loja.

Finalmente, App.jsx centraliza todas as rotas e define a estrutura de navegação da aplicação PharmaShop.
