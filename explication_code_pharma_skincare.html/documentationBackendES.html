Explicación de los modelos MongoDB

Esta página explica los diferentes modelos MongoDB utilizados en la aplicación de comercio electrónico Pharma & Skincare. Los modelos definen la estructura de los datos almacenados en MongoDB mediante Mongoose.

1. Conexión a MongoDB

El archivo de conexión permite que la aplicación Node.js se conecte a la base de datos MongoDB.

El método mongoose.connect() utiliza la dirección mongodb://localhost:27017/ecommerce. Esto significa que MongoDB se ejecuta localmente en el ordenador y que la base de datos utilizada se llama ecommerce.

La función connectDB es una función asíncrona. Utiliza try/catch para detectar cualquier posible error de conexión con MongoDB.

Cuando la conexión se realiza correctamente, el mensaje MongoDB connected aparece en la consola. En caso de error, se muestra el mensaje DB connection error.

2. Modelo Order - Pedidos

El modelo Order representa los pedidos realizados por los clientes en la tienda Pharma & Skincare.

Usuario

El campo user contiene el identificador MongoDB del cliente que realizó el pedido. Utiliza una referencia al modelo User.

El campo es opcional debido a required: false. Por lo tanto, un pedido puede registrarse eventualmente sin un usuario conectado.

Información del cliente

El bloque customer contiene la información necesaria para la entrega y el contacto con el cliente.

Contiene el nombre, apellido, dirección de correo electrónico, número de teléfono y dirección del cliente.

Productos pedidos

El campo items es un array que contiene los productos incluidos en el pedido.

Cada elemento contiene el identificador del producto, su nombre, precio y cantidad solicitada.

El campo product utiliza una referencia al modelo Product. Esto permite relacionar el pedido con el producto correspondiente.

Total del pedido

El campo totalAmount representa el importe total del pedido. Es obligatorio gracias a required: true.

Pago

El campo paymentMethod indica el método de pago. En tu aplicación, el valor predeterminado es Stripe.

El campo paymentStatus indica el estado del pago. Puede ser En attente, Payé o Échec.

Estado del pedido

El campo orderStatus se utiliza para seguir la evolución del pedido.

Un pedido puede estar: En attente, En préparation, Expédiée, Livrée o Annulée.

Marcas de tiempo

La opción timestamps: true añade automáticamente dos campos: createdAt y updatedAt. Permiten conocer la fecha de creación y la fecha de la última modificación del pedido.

3. Modelo Payment - Pagos

El modelo Payment permite almacenar información sobre los pagos realizados para los pedidos.

Pedido

El campo orderId contiene el identificador del pedido asociado al pago. Contiene una referencia al modelo Order.

Usuario

El campo userId contiene el identificador del cliente que realizó el pago. Contiene una referencia al modelo User.

Importe

El campo amount representa el importe del pago. Es obligatorio.

Moneda

El campo currency indica la moneda utilizada para el pago. Por defecto, la moneda es USD.

La opción lowercase: true convierte automáticamente el valor a minúsculas. Por ejemplo, USD se convierte en usd.

Método de pago

El campo method indica el método de pago. En este modelo, solo se permite el método stripe.

Información de Stripe

stripeSessionId contiene el ID de la sesión de Stripe Checkout.

stripePaymentIntentId contiene el ID de PaymentIntent de Stripe cuando está disponible.

Estado del pago

El campo status indica el estado del pago. Puede ser pending, paid, failed o refunded.

Esto permite a la administración determinar si un pedido ha sido pagado, si el pago ha fallado o si el importe ha sido reembolsado.

4. Modelo Product - Productos

El modelo Product representa los productos vendidos en la tienda Pharma & Skincare.

Nombre del producto

El campo name contiene el nombre del producto. Es obligatorio y la opción trim: true elimina los espacios innecesarios al principio y al final.

Precio

El campo price contiene el precio del producto. Es obligatorio.

Stock

El campo stock representa la cantidad disponible del producto. Su valor predeterminado es 0.

El valor no puede ser negativo gracias a min: 0.

Categoría

El campo category se utiliza para clasificar los productos. Por ejemplo: cuidado facial, cuidado capilar, maquillaje o protección solar.

Imagen

El campo image contiene la URL o la ruta de la imagen del producto. Si no se proporciona ninguna imagen, su valor es una cadena vacía.

Marcas de tiempo

Con timestamps: true, MongoDB añade automáticamente createdAt y updatedAt.

5. Modelo Settings - Configuración de la tienda

El modelo Settings permite al administrador guardar la configuración general de la tienda.

Información de la tienda

Los campos storeName, email, phone y address contienen la información general de la tienda.

Moneda

El campo currency representa la moneda utilizada por la tienda. Por defecto, está configurada como TND.

Pedidos

El campo allowOrders permite al administrador activar o desactivar los pedidos. Su valor predeterminado es true.

Modo mantenimiento

El campo maintenanceMode permite al administrador activar o desactivar el modo de mantenimiento del sitio web.

Entrega

El campo deliveryEnabled permite al administrador activar o desactivar la entrega.

El campo deliveryFee contiene el coste de entrega. Por defecto, es igual a 0.

Stripe

El campo stripeEnabled permite al administrador activar o desactivar Stripe.

El campo stripeCurrency indica la moneda utilizada para Stripe. En tu modelo, está configurada como USD por defecto.

El campo stripeExchangeRate representa el tipo de cambio entre TND y la moneda utilizada por Stripe.

Por ejemplo, con un valor de 0.32, se puede realizar una conversión según el tipo de cambio configurado por el administrador.

6. Modelo User - Usuarios

El modelo User se utiliza para gestionar las cuentas de usuario de la aplicación.

Email

El campo email contiene la dirección de correo electrónico del usuario. Es obligatorio y único.

La opción lowercase: true almacena automáticamente la dirección de correo electrónico en minúsculas.

Username

El campo username contiene el nombre de usuario. Es obligatorio.

Password

El campo password contiene la contraseña del usuario. Es obligatorio.

En la práctica, la contraseña no debe almacenarse en texto plano. Debe utilizarse un hash antes de almacenarla en MongoDB, por ejemplo mediante bcrypt.

Rol

El campo role determina los permisos del usuario.

Hay dos roles disponibles: user para un cliente y admin para un administrador.

Por defecto, un nuevo usuario tiene el rol user.

Marcas de tiempo

La opción timestamps: true almacena automáticamente las fechas de creación y modificación de la cuenta.

7. Relaciones entre los modelos

Los diferentes modelos están conectados entre sí mediante identificadores MongoDB de tipo ObjectId.

Un User puede realizar varios pedidos Order.

Un Order puede contener varios productos Product.

Un Order puede tener un pago Payment.

El modelo Settings contiene la configuración general de la tienda, incluyendo la configuración de Stripe, la entrega, la moneda y el modo de mantenimiento.

8. Resumen del funcionamiento

El usuario crea una cuenta utilizando el modelo User.

El usuario consulta los productos almacenados en Product.

El usuario añade productos al carrito y después confirma el pedido. La información del pedido se almacena en Order.

Cuando el usuario realiza un pago con Stripe, la información del pago se almacena en Payment.

El administrador puede posteriormente consultar los pedidos, los pagos y los productos, y modificar la configuración de la tienda utilizando el modelo Settings.

Todos estos modelos permiten construir el backend de la tienda de comercio electrónico Pharma & Skincare utilizando Node.js, Express, MongoDB y Mongoose.
