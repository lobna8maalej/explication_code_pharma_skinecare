Explicación del proyecto PharmaShop

React Router, protección de rutas, componentes, navegación y administración

1. Descripción general del código

El código presentado corresponde a la parte frontend del proyecto PharmaShop. La aplicación está desarrollada con React y utiliza react-router-dom para gestionar la navegación entre las diferentes páginas.

El proyecto contiene dos partes principales: una parte destinada a los usuarios y otra destinada al administrador.

Los usuarios pueden consultar los productos, añadir productos al carrito, realizar un pedido y acceder al proceso de pago. El administrador dispone de páginas adicionales para gestionar productos, pedidos, pagos, clientes, ventas y configuraciones.

2. El componente AdminRoute

AdminRoute es un componente utilizado para proteger las rutas de administración. Su objetivo es impedir que los usuarios normales accedan a las páginas reservadas para los administradores.

El componente primero obtiene el token de localStorage utilizando localStorage.getItem("token").

El token se utiliza para determinar si el usuario ha iniciado sesión. Si no existe ningún token, el usuario se considera no autenticado.

En este caso, Navigate redirige automáticamente al usuario a /auth, que corresponde a la página de inicio de sesión.

A continuación, el componente obtiene la información del usuario desde localStorage. Los datos se convierten de JSON a un objeto JavaScript mediante JSON.parse().

El programa comprueba entonces: user.role !== "admin". Si el usuario ha iniciado sesión pero no tiene el rol admin, será redirigido a /products.

Si el token existe y el rol del usuario es admin, el componente devuelve children. Esto significa que la página de administración puede mostrarse.

Importante: AdminRoute protege la navegación en el frontend, pero la seguridad real también debe verificarse en el backend utilizando el token JWT y el rol del usuario.

3. Cómo funciona Navigate

Navigate es proporcionado por React Router. Permite que la aplicación redirija automáticamente al usuario hacia otra URL.

Por ejemplo, <Navigate to="/auth" replace /> redirige al usuario a la página de inicio de sesión.

La propiedad replace reemplaza la entrada actual del historial del navegador en lugar de añadir una nueva.

4. El componente AdminSidebar

AdminSidebar representa el menú lateral del área de administración.

Utiliza el componente Link de React Router para permitir que el administrador navegue entre las diferentes páginas sin recargar completamente la aplicación.

El primer enlace apunta a /admin. Esta URL corresponde al panel de administración.

El segundo enlace apunta a /admin/products. Proporciona acceso a la gestión de productos.

El tercer enlace apunta a /admin/orders. Permite al administrador consultar y gestionar los pedidos.

El enlace /products permite al administrador volver a la tienda pública.

5. Estilos de AdminSidebar

Los estilos del menú están definidos en el objeto JavaScript styles.

La propiedad position: "fixed" mantiene el menú fijo en el lado izquierdo de la pantalla.

height: "100vh" significa que la barra lateral ocupa toda la altura de la ventana.

display: "flex" y flexDirection: "column" organizan los enlaces verticalmente.

El color de fondo #111 proporciona al menú una apariencia oscura.

6. El componente Footer

Footer representa el pie de página de la aplicación. Contiene varios datos importantes sobre la tienda.

La primera parte corresponde a la presentación de la empresa. Explica que PharmaShop ofrece productos para el cuidado de la piel, belleza y farmacia.

La segunda parte contiene la información de contacto: dirección de correo electrónico, número de teléfono y ubicación.

La tercera parte presenta los servicios disponibles: productos para el cuidado de la piel, productos farmacéuticos, cosméticos y entrega rápida.

La última parte muestra el aviso de copyright: © 2026 Pharma & Skincare Store.

7. Footer.css

El componente Footer importa el archivo Footer.css. Esto significa que la presentación gráfica del footer puede separarse de su lógica de React.

Este enfoque mantiene el código React más limpio y centraliza los estilos del footer en un archivo CSS específico.

8. El componente Loader

Loader es un componente utilizado para mostrar un mensaje mientras se cargan los datos.

Muestra un elemento que contiene la clase CSS spinner. Esta clase puede definirse en un archivo CSS para crear una animación de carga.

El texto Loading... informa al usuario de que los datos todavía se están recuperando.

Este componente es especialmente útil durante las llamadas a la API, por ejemplo cuando la aplicación obtiene productos desde MongoDB a través del backend.

9. El componente Navbar

Navbar representa la barra de navegación principal de la tienda.

Utiliza Link para navegar hacia la página de inicio y la página de productos.

El componente también utiliza useNavigate() para redirigir al usuario después de cerrar sesión.

10. Recuperación del usuario en Navbar

El código obtiene el usuario mediante: JSON.parse(localStorage.getItem("user")).

Si no hay ningún usuario almacenado, la variable user estará vacía. En este caso, se muestra el botón Login.

Si existe un usuario, se muestra el botón Logout.

11. La función logout

La función logout() permite al usuario cerrar sesión.

Elimina la cuenta almacenada en localStorage mediante localStorage.removeItem("user").

También elimina el token JWT mediante localStorage.removeItem("token").

Finalmente, navigate("/auth") redirige al usuario a la página de inicio de sesión.

12. El componente PrivateRoute

PrivateRoute protege las páginas que requieren autenticación.

A diferencia de AdminRoute, no comprueba el rol del usuario. Solo comprueba si existe el token.

Si no existe ningún token, el usuario es redirigido a /auth.

Si existe el token, el componente devuelve children y permite el acceso a la página.

En tu aplicación, PrivateRoute se utiliza principalmente para proteger el carrito y la página Checkout.

13. Diferencia entre PrivateRoute y AdminRoute

PrivateRoute simplemente comprueba si el usuario ha iniciado sesión.

AdminRoute comprueba dos condiciones: el usuario debe haber iniciado sesión y su rol debe ser admin.

Por lo tanto, puede resumirse de la siguiente manera: PrivateRoute = usuario conectado. AdminRoute = usuario conectado + administrador.

14. El componente ProductCard

ProductCard muestra un producto como una tarjeta en la página de productos.

El componente recibe un producto mediante la propiedad product.

Muestra la imagen, el nombre, la categoría y el precio del producto.

El precio se muestra utilizando la moneda DT, que corresponde al dinar tunecino.

15. Uso de CartContext en ProductCard

El componente utiliza useContext(CartContext) para acceder a la función addToCart.

Esta función normalmente permite añadir el producto seleccionado al carrito global de la aplicación.

Error importante en el código: el botón llama a ajouteraupanier(product), pero esta función no está definida en el componente.

Como la función obtenida desde el contexto se llama addToCart, el botón debería utilizar normalmente addToCart(product).

16. Mostrar la imagen del producto

La imagen se construye utilizando: http://localhost:3000/${product.image}.

Esto significa que las imágenes deben ser proporcionadas por el backend de Node.js que se ejecuta en el puerto 3000.

Por ejemplo, si product.image contiene uploads/cream.jpg, la aplicación buscará la imagen en la dirección correspondiente del servidor backend.

17. El archivo App.jsx

App.jsx es el componente principal que organiza las diferentes rutas de la aplicación.

Importa BrowserRouter, Routes, Route y Navigate desde React Router.

También importa todas las páginas destinadas a los usuarios y a los administradores.

18. BrowserRouter

BrowserRouter permite que React Router gestione las URL de la aplicación.

Gracias a él, una URL como /products puede mostrar la página Products sin recargar toda la aplicación.

19. Routes y Route

Routes contiene todas las rutas disponibles en la aplicación.

Cada elemento Route asocia una URL con un componente.

Por ejemplo: /products muestra el componente Products.

Del mismo modo, /checkout muestra la página Checkout.

20. Ruta Home

La ruta / corresponde a la página de inicio.

Muestra el componente Home.

21. Ruta Products

La ruta /products muestra la lista de productos disponibles en la tienda.

Esta página es pública porque no está envuelta por PrivateRoute.

22. Ruta Cart

La ruta /cart está protegida por PrivateRoute.

Esto significa que el usuario debe haber iniciado sesión para acceder al carrito.

Si el usuario no ha iniciado sesión, será redirigido automáticamente a /auth.

23. Ruta Checkout

La ruta /checkout también está protegida por PrivateRoute.

Por lo tanto, solo los usuarios autenticados pueden acceder a la página utilizada para completar un pedido.

24. Ruta Auth

La ruta /auth muestra el componente Auth.

Esta página generalmente permite al usuario iniciar sesión o crear una cuenta.

Sigue siendo accesible incluso cuando el usuario no ha iniciado sesión.

25. Ruta del panel de administración

La ruta /admin muestra AdminDashboard.

Esta ruta está protegida por AdminRoute.

Por lo tanto, solo un usuario con el rol admin puede acceder al panel.

26. Ruta Admin Products

La ruta /admin/products muestra AdminProducts.

Esta página está destinada a la gestión de productos por parte del administrador.

Está protegida por AdminRoute.

27. Ruta Admin Orders

La ruta /admin/orders muestra AdminOrders.

Permite al administrador consultar y gestionar los pedidos de los clientes.

Al igual que las demás páginas de administración, está protegida por AdminRoute.

28. Ruta Admin Payments

La ruta /admin/payments muestra AdminPayments.

Esta página está destinada a consultar o gestionar los pagos realizados en la tienda.

29. Ruta Admin Customers

La ruta /admin/customers muestra AdminCustomers.

Esta página permite al administrador consultar los clientes registrados en la aplicación.

30. Ruta Admin Sales

La ruta /admin/sales muestra AdminSales.

Puede utilizarse para mostrar estadísticas o información sobre las ventas realizadas.

31. Ruta Admin Settings

La ruta /admin/settings muestra AdminSettings.

Esta página está destinada a configurar el área de administración.

32. Protección de las rutas de administración

Todas las rutas que comienzan con /admin se encuentran dentro de AdminRoute.

Esto crea una capa de protección común. Si el usuario no es administrador, no puede mostrar estas páginas.

Esta organización evita repetir la lógica de verificación del rol en cada página de administración.

33. Ruta inexistente

La ruta * corresponde a todas las URL que no coinciden con ninguna de las rutas definidas anteriormente.

En este caso, Navigate redirige al usuario a la página de inicio /.

Esto evita que aparezca una página en blanco o un error cuando el usuario introduce una URL incorrecta.

34. Footer en App.jsx

El componente Footer se coloca después de Routes, pero sigue estando dentro de BrowserRouter.

Esto significa que el footer se mostrará globalmente en toda la aplicación, independientemente de la ruta actual.

Si quieres ocultar el Footer en determinadas páginas, como las páginas de administración, tendrás que añadir una lógica condicional basada en la URL actual.

35. Arquitectura general de navegación

La aplicación sigue una arquitectura de navegación organizada alrededor de React Router.

BrowserRouter → Routes → Route → Page

Para las páginas privadas:

Route → PrivateRoute → Verificación del token → Page

Para las páginas de administración:

Route → AdminRoute → Token + rol admin → Page

36. Organización general del proyecto

El proyecto puede organizarse en varias carpetas.

La carpeta pages contiene las páginas destinadas a los usuarios, como Home, Products, Cart, Checkout y Auth.

La carpeta admin contiene las páginas reservadas para el administrador.

La carpeta components contiene componentes reutilizables como Navbar, Footer, Loader, PrivateRoute, AdminRoute y ProductCard.

La carpeta context puede contener el CartContext, que permite compartir la información del carrito entre varios componentes.

37. Flujo de acceso del usuario

Cuando un usuario abre la aplicación, puede acceder a la página de inicio y a la lista de productos.

Cuando quiere acceder al carrito o al checkout, PrivateRoute comprueba si existe el token.

Si falta el token, el usuario es enviado a la página de inicio de sesión.

Después de iniciar sesión, el usuario puede acceder a las funcionalidades privadas de la tienda.

38. Flujo de acceso del administrador

Cuando un usuario quiere acceder a /admin o a otra ruta de administración, se ejecuta AdminRoute.

El componente primero comprueba si existe el token.

A continuación, obtiene la información del usuario desde localStorage.

Finalmente, verifica que user.role === "admin".

Si se cumplen todas las condiciones, se muestra la página de administración.

39. Punto importante que corregir en ProductCard

En tu componente ProductCard, obtienes: const { addToCart } = useContext(CartContext).

Sin embargo, el botón utiliza: ajouteraupanier(product).

Esta función no existe en el código presentado. Esto provocará un error de JavaScript cuando el usuario haga clic en el botón.

La función obtenida desde el contexto es addToCart. Por lo tanto, esta función debe utilizarse para añadir el producto al carrito.

40. Conclusión

Este código proporciona una estructura completa para una tienda React con una separación clara entre usuarios y administradores.

PrivateRoute protege las funcionalidades que requieren autenticación.

AdminRoute protege las funcionalidades reservadas para los administradores.

Navbar proporciona la navegación principal y la funcionalidad de cierre de sesión.

AdminSidebar permite al administrador navegar por el área de gestión.

ProductCard muestra los productos y permite añadirlos al carrito.

Footer muestra la información general de la tienda.

Finalmente, App.jsx centraliza todas las rutas y define la estructura de navegación de la aplicación PharmaShop.
