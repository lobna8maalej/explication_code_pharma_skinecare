Explication des composants AdminProducts, AdminSales et AdminSettings

1. Présentation de AdminProducts

Le composant AdminProducts permet à l'administrateur de gérer les produits de la boutique.

Il permet d'afficher la liste des produits, modifier leurs informations, modifier rapidement leur stock et supprimer un produit.

2. Les imports de AdminProducts

useState est un Hook React qui permet de créer et gérer les variables d'état du composant.

useEffect permet d'exécuter une fonction automatiquement lorsqu'une condition particulière est respectée. Ici, il est utilisé pour récupérer les produits lorsque la page est chargée.

axios permet au frontend React de communiquer avec le backend Node.js/Express grâce aux requêtes HTTP.

AdminNavbar représente la barre de navigation utilisée dans l'espace administrateur.

3. Les variables useState

La variable products contient la liste des produits récupérés depuis le backend.

La variable loading permet de savoir si les produits sont encore en cours de chargement.

editingProduct contient le produit actuellement sélectionné pour être modifié.

Les variables name, price, stock et category correspondent aux champs du formulaire de modification.

updatingStock permet de savoir quel produit est actuellement en train de subir une modification de stock.

4. Récupération des produits

La fonction fetchProducts() permet de récupérer les produits depuis le backend.

Elle utilise une requête HTTP GET vers : /api/products.

Lorsque le backend répond, les produits sont enregistrés dans l'état products.

Le code vérifie plusieurs formats possibles de réponse, par exemple un tableau directement ou un tableau contenu dans response.data.products.

5. useEffect dans AdminProducts

Le code utilise useEffect avec un tableau vide comme dépendance.

Cela signifie que fetchProducts() est exécutée lorsque le composant est chargé.

L'objectif est de récupérer automatiquement les produits lorsque l'administrateur ouvre la page.

6. Modification du stock

La fonction updateStock() permet de modifier la quantité disponible d'un produit.

Avant d'effectuer la modification, le code vérifie que le stock n'est pas négatif.

Le token JWT est récupéré depuis localStorage.

Le token est envoyé au backend dans l'en-tête : Authorization: Bearer TOKEN.

Une requête PUT est ensuite envoyée vers : /products/:id.

7. Augmenter le stock

La fonction increaseStock() récupère le stock actuel du produit et ajoute une unité.

Par exemple, si le stock est égal à 10, le nouveau stock devient 11.

8. Diminuer le stock

La fonction decreaseStock() retire une unité du stock.

Le code vérifie que le stock actuel est supérieur à zéro. Cela évite d'avoir une quantité négative.

9. Modifier un produit

La fonction handleEdit() permet de sélectionner un produit.

Les informations du produit sélectionné sont ensuite placées dans les champs du formulaire.

L'administrateur peut alors modifier le nom, le prix, le stock et la catégorie.

10. Enregistrer les modifications

La fonction handleUpdate() est exécutée lorsque l'administrateur valide le formulaire.

Elle vérifie les données saisies puis envoie une requête PUT vers le backend.

Le prix et le stock sont convertis en nombres grâce à Number().

11. Supprimer un produit

La fonction handleDelete() permet de supprimer un produit.

Avant la suppression, window.confirm() demande une confirmation à l'administrateur.

Si l'administrateur confirme, une requête DELETE est envoyée au backend.

Après la suppression, filter() permet de retirer le produit de la liste affichée.

12. Statut du stock

Le composant affiche différents messages selon la quantité disponible.

Si le stock est égal à zéro, le produit affiche « Rupture ».

Si le stock est compris entre 1 et 5, le produit affiche « Stock faible ».

Si le stock est supérieur à 5, le produit affiche « En stock ».

13. Présentation de AdminSales

Le composant AdminSales permet à l'administrateur de consulter les statistiques commerciales de la boutique.

Il affiche le chiffre d'affaires, le nombre de commandes, le panier moyen et l'évolution des ventes par jour.

14. Les états de AdminSales

L'objet sales contient les statistiques générales des ventes.

totalSales représente le chiffre d'affaires.

totalOrders représente le nombre de commandes.

averageOrder représente le panier moyen.

dailySales contient les ventes regroupées par journée.

15. Récupération des statistiques

La fonction fetchSales() récupère d'abord le token administrateur.

Elle envoie ensuite une requête vers : /sales/overview.

Cette route retourne les statistiques générales de la boutique.

Une deuxième requête est envoyée vers : /sales/by-day.

Cette route permet d'obtenir les ventes quotidiennes.

16. Gestion des erreurs

Le composant utilise try, catch et finally pour gérer les requêtes asynchrones.

Une erreur 401 signifie généralement que le token n'est plus valide ou que la session a expiré.

Une erreur 403 signifie que l'utilisateur n'a pas les autorisations nécessaires.

17. Formatage des montants

La fonction formatMoney() utilise toLocaleString("fr-FR").

Cela permet d'afficher les nombres selon le format français avec deux chiffres après la virgule.

18. Formatage des dates

La fonction formatDate() transforme une date comme 2026-09-07 en : 07/09/2026.

19. Graphique des ventes

Le graphique est créé directement avec HTML et CSS. Aucune bibliothèque graphique externe n'est nécessaire.

La largeur de chaque barre dépend du montant des ventes de la journée par rapport au montant maximum.

Plus le montant est important, plus la barre affichée est grande.

20. Tableau des ventes

Le tableau affiche pour chaque journée la date, le nombre de commandes, le chiffre d'affaires et le panier moyen.

Le panier moyen est calculé en divisant le chiffre d'affaires par le nombre de commandes.

21. Présentation de AdminSettings

Le composant AdminSettings permet à l'administrateur de configurer les paramètres généraux de la boutique.

Il permet notamment de modifier les informations de la boutique, la devise, la livraison, Stripe et le mode maintenance.

22. Informations de la boutique

storeName contient le nom de la boutique.

email contient l'adresse email de la boutique.

phone contient le numéro de téléphone.

address contient l'adresse de la boutique.

23. Paramètres commerciaux

currency définit la devise principale utilisée par la boutique.

allowOrders permet d'autoriser ou de désactiver les commandes.

24. Paramètres de livraison

deliveryEnabled permet d'activer ou de désactiver la livraison.

deliveryFee correspond aux frais de livraison.

25. Paramètres Stripe

stripeEnabled permet d'activer ou de désactiver Stripe.

stripeCurrency définit la devise utilisée pour Stripe.

stripeExchangeRate représente le taux de conversion utilisé par l'application.

Par exemple, avec un taux de 0,32, une valeur de 100 TND peut être convertie en 32 unités de la devise Stripe sélectionnée.

26. handleChange

La fonction handleChange() permet de gérer les changements de tous les champs du formulaire.

Pour une checkbox, le code utilise checked. Pour les autres champs, il utilise value.

La notation [name] permet de modifier automatiquement la propriété correspondant au champ.

27. Enregistrer les paramètres

La fonction handleSubmit() est exécutée lorsque l'administrateur clique sur le bouton d'enregistrement.

Les données sont préparées puis envoyées au backend avec une requête PUT vers /settings.

Après une réponse positive du serveur, les nouveaux paramètres sont enregistrés dans le state React.

28. useState

useState permet de stocker des données qui peuvent changer pendant l'utilisation de la page.

Lorsque la fonction de modification du state est appelée, React met à jour l'interface automatiquement.

29. useEffect

useEffect est principalement utilisé ici pour effectuer les appels API lorsque les composants sont chargés.

30. Axios

Axios est une bibliothèque JavaScript qui permet d'envoyer des requêtes HTTP.

Dans le projet, Axios permet à React de communiquer avec le serveur Node.js/Express.

31. localStorage et JWT

Le token JWT est récupéré depuis localStorage.

Il est ensuite envoyé au backend avec : Authorization: Bearer TOKEN.

Le backend peut ainsi vérifier l'identité et les autorisations de l'administrateur.

32. map()

La méthode map() permet de parcourir un tableau et de créer un nouvel élément pour chaque élément du tableau.

Elle est utilisée notamment pour afficher les produits et les ventes dans les tableaux HTML.

33. filter()

La méthode filter() permet de conserver uniquement les éléments qui respectent une condition.

Dans AdminProducts, elle permet par exemple de retirer un produit après sa suppression.

34. async et await

Les mots-clés async et await permettent de travailler plus facilement avec les opérations asynchrones comme les appels API.

Le programme attend la réponse du serveur avant de continuer l'exécution de certaines instructions.

35. try, catch et finally

try contient le code qui peut provoquer une erreur.

catch récupère l'erreur afin de pouvoir afficher un message approprié.

finally permet d'exécuter une action dans tous les cas, par exemple arrêter l'affichage du chargement.

36. Architecture générale du projet

Le fonctionnement général est :

React → Axios → API Express → Middleware JWT → Contrôleur → MongoDB → Réponse JSON → React

React représente le frontend. Axios envoie les requêtes. Express reçoit les requêtes. Le middleware vérifie l'authentification. Le contrôleur traite les données. MongoDB stocke les informations.

Enfin, le backend renvoie une réponse JSON et React actualise l'interface.

37. Points importants à vérifier

Port API : les composants utilisent actuellement http://localhost:3000/api. Il faut vérifier que le backend utilise bien le port 3000.

Catégorie : la valeur skinecare semble être une faute d'orthographe. Si le backend utilise skincare, les deux doivent être identiques.

Sécurité : les validations présentes dans React ne remplacent pas les validations du backend.

Routes : les routes GET, PUT et DELETE utilisées par React doivent exister dans le backend Express.

38. Conclusion

AdminProducts permet de gérer les produits et les stocks.

AdminSales permet de consulter les performances commerciales et les ventes.

AdminSettings permet de configurer les paramètres généraux de la boutique, la livraison et les paiements.

Ces trois composants utilisent React, Axios, une API Node.js/Express, MongoDB et l'authentification JWT pour construire un espace d'administration complet.
