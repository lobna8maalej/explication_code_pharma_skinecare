PharmaShop Project Explanation

React Router, route protection, components, navigation and administration

1. General Code Overview

The code presented corresponds to the frontend part of the PharmaShop project. The application is developed with React and uses react-router-dom to manage navigation between the different pages.

The project contains two main parts: one part intended for users and another part intended for the administrator.

Users can browse products, add products to the cart, place an order and access the payment process. The administrator has additional pages for managing products, orders, payments, customers, sales and settings.

2. The AdminRoute Component

AdminRoute is a component used to protect administrator routes. Its purpose is to prevent regular users from accessing pages reserved for administrators.

The component first retrieves the token from localStorage using localStorage.getItem("token").

The token is used to determine whether the user is logged in. If no token exists, the user is considered unauthenticated.

In this case, Navigate automatically redirects the user to /auth, which corresponds to the login page.

The component then retrieves the user's information from localStorage. The data is converted from JSON into a JavaScript object using JSON.parse().

The program then checks: user.role !== "admin". If the user is logged in but does not have the admin role, they are redirected to /products.

If the token exists and the user's role is admin, the component returns children. This means that the administrator page can be displayed.

Important: AdminRoute protects navigation on the frontend, but real security must also be verified on the backend using the JWT token and the user's role.

3. How Navigate Works

Navigate is provided by React Router. It allows the application to automatically redirect the user to another URL.

For example, <Navigate to="/auth" replace /> redirects the user to the login page.

The replace property replaces the current entry in the browser history instead of adding a new one.

4. The AdminSidebar Component

AdminSidebar represents the sidebar menu of the administrator area.

It uses the Link component from React Router to allow the administrator to navigate between the different pages without completely reloading the application.

The first link points to /admin. This URL corresponds to the administrator dashboard.

The second link points to /admin/products. It provides access to product management.

The third link points to /admin/orders. It allows the administrator to view and manage orders.

The /products link allows the administrator to return to the public store.

5. AdminSidebar Styling

The menu styling is defined in the JavaScript object styles.

The property position: "fixed" keeps the menu fixed on the left side of the screen.

height: "100vh" means that the sidebar occupies the entire height of the window.

display: "flex" and flexDirection: "column" organize the links vertically.

The background color #111 gives the menu a dark appearance.

6. The Footer Component

Footer represents the footer of the application. It contains several important pieces of information about the store.

The first part corresponds to the company presentation. It explains that PharmaShop offers skincare, beauty and pharmacy products.

The second part contains contact information: email address, phone number and location.

The third part presents the available services: skincare products, pharmaceutical products, cosmetics and fast delivery.

The last part displays the copyright notice: © 2026 Pharma & Skincare Store.

7. Footer.css

The Footer component imports the Footer.css file. This means that the graphical presentation of the footer can be separated from its React logic.

This approach keeps the React code cleaner and centralizes the footer styles in a dedicated CSS file.

8. The Loader Component

Loader is a component used to display a message while data is being loaded.

It displays an element containing the CSS class spinner. This class can be defined in a CSS file to create a loading animation.

The text Loading... informs the user that the data is still being retrieved.

This component is particularly useful during API calls, for example when the application retrieves products from MongoDB through the backend.

9. The Navbar Component

Navbar represents the main navigation bar of the store.

It uses Link to navigate to the home page and the products page.

The component also uses useNavigate() to redirect the user after logging out.

10. Retrieving the User in Navbar

The code retrieves the user with: JSON.parse(localStorage.getItem("user")).

If no user is stored, the user variable is empty. In this case, the Login button is displayed.

If a user exists, the Logout button is displayed instead.

11. The logout Function

The logout() function allows the user to log out.

It removes the account stored in localStorage using localStorage.removeItem("user").

It also removes the JWT token using localStorage.removeItem("token").

Finally, navigate("/auth") redirects the user to the login page.

12. The PrivateRoute Component

PrivateRoute protects pages that require authentication.

Unlike AdminRoute, it does not check the user's role. It only checks whether the token exists.

If no token exists, the user is redirected to /auth.

If the token exists, the component returns children and grants access to the page.

In your application, PrivateRoute is used in particular to protect the cart and the Checkout page.

13. Difference Between PrivateRoute and AdminRoute

PrivateRoute simply checks whether the user is logged in.

AdminRoute checks two conditions: the user must be logged in and their role must be admin.

It can therefore be summarized as follows: PrivateRoute = logged-in user. AdminRoute = logged-in user + administrator.

14. The ProductCard Component

ProductCard displays a product as a card on the products page.

The component receives a product through the product property.

It displays the product image, name, category and price.

The price is displayed using the currency DT, which corresponds to the Tunisian dinar.

15. Using CartContext in ProductCard

The component uses useContext(CartContext) to access the addToCart function.

This function normally allows the selected product to be added to the application's global cart.

Important error in the code: the button calls ajouteraupanier(product), but this function is not defined in the component.

Since the function retrieved from the context is called addToCart, the button should normally use addToCart(product).

16. Displaying the Product Image

The image is constructed using: http://localhost:3000/${product.image}.

This means that the images are expected to be served by the Node.js backend running on port 3000.

For example, if product.image contains uploads/cream.jpg, the application will look for the image at the corresponding address on the backend server.

17. The App.jsx File

App.jsx is the main component that organizes the different routes of the application.

It imports BrowserRouter, Routes, Route and Navigate from React Router.

It also imports all user and administrator pages.

18. BrowserRouter

BrowserRouter allows React Router to manage the application's URLs.

Thanks to it, a URL such as /products can display the Products page without reloading the entire application.

19. Routes and Route

Routes contains all the available routes in the application.

Each Route element associates a URL with a component.

For example: /products displays the Products component.

Similarly, /checkout displays the Checkout page.

20. Home Route

The / route corresponds to the home page.

It displays the Home component.

21. Products Route

The /products route displays the list of products available in the store.

This page is public because it is not wrapped by PrivateRoute.

22. Cart Route

The /cart route is protected by PrivateRoute.

This means that a user must be logged in to access the cart.

If the user is not logged in, they will automatically be redirected to /auth.

23. Checkout Route

The /checkout route is also protected by PrivateRoute.

Therefore, only authenticated users can access the page used to complete an order.

24. Auth Route

The /auth route displays the Auth component.

This page generally allows the user to log in or create an account.

It remains accessible even when the user is not logged in.

25. Admin Dashboard Route

The /admin route displays AdminDashboard.

This route is protected by AdminRoute.

Therefore, only a user with the admin role can access the dashboard.

26. Admin Products Route

The /admin/products route displays AdminProducts.

This page is intended for product management by the administrator.

It is protected by AdminRoute.

27. Admin Orders Route

The /admin/orders route displays AdminOrders.

It allows the administrator to view and manage customer orders.

Like the other administrator pages, it is protected by AdminRoute.

28. Admin Payments Route

The /admin/payments route displays AdminPayments.

This page is intended for viewing or managing payments made in the store.

29. Admin Customers Route

The /admin/customers route displays AdminCustomers.

This page allows the administrator to view registered customers in the application.

30. Admin Sales Route

The /admin/sales route displays AdminSales.

It can be used to display statistics or information about completed sales.

31. Admin Settings Route

The /admin/settings route displays AdminSettings.

This page is intended for configuring the administrator area.

32. Protecting Administrator Routes

All routes beginning with /admin are placed inside AdminRoute.

This creates a common protection layer. If the user is not an administrator, they cannot display these pages.

This organization avoids repeating the role verification logic in every administrator page.

33. Non-Existing Route

The * route corresponds to all URLs that do not match any previously defined route.

In this case, Navigate redirects the user to the home page /.

This prevents a blank page or an error when the user enters an incorrect URL.

34. Footer in App.jsx

The Footer component is placed after Routes, but still inside BrowserRouter.

This means that the footer will be displayed globally throughout the application, regardless of the current route.

If you want to hide the Footer on certain pages, such as administrator pages, you will need to add conditional logic based on the current URL.

35. General Navigation Architecture

The application follows a navigation architecture organized around React Router.

BrowserRouter → Routes → Route → Page

For private pages:

Route → PrivateRoute → Token verification → Page

For administrator pages:

Route → AdminRoute → Token + admin role → Page

36. Overall Project Organization

The project can be organized into several folders.

The pages folder contains pages intended for users such as Home, Products, Cart, Checkout and Auth.

The admin folder contains pages reserved for the administrator.

The components folder contains reusable components such as Navbar, Footer, Loader, PrivateRoute, AdminRoute and ProductCard.

The context folder can contain the CartContext, which allows cart information to be shared between multiple components.

37. User Access Flow

When a user opens the application, they can access the home page and the list of products.

When they want to access the cart or checkout, PrivateRoute checks whether the token exists.

If the token is missing, the user is sent to the login page.

After logging in, the user can access the private features of the store.

38. Administrator Access Flow

When a user wants to access /admin or another administrator route, AdminRoute is executed.

The component first checks whether the token exists.

It then retrieves the user's information from localStorage.

Finally, it verifies that user.role === "admin".

If all conditions are satisfied, the administrator page is displayed.

39. Important Point to Fix in ProductCard

In your ProductCard component, you retrieve: const { addToCart } = useContext(CartContext).

However, the button uses: ajouteraupanier(product).

This function does not exist in the presented code. This will cause a JavaScript error when the user clicks the button.

The function retrieved from the context is addToCart. Therefore, this function should be used to add the product to the cart.

40. Conclusion

This code provides a complete structure for a React store with a clear separation between users and administrators.

PrivateRoute protects features that require authentication.

AdminRoute protects features reserved for administrators.

Navbar provides the main navigation and logout functionality.

AdminSidebar allows the administrator to navigate through the management area.

ProductCard displays products and allows them to be added to the cart.

Footer displays the store's general information.

Finally, App.jsx centralizes all routes and defines the navigation structure of the PharmaShop application.
