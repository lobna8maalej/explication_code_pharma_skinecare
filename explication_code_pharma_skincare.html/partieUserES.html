Explicación del código React – PharmaShop

Documentación completa del funcionamiento de la aplicación de comercio electrónico

1. Presentación general del proyecto PharmaShop

El proyecto PharmaShop es una aplicación de comercio electrónico desarrollada con React para el frontend y Node.js, Express y MongoDB para el backend. El objetivo principal de esta aplicación es permitir a los usuarios consultar productos farmacéuticos y de skincare, buscar y filtrar productos, añadirlos al carrito, modificar las cantidades, eliminar productos, crear un pedido y finalmente realizar un pago con Stripe.

La aplicación también contiene un sistema de autenticación que permite al usuario crear una cuenta o iniciar sesión. Dependiendo del rol del usuario, especialmente administrador o usuario normal, la aplicación puede redirigir al usuario a diferentes interfaces.

El frontend React se comunica con el backend mediante Axios, mientras que el backend se comunica con MongoDB para recuperar o guardar los datos. Por lo tanto, todo el proyecto sigue una arquitectura compuesta por una interfaz frontend, una API backend y una base de datos.

2. Función login()

La función login() gestiona la autenticación del usuario en la aplicación. Recibe dos parámetros importantes: user, que representa la información del usuario conectado, y token, que generalmente representa un token JWT utilizado para autenticar al usuario.

La primera instrucción utiliza localStorage.setItem() para guardar la información del usuario en el navegador. Como localStorage no puede almacenar directamente un objeto JavaScript, JSON.stringify() convierte el objeto usuario en texto JSON.

El token se guarda después bajo la clave token. Finalmente, setUser(user) actualiza el estado de React que contiene al usuario actualmente conectado.

3. Gestión global del carrito con CartContext

CartContext se utiliza para gestionar el carrito de forma global en la aplicación React. Sin Context API, sería necesario pasar la información del carrito entre varios componentes mediante props, lo que haría que la aplicación fuera más difícil de mantener.

Con createContext(), se crea un espacio compartido para contener la información y las funciones del carrito. El componente CartProvider contiene este estado global y proporciona los datos a los componentes que se encuentran dentro del Provider.

El carrito se inicializa con useState([]), lo que significa que al iniciar la aplicación el array cart está vacío. Los componentes como Products, Cart y Checkout pueden acceder posteriormente a los mismos datos mediante useContext().

4. Función addToCart()

La función addToCart() permite añadir un producto al carrito. Antes de añadir el producto, el código utiliza el método find() para comprobar si ya existe un producto con el mismo identificador _id.

Si el producto ya existe, el método map() recorre el carrito y crea una nueva versión del producto con la cantidad aumentada en uno. El operador spread conserva las demás propiedades del producto.

Si el producto todavía no existe, se añade al array con la propiedad quantity: 1. Esta lógica permite gestionar automáticamente las cantidades de los productos en el carrito.

5. Eliminación y modificación de productos del carrito

La función removeFromCart() permite eliminar un producto del carrito. Utiliza el método filter() para crear un nuevo array que contiene únicamente los productos cuyo identificador es diferente del identificador del producto que se desea eliminar.

La función updateQuantity() permite modificar la cantidad de un producto. Si la nueva cantidad es menor o igual a cero, la función llama automáticamente a removeFromCart().

La función clearCart() permite vaciar completamente el carrito utilizando setCart([]).

6. Cálculo del número de productos y del importe total

El código utiliza el método reduce() para realizar los cálculos relacionados con el carrito. La variable cartCount representa el número total de artículos presentes en el carrito.

La variable cartTotal representa el importe total del pedido. Para cada producto, el precio se multiplica por la cantidad y el resultado se añade al total general.

7. Función useCart()

useCart() es un hook personalizado creado para simplificar el uso de CartContext. En lugar de escribir directamente useContext(CartContext) en cada componente, el desarrollador puede simplemente llamar a useCart().

Este hook permite recuperar fácilmente el carrito, las funciones de añadir y eliminar, las funciones de modificación de cantidades, el número de artículos y el importe total.

8. Componente Auth

El componente Auth gestiona dos operaciones: el inicio de sesión y el registro. La variable isLogin permite determinar el modo actual del formulario.

Cuando isLogin es true, el formulario muestra la interfaz de inicio de sesión. Cuando es false, el formulario muestra la interfaz de registro. Las variables username, email y password son estados de React utilizados para controlar los campos del formulario.

El componente también utiliza useNavigate() para redirigir al usuario a otra página después de una operación exitosa.

9. Inicio de sesión del usuario

Durante el inicio de sesión, la función handleAuth() comprueba primero que la dirección de email y la contraseña hayan sido introducidas. El uso de trim() permite eliminar los espacios innecesarios alrededor de la dirección de email.

El email también se convierte a minúsculas mediante toLowerCase(). Después, Axios envía una solicitud POST a /api/users/login.

Si la respuesta contiene un token y un usuario, esta información se guarda en localStorage. Después se comprueba el rol del usuario. Si el rol es admin, el usuario es redirigido a /admin. De lo contrario, es redirigido a /products.

10. Registro del usuario

Cuando el formulario está en modo de registro, el username se vuelve obligatorio además del email y la contraseña.

La información se agrupa en un objeto registerData y después se envía con Axios a /api/users/register.

El backend crea el nuevo usuario y puede devolver un token junto con la información de la cuenta. El frontend guarda esta información en localStorage cuando está disponible.

11. Gestión de errores en Auth

Las solicitudes de inicio de sesión y registro se colocan dentro de un bloque try/catch. Si el servidor devuelve un error, el programa entra en el bloque catch.

El código utiliza err.response?.data?.message para intentar recuperar el mensaje enviado por el backend. El símbolo ?. corresponde al optional chaining y permite evitar un error si algunas propiedades no existen.

12. Componente Cart

El componente Cart representa la página del carrito. Recupera la información necesaria mediante CartContext. Cuando cart.length es igual a cero, la aplicación muestra un mensaje indicando que el carrito está vacío.

Cuando el carrito contiene productos, cart.map() se utiliza para mostrar cada artículo. Para cada producto, la aplicación muestra su nombre, precio, cantidad y subtotal.

El botón menos disminuye la cantidad mediante updateQuantity(), mientras que el botón más utiliza addToCart(). El botón de eliminar llama a removeFromCart().

13. Componente Checkout

Checkout representa la etapa de finalización del pedido. Este componente recupera la información del carrito o de una compra directa.

useLocation() permite recuperar la información transmitida durante la navegación. Si se envía un producto directamente, se añade a checkoutItems con una cantidad de uno.

En caso contrario, se utilizan los productos del carrito. El componente también contiene un estado customer que agrupa el nombre, apellido, teléfono y dirección del cliente.

14. Gestión del formulario del cliente

La función handleChange() permite actualizar dinámicamente la información del cliente. Utiliza el nombre del campo HTML como clave del objeto customer.

Esta técnica evita crear una función diferente para cada campo del formulario. De esta manera, el formulario permanece controlado por React y los valores introducidos están siempre disponibles en el estado customer.

15. Obtención del identificador del usuario

La función getUserIdFromToken() recupera el token JWT almacenado en localStorage. Un token JWT generalmente contiene tres partes separadas por puntos.

El código recupera la parte central, la decodifica con atob() y después transforma el resultado JSON en un objeto JavaScript mediante JSON.parse().

La aplicación busca después una propiedad id, _id o userId. Esto permite recuperar el identificador del usuario conectado para asociarlo al pedido.

16. Preparación de los productos para el pedido

Antes de crear un pedido, el código normaliza la información de los productos. La función getProductPrice() busca el precio en varias propiedades posibles.

La función getProductName() busca el nombre del producto en varias propiedades posibles como name, productName o title.

La función getProductQuantity() busca la cantidad en qty o quantity y utiliza una cantidad mínima de uno.

17. Creación del pedido

Cuando el usuario valida el formulario Checkout, handleSubmit() comienza impidiendo el comportamiento predeterminado del formulario mediante preventDefault().

Después, el código comprueba la información del cliente, los productos, el token y el identificador del usuario.

Los productos se transforman en orderItems que contienen el producto, su nombre, precio y cantidad. El importe total se calcula mediante reduce.

El objeto orderData contiene los productos, la información del cliente, el método de pago Stripe y el estado inicial del pago. Este objeto se envía al backend mediante una solicitud POST a /api/orders.

18. Pago con Stripe

Después de crear el pedido, Checkout recupera el identificador del pedido creado por el backend.

A continuación se envía una segunda solicitud a /api/payments/create-checkout-session para solicitar al backend que cree una sesión de pago de Stripe.

Si el backend devuelve una URL de Stripe válida, el frontend redirige al usuario hacia esta URL mediante window.location.href. El usuario puede entonces realizar el pago en Stripe.

19. Componente Home

El componente Home representa la página de inicio de PharmaShop. Muestra un título que presenta la tienda, un subtítulo que explica su actividad y un botón que permite acceder a los productos.

El componente Link de React Router se utiliza para navegar hacia /products sin recargar completamente la aplicación.

20. Componente Orders

El componente Orders sirve para mostrar el historial de pedidos. En el código proporcionado, los pedidos se recuperan desde localStorage mediante la clave "orders".

Si no hay ningún pedido disponible, se muestra un mensaje indicando que todavía no hay pedidos. De lo contrario, se utiliza map para mostrar cada pedido con el cliente, teléfono, dirección, productos, importe total y fecha.

Un punto importante es que Checkout crea realmente los pedidos en el backend. Si MongoDB es la fuente oficial de los pedidos, sería preferible que Orders recuperara los pedidos desde una ruta API protegida.

21. Componente Product

El componente Product muestra los detalles de un producto. useParams() recupera el identificador del producto desde la URL.

Axios realiza después una solicitud GET a /api/products/:id. El componente contiene estados loading y error para mostrar correctamente las diferentes situaciones durante la recuperación de los datos.

Una vez recuperado el producto, la aplicación puede mostrar su nombre, imagen, precio, categoría y descripción.

22. Gestión de las imágenes de los productos

La función getImageUrl() permite construir correctamente la dirección de una imagen. Si la imagen comienza ya con http, se considera una URL completa.

Si la imagen corresponde a una ruta relativa, se añade la dirección del servidor backend delante de la ruta. Esta lógica es útil cuando MongoDB conserva solamente la ruta de la imagen mientras los archivos son servidos por el servidor Node.js.

23. Componente Products

Products es la página que muestra la lista de productos disponibles. Al iniciarse, products se inicializa con un array vacío.

useEffect se utiliza para recuperar los productos desde la API. Axios envía una solicitud GET a /api/products.

Los datos recibidos se guardan después en el estado mediante setProducts(). React actualiza automáticamente la interfaz cuando este estado cambia.

24. Búsqueda y filtrado de productos

La variable search permite buscar un producto por su nombre. El método filter() se utiliza para seleccionar los productos que coinciden con los criterios.

El nombre se convierte a minúsculas mediante toLowerCase() y después includes() comprueba si el texto buscado existe dentro del nombre del producto.

El filtro de categoría compara la categoría del producto con la categoría seleccionada. El filtro de precio comprueba que el precio del producto sea menor o igual al precio máximo.

25. Añadir al carrito desde Products

La función handleAddToCart() permite añadir un producto directamente al carrito desde la lista de productos.

Antes de añadirlo, some() comprueba si el producto ya existe en el carrito comparando los identificadores _id.

Esta comprobación permite evitar duplicados y dejar que CartContext gestione correctamente el aumento de la cantidad.

26. Función Buy Now

handleBuyNow() permite realizar una compra directa de un producto. El primer paso consiste en comprobar si el usuario está conectado mediante la presencia del token en localStorage.

Si no existe ningún token, el producto seleccionado puede guardarse temporalmente en localStorage con la clave pendingProduct y el usuario es redirigido a la página Auth.

Si el usuario ya está conectado, es redirigido directamente a Checkout con el producto transmitido en el estado de navegación.

27. Cierre de sesión

handleLogout() permite cerrar la sesión del usuario. El token, la información del usuario y el producto temporal pendingProduct se eliminan de localStorage.

Después de esta operación, la aplicación redirige al usuario a la página Auth. La eliminación del token impide que las próximas solicitudes protegidas utilicen la sesión anterior.

28. Axios y comunicación con el backend

Axios se utiliza en varios componentes para comunicarse con la API backend. Las solicitudes GET se utilizan principalmente para recuperar productos u otra información.

Las solicitudes POST se utilizan para enviar datos, por ejemplo durante el inicio de sesión, el registro, la creación de un pedido o la creación de una sesión de Stripe.

El frontend utiliza la dirección http://localhost:3000/api como base de la API en el código proporcionado.

29. Arquitectura completa de la aplicación

El funcionamiento general puede resumirse mediante una cadena de comunicación. El usuario interactúa primero con la interfaz React. React utiliza después Axios para enviar una solicitud HTTP a la API Express.

Express recibe la solicitud y la transmite al controlador correspondiente. El controlador puede consultar o modificar los datos en MongoDB mediante los modelos de Mongoose.

El backend devuelve después una respuesta JSON. React recibe esta respuesta y actualiza sus estados mediante useState, lo que provoca una nueva actualización de la interfaz.

React → Axios → Express → Controller → MongoDB → JSON → React

30. Uso de useState

useState es uno de los principales Hooks de React. Permite conservar un dato dentro de un componente y modificarlo.

En PharmaShop, useState se utiliza para gestionar los productos, el carrito, los campos de los formularios, los mensajes de error, los estados de carga y la información del usuario.

31. Uso de useEffect

useEffect permite ejecutar una acción después del renderizado de un componente. Es especialmente importante en PharmaShop para realizar llamadas a la API cuando se carga una página.

Por ejemplo, Products utiliza useEffect para recuperar los productos, Product lo utiliza para recuperar un producto específico y Checkout lo utiliza para preparar los productos que se van a pedir.

32. Uso de React Router

React Router permite gestionar las diferentes páginas de la aplicación sin recargar completamente el navegador.

Link se utiliza para crear enlaces, mientras que useNavigate() permite realizar redirecciones desde una función JavaScript.

useParams() permite recuperar los parámetros presentes en la URL y useLocation() permite recuperar la información relacionada con la navegación.

33. Gestión de errores y cargas

Las solicitudes al backend pueden fallar por diferentes razones: el servidor puede estar detenido, la URL puede ser incorrecta, puede existir un error de red, un problema de autenticación o un error del lado del servidor.

Por esta razón, el código utiliza try, catch y, en algunos casos, finally. try contiene la operación principal, catch captura el error y finally permite realizar una acción que debe ejecutarse en todos los casos.

34. Puntos importantes que comprobar en el proyecto

El primer punto se refiere al componente Orders. En el código proporcionado, Orders utiliza localStorage mientras que Checkout envía los pedidos al backend. Por lo tanto, existe el riesgo de que los pedidos creados en MongoDB no sean visibles en Orders.

Para una aplicación real, se recomienda utilizar MongoDB como fuente principal de los pedidos y crear una ruta backend que permita al usuario autenticado recuperar sus pedidos.

El segundo punto se refiere al filtro por categoría en Products. El código contiene un estado category y una condición de filtrado, pero el JSX proporcionado no muestra necesariamente un elemento que permita al usuario seleccionar una categoría.

El tercer punto se refiere a handleBuyNow. La función está diseñada para realizar una compra directa, pero es necesario comprobar que el botón "Comprar ahora" esté realmente presente en la interfaz Products.

35. Conclusión general

El código de PharmaShop implementa una aplicación de comercio electrónico completa basada en React. React es responsable de la interfaz de usuario y de la gestión de estados, Context API permite compartir el carrito entre los componentes, React Router gestiona la navegación, Axios se encarga de la comunicación con la API y localStorage conserva determinada información relacionada con la sesión.

El backend Node.js y Express procesa las solicitudes, verifica los usuarios, crea los pedidos y prepara los pagos con Stripe. MongoDB constituye la base de datos utilizada para almacenar los usuarios, productos y pedidos.

El funcionamiento general es el siguiente: el usuario consulta los productos, busca o filtra un producto, añade sus productos al carrito, inicia sesión si es necesario, introduce la información de entrega, crea un pedido y finalmente es redirigido a Stripe para realizar el pago.

Esta organización constituye una buena base para una aplicación de comercio electrónico moderna, siempre que se mantenga una separación clara entre los datos temporales del navegador y los datos oficiales almacenados en el backend y MongoDB.
