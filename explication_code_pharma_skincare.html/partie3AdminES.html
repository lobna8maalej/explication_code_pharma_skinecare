```html Explicación de AdminProducts, AdminSales y AdminSettings

Explicación de los componentes AdminProducts, AdminSales y AdminSettings

1. Descripción general de AdminProducts

El componente AdminProducts permite al administrador gestionar los productos de la tienda.

Permite mostrar la lista de productos, modificar su información, actualizar rápidamente su stock y eliminar un producto.

2. Imports de AdminProducts

useState es un Hook de React que permite crear y gestionar las variables de estado del componente.

useEffect permite ejecutar una función automáticamente cuando se cumple una condición específica. Aquí se utiliza para recuperar los productos cuando se carga la página.

axios permite al frontend React comunicarse con el backend Node.js/Express mediante solicitudes HTTP.

AdminNavbar representa la barra de navegación utilizada en el área de administración.

3. Variables useState

La variable products contiene la lista de productos recuperados del backend.

La variable loading indica si los productos todavía se están cargando.

editingProduct contiene el producto seleccionado actualmente para su edición.

Las variables name, price, stock y category corresponden a los campos del formulario de edición.

updatingStock indica qué producto está siendo actualizado actualmente en cuanto a stock.

4. Recuperación de productos

La función fetchProducts() permite recuperar los productos desde el backend.

Utiliza una solicitud HTTP GET hacia: /api/products.

Cuando el backend responde, los productos se almacenan en el estado products.

El código comprueba varios formatos posibles de respuesta, por ejemplo un array directamente o un array contenido en response.data.products.

5. useEffect en AdminProducts

El código utiliza useEffect con un array de dependencias vacío.

Esto significa que fetchProducts() se ejecuta cuando se carga el componente.

El objetivo es recuperar automáticamente los productos cuando el administrador abre la página.

6. Actualización del stock

La función updateStock() permite modificar la cantidad disponible de un producto.

Antes de realizar la actualización, el código comprueba que el stock no sea negativo.

El token JWT se recupera desde localStorage.

El token se envía al backend en el encabezado: Authorization: Bearer TOKEN.

A continuación, se envía una solicitud PUT hacia: /products/:id.

7. Aumentar el stock

La función increaseStock() recupera el stock actual del producto y añade una unidad.

Por ejemplo, si el stock es igual a 10, el nuevo stock será 11.

8. Disminuir el stock

La función decreaseStock() elimina una unidad del stock.

El código comprueba que el stock actual sea mayor que cero. Esto evita que la cantidad se vuelva negativa.

9. Editar un producto

La función handleEdit() permite al administrador seleccionar un producto.

La información del producto seleccionado se coloca posteriormente en los campos del formulario.

El administrador puede modificar el nombre, el precio, el stock y la categoría.

10. Guardar los cambios

La función handleUpdate() se ejecuta cuando el administrador envía el formulario.

Valida los datos introducidos y después envía una solicitud PUT al backend.

El precio y el stock se convierten en números mediante Number().

11. Eliminar un producto

La función handleDelete() permite eliminar un producto.

Antes de eliminarlo, window.confirm() solicita una confirmación al administrador.

Si el administrador confirma, se envía una solicitud DELETE al backend.

Después de la eliminación, filter() se utiliza para eliminar el producto de la lista mostrada.

12. Estado del stock

El componente muestra diferentes mensajes dependiendo de la cantidad disponible.

Si el stock es igual a cero, el producto muestra "Sin stock".

Si el stock está entre 1 y 5, el producto muestra "Stock bajo".

Si el stock es superior a 5, el producto muestra "En stock".

13. Descripción general de AdminSales

El componente AdminSales permite al administrador consultar las estadísticas comerciales de la tienda.

Muestra los ingresos, el número de pedidos, el valor medio de los pedidos y la evolución de las ventas por día.

14. Estados de AdminSales

El objeto sales contiene las estadísticas generales de ventas.

totalSales representa los ingresos totales.

totalOrders representa el número de pedidos.

averageOrder representa el valor medio de un pedido.

dailySales contiene las ventas agrupadas por día.

15. Recuperación de las estadísticas de ventas

La función fetchSales() recupera primero el token del administrador.

Después envía una solicitud a: /sales/overview.

Esta ruta devuelve las estadísticas generales de la tienda.

Se envía una segunda solicitud a: /sales/by-day.

Esta ruta permite obtener las ventas diarias.

16. Gestión de errores

El componente utiliza try, catch y finally para gestionar las solicitudes asíncronas.

Un error 401 generalmente significa que el token ya no es válido o que la sesión ha expirado.

Un error 403 significa que el usuario no tiene los permisos necesarios.

17. Formato de los importes

La función formatMoney() utiliza toLocaleString("fr-FR").

Esto permite mostrar los números según el formato francés con dos decimales.

18. Formato de las fechas

La función formatDate() transforma una fecha como 2026-09-07 en: 07/09/2026.

19. Gráfico de ventas

El gráfico se crea directamente con HTML y CSS. No es necesaria ninguna biblioteca gráfica externa.

El ancho de cada barra depende del importe de las ventas del día en comparación con el importe máximo.

Cuanto mayor sea el importe, mayor será la barra mostrada.

20. Tabla de ventas

La tabla muestra para cada día la fecha, el número de pedidos, los ingresos y el valor medio de los pedidos.

El valor medio del pedido se calcula dividiendo los ingresos entre el número de pedidos.

21. Descripción general de AdminSettings

El componente AdminSettings permite al administrador configurar los ajustes generales de la tienda.

Permite modificar la información de la tienda, la moneda, la entrega, Stripe y el modo de mantenimiento.

22. Información de la tienda

storeName contiene el nombre de la tienda.

email contiene la dirección de correo electrónico de la tienda.

phone contiene el número de teléfono.

address contiene la dirección de la tienda.

23. Configuración comercial

currency define la moneda principal utilizada por la tienda.

allowOrders permite activar o desactivar los pedidos.

24. Configuración de entrega

deliveryEnabled permite activar o desactivar la entrega.

deliveryFee corresponde a los gastos de entrega.

25. Configuración de Stripe

stripeEnabled permite activar o desactivar Stripe.

stripeCurrency define la moneda utilizada para Stripe.

stripeExchangeRate representa el tipo de cambio utilizado por la aplicación.

Por ejemplo, con un tipo de cambio de 0.32, un valor de 100 TND puede convertirse en 32 unidades de la moneda de Stripe seleccionada.

26. handleChange

La función handleChange() permite gestionar los cambios realizados en todos los campos del formulario.

Para un checkbox, el código utiliza checked. Para los demás campos, utiliza value.

La notación [name] permite modificar automáticamente la propiedad correspondiente al campo.

27. Guardar la configuración

La función handleSubmit() se ejecuta cuando el administrador hace clic en el botón de guardar.

Los datos se preparan y después se envían al backend mediante una solicitud PUT a /settings.

Después de una respuesta positiva del servidor, los nuevos parámetros se almacenan en el estado de React.

28. useState

useState permite almacenar datos que pueden cambiar durante el uso de la página.

Cuando se llama a la función de actualización del estado, React actualiza automáticamente la interfaz.

29. useEffect

useEffect se utiliza principalmente aquí para realizar llamadas a la API cuando se cargan los componentes.

30. Axios

Axios es una biblioteca de JavaScript que permite enviar solicitudes HTTP.

En el proyecto, Axios permite que React se comunique con el servidor Node.js/Express.

31. localStorage y JWT

El token JWT se recupera desde localStorage.

Después se envía al backend mediante: Authorization: Bearer TOKEN.

De esta manera, el backend puede verificar la identidad y los permisos del administrador.

32. map()

El método map() permite recorrer un array y crear un nuevo elemento para cada elemento del array.

Se utiliza especialmente para mostrar productos y ventas en las tablas HTML.

33. filter()

El método filter() permite conservar únicamente los elementos que cumplen una condición.

En AdminProducts, por ejemplo, permite eliminar un producto de la lista después de su eliminación.

34. async y await

Las palabras clave async y await permiten trabajar más fácilmente con operaciones asíncronas como las llamadas a la API.

El programa espera la respuesta del servidor antes de continuar con la ejecución de determinadas instrucciones.

35. try, catch y finally

try contiene el código que puede generar un error.

catch captura el error para poder mostrar un mensaje apropiado.

finally permite ejecutar una acción en todos los casos, por ejemplo detener el indicador de carga.

36. Arquitectura general del proyecto

El funcionamiento general es:

React → Axios → API Express → Middleware JWT → Controller → MongoDB → JSON Response → React

React representa el frontend. Axios envía las solicitudes. Express recibe las solicitudes. El middleware verifica la autenticación. El controlador procesa los datos. MongoDB almacena la información.

Finalmente, el backend devuelve una respuesta JSON y React actualiza la interfaz.

37. Puntos importantes que comprobar

Puerto de la API: los componentes utilizan actualmente http://localhost:3000/api. Es necesario verificar que el backend utilice realmente el puerto 3000.

Categoría: el valor skinecare parece ser un error ortográfico. Si el backend utiliza skincare, ambos valores deben ser idénticos.

Seguridad: las validaciones realizadas en React no sustituyen las validaciones del backend.

Rutas: las rutas GET, PUT y DELETE utilizadas por React deben existir en el backend Express.

38. Conclusión

AdminProducts permite gestionar los productos y el stock.

AdminSales permite consultar el rendimiento comercial y las ventas.

AdminSettings permite configurar los parámetros generales de la tienda, la entrega y los pagos.

Estos tres componentes utilizan React, Axios, una API Node.js/Express, MongoDB y autenticación JWT para construir un área de administración completa.
```
