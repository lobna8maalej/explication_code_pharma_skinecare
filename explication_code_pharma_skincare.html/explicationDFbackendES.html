Explicación del Backend de la Plataforma Pharma

1. Middleware de autenticación JWT

El middleware de autenticación protege las rutas de la aplicación. Comprueba que el usuario tenga un token JWT válido antes de permitirle acceder a determinadas funcionalidades.

El módulo jsonwebtoken se importa mediante require("jsonwebtoken"). Se utiliza para verificar los tokens JWT enviados por el frontend.

2. Función auth

La función auth es un middleware que se ejecuta antes de determinados controladores. Su función es verificar la identidad del usuario.

El middleware obtiene el encabezado HTTP Authorization mediante req.headers.authorization.

Normalmente, el frontend debe enviar la información con este formato:

Authorization: Bearer TOKEN_JWT

Si no se envía ningún encabezado Authorization, el servidor devuelve un error HTTP 401 con el mensaje "No token provided".

A continuación, el servidor comprueba que el encabezado comience correctamente con Bearer . Esto permite verificar que el formato del token sea correcto.

El token se obtiene mediante: authHeader.split(" ")[1].

La función jwt.verify() verifica entonces el token utilizando la clave secreta contenida en la variable de entorno JWT_SECRET.

Si el token es válido, la información contenida en el token se coloca en req.user.

Esto permite que los siguientes controladores conozcan qué usuario ha iniciado sesión.

Finalmente, next() permite continuar hacia el siguiente middleware o controlador.

3. Gestión de errores JWT

Si el token es incorrecto, ha expirado o no es válido, se genera una excepción. El bloque catch captura este error.

El servidor devuelve entonces una respuesta HTTP 401 con el mensaje Invalid token.

4. Middleware isAdmin

El middleware isAdmin comprueba si el usuario conectado tiene el rol admin.

La condición comprueba:

req.user && req.user.role === "admin"

Si el usuario es administrador, next() permite acceder al controlador.

De lo contrario, el servidor devuelve un error HTTP 403. Esto significa que el usuario está autenticado, pero no tiene los permisos necesarios.

5. Segunda versión de isAdmin

En tu código también existe una segunda función llamada isAdmin. Comprueba directamente:

req.user.role !== "admin"

Si el rol no es admin, devuelve un error 403. De lo contrario, llama a next().

Es preferible mantener una sola versión de isAdmin para evitar duplicaciones y conflictos de importación.

6. Middleware Multer

El middleware Multer permite gestionar la carga de archivos desde el frontend hacia el servidor, especialmente las imágenes de los productos.

multer.diskStorage() define cómo se almacenarán los archivos en el servidor.

La propiedad destination indica que los archivos se guardarán en la carpeta:

uploads/

La propiedad filename permite generar un nombre único para cada imagen.

El nombre contiene la fecha actual mediante Date.now(), seguida del nombre original del archivo.

Por ejemplo, una imagen llamada vitamine.jpg puede convertirse en:

1725647890000-vitamine.jpg

La función multer({ storage }) crea entonces el middleware de carga de archivos.

7. Rutas de pedidos

El archivo de rutas de pedidos utiliza Express para definir las diferentes URL relacionadas con los pedidos.

El router se crea mediante:

const router = express.Router();

A continuación, se importan las funciones del orderController.

8. Creación de un pedido

La ruta:

POST /api/orders

permite crear un nuevo pedido.

Utiliza el middleware auth. Esto significa que solo un usuario conectado puede crear un pedido.

El controlador utilizado es createOrder.

9. Recuperación de todos los pedidos

La ruta:

GET /api/orders

permite recuperar todos los pedidos.

Está protegida por dos middlewares: auth seguido de isAdmin.

Esto significa que el usuario debe estar conectado y tener el rol de administrador.

10. Recuperación de los pedidos de un usuario

La ruta:

GET /api/orders/user/:userId

permite recuperar los pedidos asociados a un usuario específico.

La ruta está protegida por auth, pero en esta versión no se utiliza el middleware isAdmin.

11. Recuperación de un pedido

La ruta:

GET /api/orders/:id

permite recuperar un pedido utilizando su identificador de MongoDB.

El usuario debe estar autenticado mediante el middleware auth.

12. Actualización del estado de un pedido

La ruta:

PUT /api/orders/:id/status

permite modificar el estado de un pedido.

Está reservada para los administradores.

El estado puede, por ejemplo, pasar de En attente a En préparation, después a Expédiée y finalmente a Livrée.

13. Actualización del estado del pago

La ruta:

PUT /api/orders/:id/payment-status

permite modificar el estado del pago de un pedido.

Esta operación también está reservada al administrador.

14. Eliminación de un pedido

La ruta:

DELETE /api/orders/:id

permite eliminar un pedido.

Esta operación está protegida por auth y isAdmin. Por lo tanto, un usuario normal no puede eliminar un pedido.

15. Rutas de pagos de Stripe

El archivo paymentRoutes.js contiene las rutas utilizadas para gestionar los pagos con Stripe.

16. Creación de una sesión de Stripe

La ruta:

POST /api/payments/create-checkout-session

permite crear una sesión de pago de Stripe.

La ruta utiliza el middleware auth. Por lo tanto, el usuario debe estar conectado antes de realizar el pago.

El controlador utilizado es createCheckoutSession.

17. Recuperación de los pagos

La ruta:

GET /api/payments/admin

permite al administrador recuperar la lista de pagos.

Utiliza auth y isAdmin.

18. Webhook de Stripe

La ruta:

POST /api/payments/webhook

es utilizada por Stripe para enviar automáticamente notificaciones al servidor.

Utiliza express.raw() porque Stripe necesita el cuerpo original de la solicitud para verificar la firma del webhook.

El controlador stripeWebhook recibe entonces el evento enviado por Stripe.

19. Rutas de productos

El archivo productRoutes.js contiene las rutas utilizadas para gestionar los productos de la farmacia.

20. Creación de un producto

La ruta:

POST /api/products

permite a un administrador crear un nuevo producto.

Utiliza tres middlewares: auth, isAdmin y upload.single("image").

El primero verifica la identidad del usuario. El segundo comprueba que sea administrador. El tercero permite recibir una imagen.

21. Recuperación de los productos

La ruta:

GET /api/products

permite recuperar todos los productos.

Esta ruta es pública. No se necesita ningún token JWT.

Esto permite a los visitantes y clientes consultar los productos disponibles.

22. Modificación de un producto

La ruta:

PUT /api/products/:id

permite a un administrador modificar un producto.

La imagen es opcional gracias a upload.single("image").

Si se envía una nueva imagen, puede reemplazar la imagen anterior.

23. Rutas de ventas

El archivo salesRoutes.js permite acceder a las estadísticas de ventas de la plataforma.

24. Vista general de las ventas

La ruta:

GET /api/sales/overview

permite obtener una vista general de las ventas.

Está protegida por auth y isAdmin. Solo un administrador puede consultar esta información.

El controlador puede devolver, entre otros datos, los ingresos totales, el número de pedidos y el valor medio de los pedidos.

25. Ventas por día

La ruta:

GET /api/sales/by-day

permite obtener las ventas agrupadas por día.

Estos datos pueden utilizarse posteriormente en un dashboard de administración para mostrar gráficos estadísticos.

26. Rutas de configuración

El archivo settingsRoutes.js permite gestionar los parámetros generales de la tienda.

27. Recuperación de la configuración

La ruta:

GET /api/settings

permite al administrador recuperar la configuración de la tienda.

Requiere autenticación y el rol de administrador.

28. Modificación de la configuración

La ruta:

PUT /api/settings

permite al administrador modificar la configuración.

Estos parámetros pueden incluir el nombre de la tienda, el email, el teléfono, la dirección, la moneda, los pedidos, el mantenimiento, la entrega y Stripe.

29. Rutas de usuarios

El archivo userRoutes.js contiene las rutas relacionadas con la autenticación y los clientes.

30. Registro

La ruta:

POST /api/users/register

permite a un nuevo usuario crear una cuenta.

Esta ruta es pública porque el usuario todavía no ha iniciado sesión.

31. Inicio de sesión

La ruta:

POST /api/users/login

permite a un usuario existente iniciar sesión.

El servidor verifica la dirección de email y la contraseña. Si la información es correcta, se genera un token JWT.

32. Lista de clientes

La ruta:

GET /api/users/customers

permite recuperar la lista de clientes.

En el controlador, solo se seleccionan los usuarios que tienen el rol user.

33. Recuperación de un cliente

La ruta:

GET /api/users/customers/:id

permite recuperar un cliente utilizando su identificador.

34. Eliminación de un cliente

La ruta:

DELETE /api/users/customers/:id

permite eliminar un cliente.

Atención: en el código presentado, estas tres rutas de clientes no están protegidas por auth e isAdmin.

Para una aplicación real, se recomienda encarecidamente proteger estas rutas si están destinadas a ser utilizadas únicamente por la administración.

35. Script de lanzamiento del scraper Python

El código:

from scrapers.pharma_scraper import scrape_products scrape_products()

importa una función llamada scrape_products desde el módulo scrapers.pharma_scraper.

A continuación, la función se ejecuta mediante scrape_products().

Su objetivo es iniciar automáticamente el scraping de los productos.

36. Biblioteca Requests

En el scraper Python, la biblioteca requests se utiliza para enviar una solicitud HTTP a un sitio web.

La función requests.get() recupera el contenido HTML de la página.

37. Biblioteca BeautifulSoup

BeautifulSoup se utiliza para analizar el código HTML recuperado del sitio web.

Gracias a BeautifulSoup, el programa puede buscar elementos HTML que contienen información sobre los productos.

38. Conexión a MongoDB con Python

La biblioteca pymongo permite a Python comunicarse con MongoDB.

La conexión se realiza mediante:

MongoClient("mongodb://localhost:27017/")

Por lo tanto, el programa se conecta a una instancia de MongoDB instalada localmente en la máquina.

39. Base de datos pharma_db

El código utiliza la base de datos:

pharma_db

A continuación, utiliza la colección:

products

Los productos recuperados de los sitios web se almacenarán en esta colección.

40. Primer scraper: Pharma Shop

El primer scraper utiliza la dirección:

https://pharma-shop.tn/

El programa envía una solicitud HTTP con un User-Agent. Esto permite simular un navegador al recuperar la página.

41. Búsqueda de productos

El programa busca todos los elementos HTML con la siguiente estructura:

div class="product"

Cada elemento encontrado se considera un producto.

42. Extracción del nombre del producto

Para cada producto, el programa busca la etiqueta h2.

A continuación, el texto se obtiene mediante .text y se limpia mediante .strip().

El resultado se almacena en la variable name.

43. Extracción del precio

El scraper busca después una etiqueta:

span class="price"

El contenido de esta etiqueta se recupera y se almacena en la variable price.

44. Creación del objeto producto

El programa crea después un diccionario Python que contiene el nombre y el precio:

{ "name": name, "price": price }

Este objeto representa la información del producto que se almacenará en MongoDB.

45. Inserción en MongoDB

La función collection.insert_one() se utiliza para insertar un producto en MongoDB.

Después de la inserción, el programa muestra el nombre del producto en la consola mediante print("Inserted:", name).

46. Gestión de errores del scraper

El procesamiento de cada producto se coloca dentro de un bloque try / except.

Si el scraper encuentra un problema al recuperar el nombre, el precio o insertar el producto, el error se captura y se muestra en la consola.

Esto permite que el scraper continúe procesando en lugar de detenerse completamente ante el primer error.

47. Segundo scraper: Doppelherz

El segundo scraper funciona de manera similar, pero utiliza otra fuente:

https://www.doppelherz.tn/produits

Recupera el contenido de esta página mediante requests.

A continuación, BeautifulSoup analiza el HTML y busca elementos que tengan la clase product.

Para cada producto, el programa recupera su nombre y su precio.

La información se almacena posteriormente en la misma colección de MongoDB: pharma_db.products.

48. Ejecución directa del scraper

La condición:

if __name__ == "__main__":

permite ejecutar automáticamente la función scrape_and_save() cuando el archivo Python se ejecuta directamente.

Esto evita que la función se ejecute automáticamente si el archivo simplemente se importa en otro programa.

49. Arquitectura general del proyecto

La arquitectura general puede representarse de la siguiente manera:

React Frontend ↓ Express REST API ↓ JWT Middleware ↓ Routes ↓ Controllers ↓ Mongoose Models ↓ MongoDB

Para los pagos interviene una parte adicional:

React ↓ Express ↓ Payment Controller ↓ Stripe Checkout ↓ Stripe Webhook ↓ MongoDB

Para la recuperación de productos externos, el flujo es diferente:

External Website ↓ Python Requests ↓ BeautifulSoup ↓ Scraper ↓ PyMongo ↓ MongoDB

50. Flujo de autenticación

Cuando un usuario se registra, el servidor crea su cuenta y genera un token JWT.

Cuando el usuario inicia sesión, el servidor verifica su contraseña y también genera un token JWT.

El frontend almacena entonces este token y lo envía con las solicitudes que requieren autenticación.

El middleware auth verifica el token y coloca la información del usuario en req.user.

A continuación, el middleware isAdmin verifica el rol del usuario.

51. Flujo de un pedido

El cliente consulta los productos mediante la ruta pública GET /api/products.

A continuación, añade los productos al carrito.

Cuando confirma el carrito, el frontend envía una solicitud POST /api/orders.

El middleware JWT verifica que el cliente haya iniciado sesión.

El controlador createOrder valida los productos, calcula el importe total y crea el pedido en MongoDB.

52. Flujo del pago con Stripe

Después de crear el pedido, el frontend puede solicitar la creación de una sesión de Stripe.

El backend verifica que el pedido pertenezca al usuario conectado.

A continuación, crea una sesión de Stripe Checkout que contiene los productos y sus precios.

El cliente es redirigido a Stripe para realizar el pago.

Una vez completado el pago, Stripe puede enviar un evento al servidor mediante el webhook.

El webhook actualiza entonces el pago y el pedido en MongoDB.

53. Flujo del scraping

Los scripts Python permiten recuperar automáticamente productos de varios sitios web farmacéuticos.

El scraper envía una solicitud HTTP, analiza la página HTML, recupera la información de los productos y posteriormente la guarda en MongoDB.

Los datos pueden ser recuperados posteriormente por el backend Node.js y mostrados en la aplicación React.

54. Puntos importantes que mejorar

El primer punto se refiere al código duplicado. Tienes dos versiones del middleware isAdmin. Es preferible conservar una sola función isAdmin.

El segundo punto se refiere a las rutas de clientes. Las rutas /customers son actualmente públicas. Si están destinadas al dashboard de administración, es preferible utilizar:

auth, isAdmin

antes de los controladores correspondientes.

El tercer punto se refiere al scraping. Los selectores HTML div.product, h2 y span.price deben coincidir exactamente con la estructura real de los sitios web correspondientes. Si el sitio cambia su HTML, el scraper puede dejar de funcionar.

El cuarto punto se refiere al precio. En el scraper, el precio se recupera actualmente como una cadena de caracteres. Para realizar correctamente cálculos en MongoDB o en el backend, es preferible limpiar el precio y convertirlo después en un número.

El quinto punto se refiere a las variables sensibles. Valores como JWT_SECRET y STRIPE_SECRET_KEY deben almacenarse en el archivo .env y nunca deben publicarse en GitHub.

55. Resumen general

El backend de esta plataforma Pharma está construido alrededor de varias tecnologías complementarias.

Node.js y Express permiten crear la API REST y las rutas.

JWT permite autenticar a los usuarios y proteger las rutas privadas.

isAdmin permite restringir determinadas funcionalidades a los administradores.

Multer permite recibir y almacenar las imágenes de los productos.

MongoDB permite almacenar usuarios, productos, pedidos, pagos y configuraciones.

Stripe permite gestionar los pagos en línea.

Python Requests y BeautifulSoup permiten recuperar productos desde sitios web externos.

PyMongo permite posteriormente que el scraper Python guarde los productos recuperados directamente en MongoDB.

Todo el sistema forma, por tanto, una arquitectura completa de comercio electrónico con gestión de usuarios, administración, productos, pedidos, pagos, estadísticas y recuperación automatizada de datos externos.
