Explication des modèles MongoDB

Cette page explique les différents modèles MongoDB utilisés dans l'application e-commerce Pharma & Skincare. Les modèles permettent de définir la structure des données stockées dans MongoDB avec Mongoose.

1. Connexion à MongoDB

Le fichier de connexion permet de connecter l'application Node.js à la base de données MongoDB.

La méthode mongoose.connect() utilise l'adresse mongodb://localhost:27017/ecommerce. Cela signifie que MongoDB fonctionne localement sur l'ordinateur et que la base de données utilisée s'appelle ecommerce.

La fonction connectDB est une fonction asynchrone. Elle utilise try/catch afin de détecter une éventuelle erreur de connexion à MongoDB.

Lorsque la connexion fonctionne, le message MongoDB connected est affiché dans la console. En cas d'erreur, le message DB connection error est affiché.

2. Modèle Order - Commandes

Le modèle Order représente les commandes effectuées par les clients dans la boutique Pharma & Skincare.

Utilisateur

Le champ user contient l'identifiant MongoDB du client qui a effectué la commande. Il utilise une référence vers le modèle User.

Le champ est facultatif grâce à required: false. Une commande peut donc éventuellement être enregistrée sans utilisateur connecté.

Informations du client

Le bloc customer contient les informations nécessaires pour la livraison et le contact avec le client.

Il contient le prénom, le nom, l'adresse e-mail, le numéro de téléphone et l'adresse du client.

Produits commandés

Le champ items est un tableau contenant les produits présents dans la commande.

Chaque élément contient l'identifiant du produit, son nom, son prix et la quantité commandée.

Le champ product utilise une référence vers le modèle Product. Cela permet de relier la commande au produit correspondant.

Total de la commande

Le champ totalAmount représente le montant total de la commande. Il est obligatoire grâce à required: true.

Paiement

Le champ paymentMethod indique la méthode de paiement. Dans ton application, la valeur par défaut est Stripe.

Le champ paymentStatus indique l'état du paiement. Il peut être En attente, Payé ou Échec.

Statut de la commande

Le champ orderStatus permet de suivre l'évolution de la commande.

Une commande peut être : En attente, En préparation, Expédiée, Livrée ou Annulée.

Timestamps

L'option timestamps: true ajoute automatiquement deux champs : createdAt et updatedAt. Ils permettent de connaître la date de création et la date de dernière modification de la commande.

3. Modèle Payment - Paiements

Le modèle Payment permet d'enregistrer les informations concernant les paiements effectués pour les commandes.

Commande

Le champ orderId contient l'identifiant de la commande associée au paiement. Il possède une référence vers le modèle Order.

Utilisateur

Le champ userId contient l'identifiant du client ayant effectué le paiement. Il possède une référence vers le modèle User.

Montant

Le champ amount représente le montant du paiement. Il est obligatoire.

Devise

Le champ currency indique la devise utilisée pour le paiement. Par défaut, la devise est USD.

L'option lowercase: true transforme automatiquement la valeur en minuscules. Par exemple, USD devient usd.

Méthode de paiement

Le champ method indique la méthode de paiement. Dans ce modèle, seule la méthode stripe est autorisée.

Informations Stripe

stripeSessionId contient l'identifiant de la session Stripe Checkout.

stripePaymentIntentId contient l'identifiant du PaymentIntent Stripe lorsqu'il est disponible.

Statut du paiement

Le champ status permet de connaître l'état du paiement. Il peut être pending, paid, failed ou refunded.

Cela permet notamment à l'administration de savoir si une commande a été payée, si le paiement a échoué ou si le montant a été remboursé.

4. Modèle Product - Produits

Le modèle Product représente les produits vendus dans la boutique Pharma & Skincare.

Nom du produit

Le champ name contient le nom du produit. Il est obligatoire et l'option trim: true permet de supprimer les espaces inutiles au début et à la fin.

Prix

Le champ price contient le prix du produit. Il est obligatoire.

Stock

Le champ stock représente la quantité disponible du produit. Sa valeur par défaut est 0.

La valeur ne peut pas être négative grâce à min: 0.

Catégorie

Le champ category permet de classer les produits. Par exemple : soins visage, cheveux, maquillage ou protection solaire.

Image

Le champ image contient l'adresse ou le chemin de l'image du produit. Si aucune image n'est fournie, sa valeur est une chaîne vide.

Timestamps

Avec timestamps: true, MongoDB ajoute automatiquement createdAt et updatedAt.

5. Modèle Settings - Paramètres de la boutique

Le modèle Settings permet à l'administrateur de sauvegarder les paramètres généraux de la boutique.

Informations de la boutique

Les champs storeName, email, phone et address contiennent les informations générales de la boutique.

Devise

Le champ currency représente la devise utilisée par la boutique. Par défaut, elle est définie sur TND.

Commandes

Le champ allowOrders permet d'autoriser ou de désactiver les commandes. Sa valeur par défaut est true.

Mode maintenance

Le champ maintenanceMode permet à l'administrateur d'activer ou de désactiver le mode maintenance du site.

Livraison

Le champ deliveryEnabled permet d'activer ou désactiver la livraison.

Le champ deliveryFee contient le coût de livraison. Par défaut, il est égal à 0.

Stripe

Le champ stripeEnabled permet d'activer ou désactiver Stripe.

Le champ stripeCurrency indique la devise utilisée pour Stripe. Dans ton modèle, elle est par défaut définie sur USD.

Le champ stripeExchangeRate représente le taux de conversion entre le TND et la devise utilisée par Stripe.

Par exemple, avec une valeur de 0.32, une conversion peut être effectuée selon le taux configuré par l'administrateur.

6. Modèle User - Utilisateurs

Le modèle User permet de gérer les comptes utilisateurs de l'application.

Email

Le champ email contient l'adresse e-mail de l'utilisateur. Il est obligatoire et unique.

L'option lowercase: true permet de stocker automatiquement l'e-mail en minuscules.

Username

Le champ username contient le nom d'utilisateur. Il est obligatoire.

Password

Le champ password contient le mot de passe de l'utilisateur. Il est obligatoire.

En pratique, le mot de passe ne doit pas être stocké en clair. Il doit être hashé avant d'être enregistré dans MongoDB, par exemple avec bcrypt.

Rôle

Le champ role permet de déterminer les permissions de l'utilisateur.

Deux rôles sont disponibles : user pour un client et admin pour un administrateur.

Par défaut, un nouvel utilisateur possède le rôle user.

Timestamps

L'option timestamps: true permet de conserver automatiquement les dates de création et de modification du compte.

7. Relations entre les modèles

Les différents modèles sont reliés entre eux grâce aux identifiants MongoDB de type ObjectId.

Un User peut effectuer plusieurs commandes Order.

Une Order peut contenir plusieurs produits Product.

Une commande Order peut avoir un paiement Payment.

Le modèle Settings contient les paramètres généraux de la boutique et notamment les paramètres concernant Stripe, la livraison, la devise et le mode maintenance.

8. Résumé du fonctionnement

L'utilisateur crée un compte avec le modèle User.

Il consulte les produits enregistrés dans Product.

Il ajoute les produits au panier puis valide sa commande. Les informations de la commande sont enregistrées dans Order.

Lorsqu'il effectue un paiement avec Stripe, les informations du paiement sont enregistrées dans Payment.

L'administrateur peut ensuite consulter les commandes, les paiements, les produits et modifier les paramètres de la boutique grâce au modèle Settings.

L'ensemble de ces modèles permet donc de construire la partie backend de la boutique e-commerce Pharma & Skincare avec Node.js, Express, MongoDB et Mongoose.
