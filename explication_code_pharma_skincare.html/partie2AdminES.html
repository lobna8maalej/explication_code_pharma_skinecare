Documentación de Administración de la Tienda

Esta documentación explica detalladamente cómo funcionan los componentes de React utilizados en el área de administración de la tienda.

Los componentes cubiertos son AdminOrders, AdminProducts y AdminPayments.

Estos componentes permiten al administrador gestionar los pedidos, productos, inventario y pagos realizados con Stripe.

1. Arquitectura General

La aplicación utiliza React para construir la interfaz de usuario de administración. React se comunica con el backend mediante la biblioteca Axios.

El frontend envía solicitudes HTTP a la API backend disponible en: http://localhost:3000/api.

El backend recibe las solicitudes, realiza las operaciones necesarias, se comunica con MongoDB y devuelve los resultados al frontend.

React Admin → Axios → API Express/Node.js → MongoDB

Para determinadas operaciones administrativas, se recupera un token JWT de localStorage y luego se envía en el encabezado HTTP Authorization.

2. Componente AdminOrders

El componente AdminOrders representa la página de administración dedicada a la gestión de los pedidos de los clientes.

El administrador puede consultar los pedidos, ver la información del cliente, consultar los productos solicitados, comprobar el importe total, consultar el pago, modificar el estado del pedido y eliminar un pedido.

3. Importación de Dependencias en AdminOrders

El componente comienza importando los hooks de React useEffect y useState.

useState se utiliza para gestionar los datos dinámicos de la página, mientras que useEffect se utiliza para ejecutar código cuando el componente se carga.

Axios se utiliza para comunicarse con el backend.

El componente también importa AdminNavbar para mostrar la barra de navegación de administración.

El archivo AdminOrders.css contiene los estilos específicos de la página de pedidos.

4. API Utilizada por AdminOrders

La constante API contiene la dirección principal del backend. 

const API = "http://localhost:3000/api";

Todas las solicitudes relacionadas con los pedidos se construyen a partir de esta dirección.

5. Estado de los Pedidos

El componente utiliza tres estados principales: orders, loading y error.

orders contiene la lista de pedidos recuperados del backend.

loading indica si los pedidos se están cargando actualmente.

error puede contener el mensaje de error que se mostrará cuando falle la recuperación de los pedidos.

6. Recuperación de los Pedidos

La función fetchOrders recupera todos los pedidos desde la API.

Antes de realizar la solicitud, el componente recupera el token del administrador almacenado en localStorage. 

const token = localStorage.getItem("token");

El token se envía al backend mediante el siguiente encabezado: Authorization: Bearer token.

Este método permite al backend verificar que la solicitud procede de un usuario autenticado.

7. Solicitud GET de los Pedidos

La siguiente solicitud se utiliza para recuperar todos los pedidos: 

axios.get(`${API}/orders`, {
  headers: {
    Authorization: `Bearer ${token}`,
  },
});

El backend debe devolver los pedidos en la propiedad orders o posiblemente en data.

El frontend verifica entonces que el resultado sea realmente un array antes de almacenarlo en orders.

8. useEffect en AdminOrders

El hook useEffect se utiliza con un array de dependencias vacío. 

useEffect(() => {
  fetchOrders();
}, []);

Esto significa que fetchOrders se ejecuta una sola vez cuando se carga la página.

9. Cambio del Estado de un Pedido

La función updateStatus permite al administrador cambiar el estado de un pedido.

El ID del pedido y el nuevo estado se envían al backend. 

axios.put(
  `${API}/orders/${orderId}/status`,
  {
    orderStatus: newStatus,
  },
  {
    headers: {
      Authorization: `Bearer ${token}`,
    },
  }
);

El nuevo estado puede ser, por ejemplo: En attente, En préparation, Expédiée, Livrée o Annulée.

10. Actualización Inmediata de la Interfaz

Después de modificar correctamente el estado, el frontend no necesariamente vuelve a cargar toda la lista desde el servidor.

Actualiza directamente el pedido correspondiente en el estado orders.

Esta técnica proporciona una interfaz más rápida y receptiva.

11. Eliminación de un Pedido

La función deleteOrder permite eliminar un pedido.

Antes de eliminarlo, se muestra un cuadro de confirmación mediante window.confirm.

Si el administrador confirma, se envía una solicitud HTTP DELETE al backend. 

axios.delete(`${API}/orders/${orderId}`, {
  headers: {
    Authorization: `Bearer ${token}`,
  },
});

Después de la eliminación, el pedido también se elimina del estado orders.

12. Recuperación del Nombre del Cliente

La función getCustomerName determina el nombre del cliente asociado al pedido.

El componente comprueba primero la información disponible en order.customer.

Si existe el nombre o apellido, ambos se combinan para formar el nombre completo.

Si esta información no está disponible, el componente utiliza order.user.username.

Si no hay ninguna información disponible, se muestra el texto Client inconnu.

13. Recuperación del Correo Electrónico del Cliente

La función getCustomerEmail busca el correo electrónico en order.customer.email.

Si este valor no existe, utiliza order.user.email.

Si no hay ninguna dirección disponible, se muestra el texto Email inconnu.

14. Recuperación de los Productos de un Pedido

La función getItems comprueba si el pedido contiene un array items.

Si este array no existe, también comprueba la propiedad products.

Esta lógica hace que el componente sea más flexible cuando el backend devuelve una estructura diferente.

15. Cálculo del Importe Total

La función getTotal recupera el importe total del pedido.

Primero utiliza totalAmount.

Si esta propiedad no existe, utiliza totalPrice.

Si no hay ningún valor disponible, el importe predeterminado es 0.

16. Estado del Pago

La función getPaymentStatus recupera el estado del pago.

Si no existe ningún estado, el valor predeterminado es En attente.

Esto evita que se muestre un valor vacío en la interfaz.

17. Estado del Pedido

La función getOrderStatus recupera el estado actual del pedido.

Si el backend no proporciona ningún estado, se utiliza el valor En attente.

18. Formato de las Fechas

La función formatDate transforma una fecha procedente de MongoDB en una fecha legible para el usuario.

El formato utilizado es el francés gracias a toLocaleDateString("fr-FR").

Por lo tanto, una fecha puede mostrarse en el formato 07/09/2026.

19. Gestión de la Carga

Cuando loading es true, el componente muestra un mensaje indicando que los pedidos se están cargando.

La barra de navegación AdminNavbar también permanece visible.

20. Gestión de Errores

Si se produce un error al recuperar los pedidos, el mensaje se almacena en error.

El usuario verá entonces un mensaje de error junto con un botón Réessayer.

El botón permite ejecutar nuevamente la función fetchOrders sin tener que recargar manualmente la página.

21. Visualización de un Pedido

Cada pedido se muestra como una tarjeta utilizando la clase order-card.

La tarjeta contiene varios datos: número del pedido, fecha, cliente, correo electrónico, número de teléfono, dirección, productos, importe, pago y estado.

22. Visualización de los Productos

Para cada producto solicitado, el componente recupera el nombre, el precio y la cantidad.

El subtotal se calcula utilizando la siguiente fórmula: 

Subtotal = Price × Quantity

El resultado se muestra con dos decimales.

23. Cambio del Estado mediante un Select

El administrador dispone de un elemento HTML select que permite elegir el nuevo estado.

Cuando cambia el valor, la función updateStatus se ejecuta automáticamente.

Esto permite cambiar rápidamente el estado de un pedido directamente desde la tabla de administración.

24. Componente AdminProducts

El componente AdminProducts permite al administrador gestionar los productos de la tienda.

Permite consultar productos, modificar su información, aumentar o disminuir el stock y eliminar un producto.

25. Estado de los Productos

El estado products contiene la lista de productos.

El estado loading indica si los productos todavía se están recuperando.

El estado editingProduct contiene el producto seleccionado actualmente para editarlo.

26. Estados del Formulario de Edición

Se utilizan varios estados para gestionar los campos del formulario: name, price, stock y category.

Cada campo está controlado por React. Cuando el usuario escribe en un campo, su estado correspondiente se actualiza automáticamente.

27. Recuperación de los Productos

La función fetchProducts envía una solicitud GET a /products. 

axios.get(`${API}/products`);

El componente acepta varios formatos posibles de respuesta: un array directamente, products o data.

28. Actualización Rápida del Stock

La función updateStock permite modificar el stock de un producto directamente desde la lista.

Antes de enviar la solicitud, el componente comprueba que el nuevo stock no sea negativo.

El nuevo stock se envía al backend mediante una solicitud PUT. 

axios.put(
  `${API}/products/${productId}`,
  {
    stock: Number(newStock)
  }
);

29. Protección contra un Stock Negativo

El código evita deliberadamente la creación de un stock inferior a cero.

Cuando el stock es igual a cero, el botón utilizado para disminuir el stock se desactiva.

Esta comprobación es importante para garantizar la coherencia de los datos comerciales.

30. Botones Más y Menos del Stock

La función decreaseStock disminuye el stock en una unidad.

La función increaseStock aumenta el stock en una unidad.

Ambas funciones llaman posteriormente a updateStock para enviar el nuevo valor al backend.

31. Indicador del Nivel de Stock

El componente utiliza tres niveles de stock.

Cuando el stock es igual a cero, la interfaz muestra Rupture.

Cuando el stock es mayor que cero pero menor o igual a cinco, la interfaz muestra Stock faible.

Cuando el stock es mayor que cinco, la interfaz muestra En stock.

32. Apertura del Formulario de Edición

La función handleEdit se ejecuta cuando el administrador hace clic en el botón Modifier.

Almacena el producto seleccionado en editingProduct y copia sus valores en los diferentes campos del formulario.

33. Cancelación de la Edición

La función handleCancelEdit cierra el formulario de edición.

También restablece los campos name, price, stock y category a sus valores iniciales.

34. Validación del Formulario del Producto

Antes de modificar un producto, el código comprueba que todos los campos obligatorios hayan sido completados.
